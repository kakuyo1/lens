## 2. 专属性判定

**Authored。** 第二层的专属性最强：义项路标、下钻链的双栈边、hover 判定行、等宽 `~` 脚注、「Disappears in Ns」元信息行。默认卡的脸仍接近通用词典弹窗，单看 `bubble.png` 认不出 Lens；但「无焦点表面 + 读屏地板」这个交互契约本身是产品专属的：为沉浸取词放弃焦点，用名称与按压动作换回可达，代价写进 UI-SPEC 与 ADR 0107。

## 3. 最终切片里真正改掉的

1. **读屏地板**：判定胶囊、关闭、语言切换、链中词、义项图入口全部有 `Accessible.role` / `name` / `onPressAction`，名称走 `qsTr` 随界面语言本地化。`tst_bubble.qml:265` 走表面树，断言每个 Button 都有非空名称，并断言窗口仍带 `WindowDoesNotAcceptFocus`。
2. **玻璃正文档位**：`TokenTable.qml:53` 新增语义色 `body`——实心底保持 `muted`，玻璃取 `text`。气泡的释义、义项英文行、词源 / 例句正文、释义链当前层、判定 / 句子 / Preview 标签改读 `body`；音标、倒计时、搭配、面包屑仍 `faint`。实测正文从 2.33:1 提到 4.39:1，仍低于 4.5，ADR 0106 写明这是 40% 白底的材质边界，不再写成「已过 AA」。
3. **判定行首次提示**：`BubbleVerdictRow.qml:29-46` 用 `hintLatch` 在本次展开内锁住提示，`showHint` 只在悬停且有待判定时出现；`Timer` 停留 1.5 秒才写 `verdictHintSeen`，快速路过不消耗唯一一次说明。`BubbleCard.qml:37-39` 把未读提示的高度预先计入 `verdictRowHeight`，卡片不会因为提示出现而二次长高。文案是「Known stops automatic scans; New marks it for more practice.」，和 GLOSSARY 的学习标记语义对齐。
4. **测试夹具回到生产形状**：主夹具从 en + zh 双语言改为只带 en，镜像 `explanation_duty.cpp:486-489` 的单语言不变量，并新增一条断言（`test_theFixtureCarriesOneAnswerLanguage`）。

## 6. 边界（不是待办）

- **玻璃正文 4.39:1**：比 2.33 好，但仍低于 4.5；音标、倒计时、搭配、面包屑等 `faint` 元信息更低。ADR 0106 已把这条写成材质边界。任何「玻璃主题已过 AA」的说法都是不诚实的。已裁 D2：先做 40 / 42 / 44% 三档测量，选最小的正文达标档；没有可接受档才接受 4.39。
- **无焦点、无 Esc**：气泡不抢焦点、不认 Esc，是沉浸取词的产品选择；读屏以浏览模式可达，键盘专用读者不可遍历。ADR 0107 记的是这个代价，不是待修的缺陷。
- **图片不在卡内搜索**：悬浮本身绝不发请求，恢复动作打开的是浏览器搜索（`docs/adr/0079`）。这是成本与隐私的取舍，不是图片态的失败。
- **真实屏幕阅读器会话**没有跑。探针只证明树里的名称与按压动作，不证明 NVDA / UIA 的朗读顺序。

## 8. 开放问题

1. 停表要不要认「读屏在场」？最小版是每次读屏按压重灌一程，完整版是加第六条停表条件。哪一档配得上「沉浸优先」？
2. 一次性提示能不能在不加 Tab 站的前提下让读屏也听到？例如把提示并进判定按钮的 `Accessible.description`，只在未读时存在。
3. 图片失败的三类原因要不要写死三句，像更新卡那样不让传输层原话漏出来？恢复动作静止态能不能不光靠 hover 才像按钮？
4. 玻璃材质要不要为了 4.39 → 4.5 改 40% 白底？已裁 D2：先测 40 / 42 / 44% 三档，最小达标档优先；若视觉代价不可接受，才接受 4.39 并在文档里长期保留「未过 AA」。
