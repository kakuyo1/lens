# 选区动作条 · 最终 critique

**方法**：最终源码逐条对照 + 战役内五形真机 2x 快照（`%TEMP%\lens-critique\bar-bar.png`、`bar-tab.png`、`bar-hand.png`、`bar-tag.png`、`bar-fan.png`）+ `tst_selectionbar.qml` 的末次全量。最终版没有重新拍摄玻璃两主题、hover / 按压运行态、翻边与工作区收边；这些在末尾列为未采样。

**范围**：`SelectionBar.qml` 与 `bodies/` 五件（Classic / Tab / Hand / Tag / Fan）、设置里的 `SelectionBarPreview.qml`、UI-SPEC §4.10 / §4.17、DESIGN §3.1 / 4.10、ADR 0107。评分只对动作条，不把取词蒙版与选区逻辑算进来。

## 1. 最终读数

**32 / 40（Good）**。趋势：28 → 32 → **32**。

最后 +0 是设计的诚实：读屏地板补上了，DESIGN 的焦点态例外也记了，但这只让「不该被记成违规」的东西不再被记成违规，没有让条本身多一种操作方式。挡住 33 的仍是三件：720ms 的入场重量、静止态读不出的形态身份、以及指针优先契约下的零键盘路径。

| # | 启发式 | 分 | 最终依据 |
|---|---|---|---|
| 1 | 系统状态可见 | 3 | 五形 hover / 按压 / 闪光反馈齐全且走令牌；扇面目标划分静止态仍要靠 hover 才现形 |
| 2 | 贴近真实世界 | 3 | 纸品隐喻更完整（手牌上抛、页边签位移随翻边）；扇骨 1px `line` 与页边签书脊 / 折角低于静止可读阈值 |
| 3 | 用户控制与自由 | 3 | 整条可拖、点外即关、落点翻边加夹边、退场让位 150ms；无 Esc、无静置自动收、位置拖过即忘 |
| 4 | 一致性与标准 | 4 | 圆角只从 `radiusMenu / radiusGroup / radiusField` 取，字重只剩 400 / 700，图标一律 15px，动效全走 `Tokens.motion`；五 body 逐一核对无例外 |
| 5 | 错误预防 | 3 | 三项皆轻动作、即点即发；退场期 `enabled: false` 挡穿透；扇面命中几何无死角误触；中文选区无门槛误拖即出是规格已知取舍 |
| 6 | 识别而非回忆 | 4 | 三动作在五形里同序、同图标、同标签，永远图标加文字；设置预览逐形一句话先教后用 |

| 10 | 帮助与文档 | 3 | 设置预览的逐形一句话是这扇面的说明书；条上零提示，拖动、点外关、静置不收全靠试 |

**认知负荷**：五形都是三动作，顺序固定，识别负担低；失败项是「最短路径之外的重复税」——扇形与吊牌读者每天为入场付几十次注视成本。

## 2. 专属性判定

**Authored。** 五形不是同一控件换皮：页边签有书脊与折角，手牌有中牌抬升与上抛淡出，吊牌有孔、绳与摆动，扇面三片同色加 1px 扇骨。三动作等权的裁定同时落在实现、规格和设置预览三处，这在复审里少见。动作条不是通用工具条，它是「从刚读完的那行字旁边长出来的一张纸」。

## 3. 最终切片里真正改掉的

1. **读屏地板**：五个形体共 15 个动作目标都有 `Accessible.role: Button`、动作标签作名称、`onPressAction` 直连 `root.activate()`——Classic `:89-91`、Tab `:152-154`、Hand `:111-113`、Tag `:224-226`；Fan 是一片形状不是三个 item，所以用三个不可见 `Item` 盖在各自扇叶上（`FanBody:130-140`），指针仍只走原来的楔形判定，读屏多一条按压路径。
2. **DESIGN 例外落纸**：ADR 0107 把「无焦点浮层保留读屏地板」写成契约：动作条、气泡、通知、更新卡继续 `WindowDoesNotAcceptFocus`，不设 Tab 站与焦点环；可按目标必须有角色、名称、按压动作。以后新增无焦点表面按同一套补齐。
3. **回归钉住**：`tst_selectionbar.qml:108` 的 `test_everyFormNamesItsThreeActions` 走五形，断言每个动作都有名称；上一轮已钉的位移翻向（`:84`）与手牌上抛淡出（`:126`）仍在。
4. **报告口径订正**：上一轮写「TagBody / FanBody 都没有 flashTimer」。最终核对：Tab / Hand 有 `flashTimer`；Tag 有 `flashing` 但确实没有计时器，只能等下次 `show` 清零；Fan 根本没有闪态代码，靠退场掩盖。因此这一项应从「两 body」收窄为「Tag 一处」，Fan 的冻住风险不成立。

## 6. 边界（不是待办）

- **无焦点、无 Esc、无键盘遍历**：这是 ADR 0107 与 §4.10 写明的产品选择。动作条由指针优先的取词手势触发，读屏以浏览模式可达；键盘专用读者按契约进不来。
- **三动作等权**：扇面同色 + 1px 扇骨，不再用明暗偷说层级；这是第 3 轮的裁定，不再回退。
- **静置自动收**没有做：误拖税与「它会不会自己跑掉」的不确定感之间仍未裁；如果入场先减半，这个问题的痛感会下降一半。
- **玻璃两主题、暗夜、日文长标签、拖拽跟手**没有在最终版重新采样。

## 7. 画像

- **Alex（效率型）**：拖选 → 单击仍是最短路径；红旗是重复税——扇形用户每天为入场付几十次 720ms，条的位置拖过即忘。
- **Sam（辅助技术）**：读屏树里现在有三个具名可按的动作，不再是空 Rectangle；但仍没有焦点遍历，也没有 Esc；他能「执行」，不能「走进来」。
- **Jordan（初见者）**：设置预览是一句好课；直接遇到扇形或页边签时，静止态读不出三个目标和页签身份，第一眼仍要靠三列文字撑着。
- **沉浸读者**：条出现得不吵，退场让位快；720ms 的扇 / 吊展开是唯一会打断阅读节奏的东西。

## 8. 开放问题

1. 入场动效要不要「首次全量、后续从简」？已裁 D3：要——第一次完整，同一会话后续 `pop×2`，reduced motion 不变；§4.17 与实现一起改，并写一条 ADR。
2. 静止态的形态身份要不要救？扇骨提 `muted`、折角加 `line`，都是小刀口；或者接受「近看细节」的定位，并在 §4.10 写明，不再让规格暗示一个读者看不见的记号。
3. 静置自动收要不要和入场减半一起裁？中文选区无门槛使误拖必出条，两个问题其实是一笔账。
4. 读屏地板之后，是否给动作条一个全局热键或第二入口？目前它只存在于指针手势里。
