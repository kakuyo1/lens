# 宠物包格式

> 镜像副本，随 skill 分发。**正本是仓库的 `docs/pet-package-format.md`**：改动在正本上做，再整文件同步过来；两处不一致时以正本为准。

面向第三方作者，也是应用校验实现的依据。应用对宠物包的接受与拒绝以本文件为准。本文件自足：生成一只包所需的一切都在这里，不需要读其他仓库文档。

宠物包是**只含数据**的目录：JSON 文档加 PNG 图片。包里没有代码，应用也不执行包里的任何东西。

## 1。放在哪，怎么被读到

| 来源 | 位置 | 谁写入 |
|---|---|---|
| 随包宠物 | 安装目录的 `data/pet/<id>/` | 开发者，随发布包分发 |
| 宠物包 | `%APPDATA%\Lens\pets\<id>\` | 读者自己 |

- 包目录必须是 `pets\` 的**直接子目录**，不再向下嵌套。
- 应用在**打开设置的扩展分类时**扫描该目录，启动时也扫描一次，用于加载读者上次选的宠物。刚放进去的包在此之前不会被读到。
- 应用对包目录**只读**：不写入、不删除、不改名、不移动。唯一的写入是读者在设置里点 “打开宠物包目录” 时，目录不存在则先创建它。卸载应用不删除 `%APPDATA%\Lens`，包因此还在。
- 读者分享包时把整个 `<id>\` 目录打包成压缩文件即可；**解压由读者自己用系统工具完成**，应用不内置解压（见 `docs/adr/0043` 的后果一节）。

## 2。目录结构

```
pets\<id>\
  pet.json            必填。画布、缩放、图层序、表情 sheet 路径、格式版本
  animations.json     必填。角色到动作的映射、空闲池、每个动作的播放参数
  anchors.json        必填。每个动作每帧的 head / face / body 锚点
  accessories.json    必填。配饰目录；一件都没有也要写 { "accessories": [] }
  sprites\            推荐布局：
    body\<动作>.png    身体 sheet，横排，每帧一格，帧间无间距
    effects\<动作>.png 特效 sheet，可选，尺寸与身体 sheet 相同
    expressions\eyes.png 表情 sheet，一排 canvas × canvas 的格子
    accessories\...    配饰单图，每张 canvas × canvas
```

- 四个 JSON **全部必填**，缺任何一个整只拒绝（`Unreadable`）。没有配饰就写空数组，没有可省的动作块就不写那个键（见 §3）。
- sheet 的路径可以是包内**任意相对位置**，不必照上面的树；`sprites\` 布局是约定，校验只管路径安全（§5 第 1–3 条）。
- 约定树之外的文件不会被读，也**不会因此被拒**；它们只计入 §4 的大小与文件数上限。
- `sign\` 目录与 `sign.json` 是随包宠物的提问牌素材，**不属于本格式**；包里放了也不会被读。包宠物的提问牌由应用直接绘制，作者无法改变它的外观。

## 3。字段

### 3.1 pet.json

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | 整数 | 必填，本版本为 `1`。缺失或为其他值整只拒绝 |
| `id` | 字符串 | 必填，必须与目录名相同 |
| `name` | 字符串 | 可选显示名。缺省时显示 `id`。**不翻译**；显示前按 §5 第 13 条去掉控制字符并做 NFC 归一 |
| `canvas` | 整数 | 必填，单帧边长（像素），16–128 |
| `scale` | 整数 | 必填，放大倍数，1–4 |
| `layers` | 对象 | 必填，`body` / `expression` / `effect` 三层的 z 值。任意整数，值大者在上面 |
| `expression` | 字符串 | 必填，表情 sheet 的相对路径 |

- 推荐取值 `canvas` 88、`scale` 3（全部随包宠物的值）：屏上边长 = `canvas × scale`，放大是整数倍最近邻，画布上的 1 像素在屏上是 3 像素。
- 校验只读上列键。**文档没写的字段一律忽略**：不拒绝、不生效，也不要依赖。

### 3.2 animations.json

`roles`、`actions`、`idlePool` 三个键都必填，缺任何一个整只拒绝。

`roles` 是动作名到角色的映射。角色名是产品定义的**闭集**，包不能新增，写了不认识的名字直接拒绝：

| 角色 | 何时播放 | 可省 |
|---|---|---|
| `idle` | 待机的基础循环，没有事件时一直播它 | 否 |
| `study` | 讲解卡片打开期间持续播放 | 否 |
| `thinking` | 读者请求讲解时播一次 | 否 |
| `celebrate` | 标记 “认识”、复习答对、应用有更新时播一次 | 否 |
| `encourage` | 标记新词、复习答错时播一次 | 否 |
| `sleep` | 学习预算暂停期间持续播放，也是打盹的落脚动作 | 否 |
| `click_react` | 被单击时播一次（连击未到生气阈值前） | 否 |
| `pickup` | 被拖起时进入，放下后回 `idle` | 否 |
| `look_around` | 选中词条弹出示窗时播一次，也是待机小动作 | 否 |
| `yawn` | 待机抽中打盹时播一次；随包宠物用 `returnTo` 把它接进 `sleep` | 否 |
| `stretch` | 待机回合一开场优先于 `look_around` 尝试的小动作 | 是 |
| `angry` | 连击达到 `angryClicks`，或复习被无视时播一次 | 是 |
| `ask` | 复习提问牌挂出期间持续播放 | 是 |
| `dizzy` | 抛掷落地后播一次；缺省时改演 `click_react`（见 `docs/adr/0091`） | 是 |

校验不禁止多个角色指向同一个动作，但随包宠物都是一角色一动作。缺 `angry` 的宠物永远不生气；缺 `ask` 的宠物照样有提问牌，只是不演那个展示动作（见 `docs/adr/0088`）。

`actions` 里每个动作的字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `frames` | 是 | 帧数，1–64 |
| `fps` | 是 | 帧率，1–24 |
| `loop` | 是 | 布尔 |
| `sheet` | 是（`blink` 除外） | 身体 sheet 的相对路径 |
| `effect` | 否 | 特效 sheet 的相对路径，像素尺寸与身体 sheet 完全相同 |
| `expressions` | 否 | 每帧的表情 sheet 索引数组；每个索引是非负整数且小于表情 sheet 格数。数组可比 `frames` 短，缺的帧用 0，多出的忽略；整个缺省 = 全程 0 |
| `returnTo` | 否 | 播完后回到的角色名，必须已在 `roles` 里映射 |
| `duration` | 否 | 毫秒，到点动作收场，1–3 600 000。循环动作因此也能自己收场（应用自带的场景用它） |
| `blink` | 否 | 布尔。只有标了 `true` 的动作播放期间才叠加眨眼循环；不标则该动作永不眨眼 |

其余要点：

- 必须有一个名为 `blink` 的动作条目：眨眼的三帧序列，只有表情、没有 `sheet`（写法见 §9 的最小包）。眨眼的节奏由应用掌握，作者只给序列。
- `idlePool` 只能列单次动作（`loop` 为假），可以为空数组。应用装载时还会把**没被 `roles` 点到的单次动作**补进池子，所以给包加一个新动作就同时给了它一个待机动作；`idlePool` 里写不写同一个名字都行，写了不会重复。循环动作（含带 `duration` 的场景动作）不进池子，只有应用自己的场景抽签能开始它们。
- `hover` 可选，控制指针靠近时播什么：`notice` 与 `dwell` 是本包已有的**单次**动作名，`dwell` 必须与 `notice` 同时出现；`noticeDelayMs`、`dwellDelayMs`、`cooldownMs` 可选，依次默认 350、2600、8000，范围都是 0–60000。没有 `hover` 的包仍有视线跟随，但没有靠近动作；`hover` 至少要给出 `notice` 或 `dwell` 之一。
- `movement` 可选，控制宠物空闲时走几步、贴边时躲不躲：`style` 必填，是 `glide` / `float` / `hop` / `trot` / `pounce` 之一（依次是滑行、漂浮、单脚跳、小跑、扑跳）；`walk` 必填，是本包已有的**循环**动作名；`peek` 可选，也是本包已有的循环动作名，缺省表示不躲藏；`range` 可选，是窗口宽度的百分比，范围 10–60，默认 30。没有 `movement` 的包保持原地待机；有 `walk` 没有 `peek` 的包只闲逛、不躲藏。走一步的时长等于 `walk` 的自然时长（`frames × 1000 / fps`）；可见比例与滑动时长是应用常数，不写进包。
- `behavior` 可选，决定这只宠物的脾气（`docs/adr/0094`）。每个字段单独可选，缺哪个用哪个的缺省：`idleBaseMs`（待机等待的基数，默认 20 000）、`idleSpreadMs`（待机等待的抖动上限，默认 70 000）、`sceneChance`（待机回合抽场景的概率，默认 1/6）、`napChance`（待机回合打盹的概率，默认 1/12）、`angryClicks`（几次连击生气，默认 3）、`angryWindowMs`（相邻两次点击的最大间隔，默认 2 000）、`wanderWaitMinMs` / `wanderWaitMaxMs`（两次闲逛之间累计空闲的下限与上限，默认 120 000 / 300 000，前者不得大于后者）、`strollSteps`（一次闲逛的最多步数，默认 2；`pounce` 步态永远只走一步）、`hideChance`（闲逛到屏幕边缘时躲藏的概率，默认 0.7）、`gazeRadius`（眼神跟随的距离，单位是画布像素，默认 26，必须大于近圈 16 与出圈余量 4 之和）。没有 `behavior` 的包保持应用缺省脾气。

### 3.3 anchors.json

结构是 `{"actions": {"<动作名>": [每帧一项]}}`，每项 `{"head": [x, y], "face": [x, y], "body": [x, y]}`。

- 坐标是**画布像素**，相对帧左上角，y 向下；`[0, 0]` 表示这一层不位移。锚点不设范围校验，移出画布的部分不可见。
- 运行时语义：`body` 锚点平移整个身体层；`face` 锚点平移表情层（视线偏移在其上叠加）；三个锚点同时是 head / face / body 三槽**配饰**的落点。**效果层永远固定在画布原点，不受任何锚点影响。**
- 每个动作的锚点条目数必须等于该动作的 `frames`。`blink` 没有 sheet，**不列**锚点；列了即整只拒绝（`BadAnchors`）。
- 约定：待机动作的第 1 帧是基准，三个锚点都是 `[0, 0]`。应用从这一帧实测墨迹包围盒，用于悬停距离、场景对齐与设置预览——第 1 帧不要留大片空白，脚线贴住画布底，宠物才 “落地”。
- 每帧的锚点就是这一帧姿势造成的位移：身体在帧里画低了，就把三个锚点一起往下写；只动脸的帧只写 `face`。

### 3.4 accessories.json

结构是 `{"accessories": [...]}`，可以为空数组。每件配饰：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 本包内唯一，读者可见，按 §5 第 15 条清洗 |
| `slot` | 是 | `head` / `face` / `body` 之一 |
| `asset` | 是 | 配饰单图的相对路径，尺寸必须是 `canvas × canvas` |
| `zIndex` | 是 | 整数，值大者画在上层 |
| `supportedActions` | 是 | 只能列本包已有的动作 |
| `sceneWeights` | 否 | “场景 id → 正数乘子” 的对象：戴上后待机抽景把对应场景权重乘上该值，摘下即恢复，多件偏爱同一场景时相乘（`docs/adr/0102`）。键必须是本包已有的动作；**场景属于应用，包没有场景，所以包里的权重只被校验与保存，不改变行为**（见 §8）。值大于 0、至多 4，一件配饰至多列 8 个场景；缺省或空对象与没有这个字段相同 |

配饰画一次（按待机姿势），之后只靠槽位锚点移动；`supportedActions` 里没列的动作不显示它。

### 3.5 PNG 的画法

全部 PNG 为 RGBA 透明底，**单行横排，帧间无间距**：

| 图 | 尺寸 | 摆放 |
|---|---|---|
| 身体 sheet | 宽 `frames × canvas`，高 `canvas` | 第 i 帧在 `x = i × canvas` |
| 特效 sheet | 与同动作的身体 sheet 完全相同 | 同上 |
| 表情 sheet | 高 `canvas`，宽为 `canvas` 的整数倍 | 一排 `canvas × canvas` 的格子，至多 64 格 |
| 配饰单图 | `canvas × canvas` | 单帧 |

- 表情格子里画的是**全画布上的五官**：按自然位置对准身体画，`face` 锚点为 `[0, 0]` 时两层正好重合。
- **索引 0 是默认脸**：没有 `expressions` 的动作全程用它；作者自定义每格长相，应用只读被 `expressions` 数组和 `blink` 条目引用的索引。推荐备齐：默认、闭眼（眨眼用）、困、眯眼、开心、惊讶、生气、半睁。
- 特效层不跟随身体（固定在画布原点）；挂在身上的图形画进身体层，跟脸但不随压扁的位移靠 `face` 锚点。

## 4。上限

超限即拒绝整只包。数值为 v1 规范值。

| 项 | 上限 |
|---|---|
| 包目录总大小 | 32 MB |
| 单个 PNG | 8 MB |
| 单个 JSON | 256 KB |
| 文件总数 | 512 |
| `canvas` | 16–128 |
| `scale` | 1–4 |
| 单个动作的 `frames` | 1–64 |
| `fps` | 1–24 |
| `duration` | 1–3 600 000 ms |
| `hover` 的三个延迟 / 冷却 | 各 0–60 000 ms |
| `behavior` 的时间字段 | `idleBaseMs` 1 000–600 000；`idleSpreadMs`、`angryWindowMs`、`wanderWaitMinMs`、`wanderWaitMaxMs` 各 0–600 000 |
| `behavior` 的概率字段 | `sceneChance`、`napChance`、`hideChance` 各 0–1 |
| `behavior` 的计数字段 | `angryClicks` 1–10；`strollSteps` 1–4 |
| `behavior.gazeRadius` | 大于 20（近圈与出圈余量之和），至 128 |
| 动作数 | 32 |
| 配饰数 | 32 |
| 单件配饰的 `sceneWeights` 条目 | 8 |
| `sceneWeights` 的单个权重 | 大于 0，至多 4 |
| `idlePool` 条目 | 16 |
| `movement.range` | 10–60（窗口宽度的百分比） |
| 单张 sheet 的声明宽度 | `frames × canvas`，且不超过 8192 |
| 表情 sheet 格数 | 64 |
| `name` 长度 | 32 个字符 |
| 整包解码后的像素总量 | 16 M 像素（约 64 MB 位图） |

`frames`、`fps`、`canvas` 的上限同时是溢出防线：`frames × canvas` 与 `frames × 1000` 都在 `int` 范围内。

超过上限的拒绝为 `TooLarge`。低于下限或类型不对的，按所在字段归类：`pet.json` 为 `Format`，动作为 `BadAnimation`，锚点为 `BadAnchors`，配饰为 `BadAccessory`。

`name` 先去掉控制字符、双向文本控制符与零宽字符，再做 NFC 归一，然后才数长度。去掉后为空是 `BadName`；超过 32 个字符是 `TooLarge`，不截断。

## 5。校验规则

按顺序执行，任一条不满足即拒绝整只包，不带残缺状态运行。规则编号供测试引用。

**路径与文件**

1. 资产路径只能是相对路径。拒绝绝对路径、盘符相对路径（`C:foo`）、UNC 路径（`\\server\share`）、以及任何 `..` 段。
2. 解析后的**规范路径**必须仍在包目录的规范路径之内。这一条覆盖重解析点：目录交接点（`mklink /J`）与符号链接不需要管理员权限即可创建，压缩文件也能携带链接条目，因此不能只看字符串。
3. 包目录内的路径不得是重解析点（符号链接或目录交接点）。包目录本身（`pets\<id>`）由读者放在那里，可以是链接；它之下的任何条目都不得是。
4. 只接受图片魔数为 PNG 的文件。**不依扩展名判断类型**：`QImageReader` 默认按内容嗅探格式，SVG 等格式会因此被当图片加载，所以必须核对魔数。
5. 每个 JSON 文件解析失败即拒绝。

**数值**

6. `format` 必须存在且为 `1`。
7. `canvas`、`scale`、`frames`、`fps`、动作数、配饰数、`idlePool` 条目、`hover` 的三个延迟、`movement.range` 与 `behavior` 的各字段均在 §4 范围内；`hover` 的 `notice` / `dwell` 必须是本包已有的单次动作，`dwell` 不能脱离 `notice` 单独出现；`movement.style` 必须在闭集内，`movement.walk` / `peek` 必须是本包已有的循环动作；`behavior` 的 `wanderWaitMinMs` 不得大于 `wanderWaitMaxMs`，`gazeRadius` 必须严格大于 20。`sceneWeights` 必须是对象，条目数与每个权重在 §4 范围内，每个键是本包已有的动作。
8. 每张 sheet 的像素尺寸等于 `frames × canvas` 宽、`canvas` 高；表情 sheet 高为 `canvas`、宽为 `canvas` 的整数倍。
9. 每个表情索引（含 `blink` 的表情列表）小于表情 sheet 的格数。
10. 缩放倍数在 1–4 之内。

**标识与显示**

11. `id` 匹配 `^[a-z0-9_]{1,32}$`，且与目录名相同。
12. `id` 与任一随包 id 冲突时拒绝该包（不覆盖随包宠物）。比较不区分大小写，以覆盖 Windows 的不区分大小写文件系统。随包宠物的文件夹名即使校验失败，也仍保留。
13. `name` 去控制字符、去双向文本控制符、去零宽字符后非空，长度在 §4 之内，并做 NFC 归一。含被去掉字符的名字按去掉后的结果显示，不因此拒绝。

**结构**

14. 角色、动作、锚点、配饰的约束同 §3。
15. 动作名与配饰 id 可以自由取名。它们是读者可见的字符串，但不做清洗：含控制、双向或零宽字符，或超过 32 个字符的，整只拒绝（`BadAnimation` 或 `BadAccessory`）。

## 6。拒绝原因

应用界面显示一条本地化说明，**不直接显示包里的字符串**；原始解析信息只进日志。

| 原因 | 含义 |
|---|---|
| `Unreadable` | 目录或文件读不到，或包目录里没有 `pet.json` |
| `Format` | 缺 `format`、版本不认识，或 JSON 格式错误 |
| `TooLarge` | 超过 §4 的任一上限 |
| `BadName` | `id` 或 `name` 不合规 |
| `MissingRole` | 必需的动作角色没有映射 |
| `BadAnimation` | `frames`、`fps`、`loop`、`returnTo`、`idlePool`、`hover`、`movement`、`behavior` 不合规 |
| `BadAnchors` | 锚点缺失或条目数与帧数不符 |
| `BadAccessory` | 配饰字段不合法、id 重复、槽位未知、引用了不存在的动作，或 `sceneWeights` 的键或值不合法 |
| `BadAssetType` | 不是 PNG，或魔数与扩展名不符 |
| `SheetSize` | sheet 尺寸与帧数、画布不符 |
| `ExpressionIndex` | 表情索引越界 |
| `PathEscapes` | 资产路径越出包目录 |
| `IdTaken` | 与随包宠物 id 冲突 |

## 7。安全规则

**包不得做的，也是应用拒绝或忽略的：**

- 不含可执行文件、脚本、DLL 或 QML。应用不加载包内的任何代码。
- 不访问网络。应用不为包发起任何请求。
- 不读取包目录以外的任何文件（第 1、2、3 条）。
- 不通过显示名伪装成随包宠物或应用自身界面。来源标记由应用绘制，包无法影响它的有无与外观。

**应用守住的：**

- 包目录只读。应用不写入、不删除、不改名、不移动。这一条同时防止 “重解析点把一次写入重定向到任意路径”。
- 读者可见的包字符串一律按**纯文本**渲染（QML 侧 `textFormat: Text.PlainText`）。默认的 `AutoText` 会识别 HTML 并渲染富文本，包提供的名字或动作名因此可能插入图片标签或撑破版面。
- 显示名与 id 展示前做第 13 条的字符清洗与长度截断。
- 被拒包的界面说明只用上表的本地化文案，不用包里的字符串。
- 解析在读取前先按文件头与声明尺寸核定，再决定是否解码，避免 “声明尺寸巨大而文件极小” 的图片炸掉内存。
- 一只包失败只影响它自己：其余宠物与程序照常，启动不受阻。

## 8。与随包宠物的差异

| | 随包宠物 | 宠物包 |
|---|---|---|
| 位置 | 安装目录 `data/pet/` | `%APPDATA%\Lens\pets\` |
| 写入者 | 开发者 | 读者 |
| 显示名 | `qsTranslate` 按 id 对照，跟随界面语言 | `name` 去掉控制字符后显示，不翻译 |
| 来源标记 | 无 | 标注外部来源 |
| 首次启用 | 直接启用 | 弹一次确认 |
| 场景 | 有，每只六个，`sceneWeights` 改变抽景 | 无；`sceneWeights` 通过校验与保存，但当前不生效 |
| 提问牌 | 随包 sprite 素材（`sign.json` + `sign\`） | 应用绘制，包不参与 |
| 缺失或被拒 | 回退到随包默认宠物，不弹通知 | 回退到随包默认宠物，弹一条通知 |
| 校验 | 同一套 | 同一套，另加上限与路径规则 |

除上表各项外，包与随包宠物能力相同：角色、眨眼、视线跟随、靠近反应、闲逛、躲藏、脾气与配饰都由包数据驱动，配齐了就是一只完整的宠物。

## 9。制作一个包

两条路，产物相同。

**手写（第三方作者）**：在 `%APPDATA%\Lens\pets\` 下建 `<id>\` 目录，写四个 JSON、画 PNG。下面的最小可行包可以直接起步——10 个必需角色共用一个循环动作，配上 `blink` 与一排表情就能加载，之后按 §3 加动作、配饰与可选块：

`pet.json`：

```json
{
  "format": 1,
  "id": "minimal",
  "name": "示例",
  "canvas": 88,
  "scale": 3,
  "layers": { "body": 0, "expression": 2, "effect": 6 },
  "expression": "sprites/expressions/eyes.png"
}
```

`animations.json`——多个角色共用一个动作是合法的：

```json
{
  "roles": {
    "idle": "still", "study": "still", "thinking": "still",
    "celebrate": "still", "encourage": "still", "sleep": "still",
    "click_react": "still", "pickup": "still",
    "look_around": "still", "yawn": "still"
  },
  "idlePool": [],
  "actions": {
    "still": { "frames": 2, "fps": 2, "loop": true,
               "expressions": [0, 0], "sheet": "sprites/body/still.png" },
    "blink": { "frames": 3, "fps": 10, "loop": false,
               "expressions": [1, 2, 1] }
  }
}
```

`anchors.json`——只列有 sheet 的动作，条目数等于帧数；`blink` 不列：

```json
{
  "actions": {
    "still": [
      { "head": [0, 0], "face": [0, 0], "body": [0, 0] },
      { "head": [0, 0], "face": [0, 0], "body": [0, 0] }
    ]
  }
}
```

`accessories.json`：

```json
{ "accessories": [] }
```

最小包只需要两张 PNG：`sprites/body/still.png`（176 × 88，两帧）与 `sprites/expressions/eyes.png`（至少 3 格，264 × 88）。

**随包管线（开发者）**：写一份配方，跑渲染器。

```sh
python -I scripts/pet/render_pet.py <id>
```

渲染器写出 `data/pet/<id>/`。把它整个目录复制到 `%APPDATA%\Lens\pets\` 下，再打开设置的扩展分类即可看到。`docs/pet-art-pipeline.md` 是完整流程、约束与经验。

自查（应用加载时仍会再查一遍）：`roles` 覆盖 10 个必需角色且名字都在闭集内、`idlePool` 只列单次动作、`returnTo` 指向已映射角色、`duration` 为正数、`hover` 的动作存在且为单次、`hover.dwell` 不脱离 `hover.notice`、`movement.walk` / `peek` 存在且为循环、`behavior` 与 `sceneWeights` 的各字段在 §4 范围内、有 `blink` 条目且 `blink` 不在 `anchors.json` 里、锚点条目数等于帧数、sheet 尺寸等于 `frames × canvas`、每个表情索引小于格数、PNG 魔数正确、路径无 `..`。

## 10。用 AI 一次生成一只宠物

把**本文件全文**连同下面的模板发给 AI，只替换 `<…>` 一处。AI 应交付一个自包含的 Python 脚本（第三方依赖只用 Pillow，`pip install pillow`），运行 `python make_pet.py` 后在当前目录写出 `pets/<id>/` 完整目录；把 `<id>` 目录整个复制到 `%APPDATA%\Lens\pets\` 下即可。被拒时把 §6 的原因发回给 AI 修。

默认目标是 **“第八只随包宠物”**：凡本格式允许的能力，除非你在描述里明确说不要，否则一律配齐。包做不到的只有两件——没有场景（`sceneWeights` 被保存但不生效），提问牌由应用绘制。

```text
请作为 Lens 桌面宠物的包作者，严格按随附的《宠物包格式》生成一只全新宠物包。

我想要的宠物：<物种、外形、配色、性格、想要的动作气质与配饰，越具体越好>

流程（按顺序执行，每道检查点都停下来，得到我的明确认可后才继续）：
0. 若我描述的是一个已存在的形象：先网络搜索它的官方图片，把找到的参考图
   下载下来亲眼看过，再告诉我你打算怎么还原（轮廓、配色、标志特征），
   等我确认后才开始画。原创形象跳过这一步。
1. 检查点一：先只画待机动作的第 1 帧（身体层 + 默认脸叠好），放大 3 倍存成
   预览图给我看。形象不好看就改到认可为止；全套生成在此之后才开始。
2. 检查点二：全套生成并通过自查后，把所有动作、表情与配饰拼成一张预览图
   给我看，经我确认才算交付。

硬性要求：
1. 交付一个自包含的 Python 脚本，第三方依赖只用 Pillow；运行后在当前目录写出
   pets/<id>/ 的全部文件。四个 JSON 以字面量写在脚本里，PNG 由脚本绘制。
   id 按格式规范 §5 第 11 条取名。脚本最后自查并打印结果：sheet 尺寸 = 帧数 × canvas、
   每个表情索引 < 表情格数、锚点条目数 = 帧数、id 与目录名一致。
2. 默认按 “第八只随包宠物” 配齐，仅当我上面的描述明确说不要时才省略：
   - 14 个角色全部映射，每个角色一个独立动作；动作名见规范 §3.2 的角色表
   - idlePool、hover、movement、behavior 全部给出，数值都在 §4 上限内，
     behavior 按这只宠物的性格取一套温和的定制值
   - 9 件配饰，head / face / body 各 3 件，每件都写 supportedActions
   - 表情 sheet 至少 10 格，索引 0 是默认脸；每个会眨眼的动作标 blink: true
   - 每个动作每帧都有锚点，待机第 1 帧三个锚点都是 [0, 0]，
     第 1 帧不留大片空白、脚线贴画布底
3. 只写规范列出的字段；规范没写的字段一律不要发明。
4. 不要做的事：不生成 sign/ 目录与 sign.json（提问牌由应用绘制）；
   不写 sceneWeights（包宠物没有场景，写了也不生效）。
5. 默认值：canvas 88、scale 3；PNG 全部 RGBA 透明底，单行横排，帧间无间距；
   同一动作的特效 sheet 与身体 sheet 尺寸完全相同。
6. 交付前按规范 §9 的自查清单逐条核对，然后列出生成的文件树与运行方法。
```

## 11。已知边界

- 包未经审核、未签名。本规范只保证 “不执行代码 + 契约校验”，不保证包的外观与行为符合预期。场景是应用自带内容，包没有场景；`sceneWeights` 会被接受与保存，但当前没有可倾斜的抽景。
- 规范只到 v1。未来版本会另行编号，未知版本按 `Format` 拒绝，不做迁移。
- 配饰 PNG 的内容不限画法；随包配方的渲染器支持格子、像素与画布像素，但没有圆形或多边形图元（渲染器的限制，见 `docs/pet-art-pipeline.md` §5）。
- 界面显示名的长度上限是 32 个字符，中文字符按一个计。
