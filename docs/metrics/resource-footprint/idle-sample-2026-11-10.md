# 空闲水位短程采样

## 对象与口径

一次只读采样：没有驱动应用，没有改设置，没有停止任何正在运行的实例。对象是
`build-ninja-release` 里的 `lens.exe`，PID 22384，启动于 18:51:10，采样时已运行约三十五分钟。
这棵树没有开发面，所以 `state` 列是空的，也无法用 `surface show` 驱动它。

```
powershell -File scripts/qa/lens-measure.ps1 -ProcessId 22384 -Seconds 60 -Interval 10 -Cpu -Out logs/measure-20261110-idle.csv
```

读的是 `Get-Process` 的 `PrivateMemorySize64`、`WorkingSet64`、`Threads.Count` 与
`HandleCount`。`cpu_cores` 是两次采样之间的处理器时间除以墙钟，单位是核，首行没有前一个
间隔所以是 0。这一列是本次新加的开关，顺带验了它能落进 CSV。

## 读法

私有字节在六十秒里从 407.6 到 407.4 MB，没有单调上涨；工作集几乎不动；线程 193 到 189、
句柄 6658 到 6638 都在慢慢回落。CPU 在 0.039 到 0.056 核之间，是空载的样子。

这一分钟不能拿去和 2026-10-05 的 156 MB 空闲态或 2026-10-18 修复后的约 270 MB 关闭态
直接比：构建不同，进程还带着读者的使用史，采样时也不知道哪几张表面开着。它值得记下的是
起点本身：407.6 MB、6658 句柄，比 10-18 报告里关掉八个表面之后的 270 MB、约 4500 句柄
高出一截。这可能是某张表面仍开着的一次性全价，也可能是 9.9 节那笔没有定位的慢速爬升
攒出来的，六十秒答不上来，正是长稳复测要追问的第一件事。

不对时间下断言，一次结论至少三轮，报区间不报点值。

## 没覆盖到的

- 没有反复开合表面、没有注入扫描帧、没有连打设置。`scripts/qa/lens-soak.ps1` 的试跑要求
  同一时间只有一个 `lens.exe`，这次没有去停读者正在运行的那个实例。
- 分配点没有定位，需要 `scripts/qa/heap-diff.ps1` 与 UMDH 的两次堆快照。
- 六十秒不是数天，托盘常驻应用的长稳仍要按 `docs/qa.md` 的一轮以上的驱动配出数小时。
