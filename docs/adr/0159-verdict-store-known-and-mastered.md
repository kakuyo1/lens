# 0159 判定库：一词两判，掌握退出流通

- **状态**：accepted（取代 ADR 0147 的二元判定口径、ADR 0158 的文件即来源）
- **背景**：二元判定把 “还在学” 与 “学完了” 压成一个动作：标已会即虚线消失、扫描跳过。铅笔层（0154）画出的全部 New 候选里，大量是读者早已掌握、只是不在任何词书覆盖内的词；逐词的出路只有档位频段、八本词书与自定义词表（0158），而自定义词表是只读的外部文件——不能逐词生长、不随同步走、文件丢失即清空判定。复习选词只看到期（`review_schedule`；`ReviewDuty::askable` 只过滤无缓存解释的词），“学完了” 也没有退出复习的通道：三态候选枚举里 `Mastered` 一直只有档位一个来源，读者自己的 “完全掌握” 没有落点。
- **决定**：
  - **一词一存，两判**：判定库（`KnownStore` 的 marks）每词至多一值——已会或掌握，缺席即新词。布尔 marks 升为判定值，`markTimes` 与墓碑结构不动；false 票语义从 “撤销已会” 扩为 “清除判定”，0147 的 newest-wins 否决票逻辑原样继承。
  - **已会 = 见过，仍在学习中**：铅笔层虚线保留但换样式（样式见 UI-SPEC 4.20），Alt 悬停与复习照旧——复习本就不读判定。它不再让虚线消失：已知库 “扫描据此跳过” 的行为整体移交给掌握。
  - **掌握 = 完全掌握，退出流通**：不画虚线、不预取路标、不进复习（`askable` 跳过判定掌握的词）；选区永远解释、查词历史与统计不动（TODO 第 0 条原则不变）。
  - **档位推导不变**（0155）：显示态 “已掌握” = 频段 ∪ 档位词书 ∪ 判定掌握；档位永不写入判定库。释义链点线从 “只看档位” 改为 “档位 ∪ 判定掌握”：读者判了掌握的词不再有点线，已会词照旧。
  - **自定义词表降为批量种子**：设置里选 `.txt` 导入，词条经 lemmatize 去重一次性写入判定掌握值，此后文件不再被监视，`customWordlist` 键退役，“缺失即清空” 随之作废。判定的权威在 settings.json 的分节里（0012、0024），随同步走。
  - **同步**：判定走现有 known 分区（0042、0157），per-lemma 形状加 `mastered` 布尔，掌握记 `learned` 与 `mastered` 同真——旧客户端把它降读作已会。一台设备标已会、另一台标掌握，时间新者赢。
- **后果**：
  - `scanJudged_` 必须随判定修改失效（TODO.md 自动扫描一节），否则同页标完虚线不走；落地时一并修。
  - 词汇弹窗的行从 “查过的词” 扩为 “判定库 ∪ 查过的词”：判定库里没有历史行的词（铅笔层掌握按钮、词汇导入、另一台设备的同步）占一行，无时间、0 次，排在该档末尾按词根排序；导出同行——ADR 0104 的 “words 是词汇” 口径由此完整。
  - 铅笔层的逐词标记入口（键盘手势先行、Alt 期悬浮按钮第二步）另记 ADR：0154 的 click-through 是窗口级决定，为悬浮按钮开输入是独立的取舍。
  - 词汇弹窗从两桶变三桶，气泡判定行多一枚胶囊；“新词” 胶囊语义收窄为 “清除判定”，幂等确认与墓碑机制不变。
  - 旧 marks 零迁移：true 即已会。
  - 被排除的方案：known-set 与 mastered-set 两库并存——两值天然互斥，两份存储只是把一份判定库非规范化，同步、墓碑、合并全要复制一套；已会保持 “虚线消失” 再加第二个过滤档——两按钮在扫描管道里行为重叠，是两个互相打架的沉默键；查词历史自动升已会——判定保持显式，“查过未判即新词” 的口径不变；掌握存独立 txt——可写、同步、撤销都要结构化数据，txt 装不下。
