# 0096 每只宠物有自己的窝：大小、配饰与落点按宠物 id 记忆

- **状态**：accepted（2026-10-24）。
- **背景**：PET 段里配饰、大小与窗口落点只有一份，属于 “读者” 而不属于任何一只宠物。换宠时上一只的帽子先戴到新宠头上（目录里没有的再逐件摘掉）、滑杆读数跟着上一只走、新宠走进的是旧宠的 home。七只随包宠物各有性格与装扮，读者给每只的打扮与安顿本该是它们自己的。
- **决定**：
  - **三样按宠物 id 各记一份**：PET 下新增 `pets` 对象，`pets[<id>]` 持 `size` / `accessories` / `position`，键名与语义不变。开关、鼠标穿透与确认列表仍是读者的，保持全局。缺项回退不变：大小用包声明 scale 的百分比，配饰为空，落点无记忆。
  - **换宠即回窝**：新宠回到它记忆的落点——当时那块屏上的位置；那块屏不在、或放不下现在的窗口，就继承换宠发生的位置。它穿戴自己的配饰、用自己的大小。第一次上场的宠物没有任何记忆，继承当时的窗口位置，落定时写下来成为自己的窝。
  - **一次性迁移**：构造 PetStore 时把平铺的 `size` / `accessories` / `position` 挪进 `pets[<文档点名的宠物>]`——平铺值本就属于当时在场的那只——然后删掉平铺键；迁移只跑一次，文档不留歧义。
  - API 上三个存取器都显式收宠物 id（`size(id, fallback)` 等），控制器始终用在场的那只；不做 “激活宠物” 的隐藏状态。
- **后果**：
  - 换宠的两条旧语义作废：旧宠的配饰不再带到新宠身上，也不再有 “摘掉就不再回来”——切回来就回来了；新宠不再走进旧宠的 home。对应 qtest 用例已改写。
  - `pets` 里的条目不随包删除清理：与确认列表同样对待，残留无害。
  - 窗口落点仍只在拖动落定、尺寸回收等真实事件时写入；换宠仪式本身只为第一次上场的宠物写一次。
