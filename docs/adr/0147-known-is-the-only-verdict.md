# 0147 已会是唯一的判定：新词是它的缺席

- **状态**：accepted（2026-10-31，收敛 `docs/adr/0042` 与 `docs/adr/0122` 里的三态判定口径）
- **背景**：词的判定存在两个来源，口径却不一致。已知库（`KnownStore::marks_`）是三态：`true` = 已会，
  `false` = 显式新词，absent = 未标记；气泡卡徽章早已按它做二元推导（`isKnown ? "known" : "new"`，
  未标记的词在卡上显示绿色 “New”）。词汇弹窗却读统计历史行的盖章 verdict（`""` / `"known"` / `"new"`），
  未标记的词两枚胶囊皆空——同一个词在卡上是 “新词”，在词表里是 “什么都不是”。多端同步合并后两个来源
  还会分叉（marks 按 newest-wins 合并，历史按并集合并），哪个都不该独自当显示权威。而显式 “新词” 标记
  在管线里没有任何行为效应：弹词顺序、扫描准入、复习池全都只看 known-set，`GLOSSARY.md` 承诺的
  “优先弹” 从未有过实现。它真正的作用只有三件：同步合并里的一张否决票、清除删除墓碑、给历史行盖章。
- **决定**：
  - **判定二元：`isKnown(lemma)` 为真即已会，其余一律新词**。未标记与旧 false 标记在显示上不可区分，
    都是未标已会。“已会” 是读者唯一的判定动作；“新词” 不再是一个要按下去的选择，而是行的默认状态。
  - **展示一律从 known-set 推导**，不从历史盖章读：`wordRowList` / `rowInScope` / `exportLemmas` /
    `exportLemmasJson` 都拿 `KnownStore::known()` 做参数，Known 桶 = 集合持有，New 桶 = 集合不持有。
    词表筛选、导出、气泡徽章从此同源，合并分叉不再影响任何显示。
  - **弹词时按当前标记态盖章**：`recordPop(lemma, minute, known)` 把 `"known"` / `"new"` 写进历史行，
    日计数从弹词那一刻就落在正确的栏里（已会词重查记已会，其余记新词）；`recordVerdict` 只在改判时
    移栏。统计弹窗的已会 + 新词两行从此相加恰等于当日弹词（旧数据除外，见后果）。
  - **存储与同步格式原样不动**：`mark(lemma, false)` 保留，语义收窄为 “撤销已会 / 确认新词”——它写下的
    false 票按时间戳参与 newest-wins 合并、能翻掉另一台设备较旧的已会标记、并照旧清除删除墓碑。删掉它
    而只存 “无标记”，另一台设备的旧已会票就会在合并时复活，多端正确性不保。
  - **胶囊动作不变**：词表与气泡的四枚胶囊仍各自调 `mark(lemma, true|false)`。在未标记行按 “新词” 是一次
    幂等的确认（把判定时刻写进同步），在已会行按它才是真正的改判。
- **后果**：
  - 旧文档里的空盖章与旧 false 标记都读作未标已会：空盖章不再被任何显示读取，false 标记与 absent 同义，
    两者都无需迁移。
  - 统计的旧日期保持原账（当年未标记的弹词两栏都没记），新日期才是二分口径；`daily` 的同步形状不变。
  - 历史盖章与 marks 在多端合并后可能不一致（stamps 并集，marks newest-wins）；盖章只剩统计机制，
    显示不理它。弹词时按标记态盖章已把本地流程的分叉收干净，剩下的分叉只来自对端设备。
  - 一条已死的兜底保留：`recordVerdict` 找不到历史行时只动当日 tally。词表与气泡能碰到词的地方它必在
    历史里，这条路径实际不可达，留着只为防御损坏的文档。
  - 气泡判定行的一次性提示句从 “New marks it for more practice” 改为 “New keeps it in practice”，
    五个语言目录随之更新。
  - 被排除的方案：给未标记一个名字（“查过” 第三态标签）——只是把问题改名，没有回答 “它到底是不是生词”；
    行内改单枚三态控件——丢单击改判，且与气泡反馈行的两枚胶囊词汇不一致；给 “新词” 补上真正的优先弹——
    为一个从未存在过的承诺加机制，方向反了。
