# 0055 预尺寸窗口只用于顶边固定的表面

- **状态**：accepted（2026-10-17）；面板部分在同日手测后回退。
- **背景**：三个表面的高度直接绑内容：气泡的判定行随悬停展开和收起、词汇面板筛选时行高折叠和展开、
  年度面板的调色板展开。内容在 180–220 ms 里连续变化，窗口高度就每帧变一次，Windows 每次都真的
  调一次 `SetWindowPos`；面板还挂着 `holdCorner`，高度一变 y 也跟着变。基线一次过渡有 8–13 次原生
  高度变化，帧间隔中位数从显示节拍的 11 ms 拉到 13–18 ms，p95 到 33 ms。
  P0-2 曾让三个表面都在过渡起点一次跳到最大高度，内容在预尺寸的窗口里动。测量结果见
  `docs/metrics/runtime-performance/content-transition-window-resizes-2026-10-17.md`：原生高度变化都降到
  1 次，帧 p95 降到 12 ms。但手测发现两个面板在过渡中闪烁，比改动前更糟，因此只保留气泡。
- **决定**：
  - **气泡保留预尺寸**：气泡的窗口顶边在放置后不动（只有贴近屏幕下缘时由 `keepOnScreen` 推一次），
    判定行向下展开。窗口在起点一次变高，多出的空间正好是判定行要长进去的地方，卡片和内容都不在
    窗口内移动。`HeightHold.qml` 记录 `floor = max(当前内容高, 目标内容高)`，窗口高读
    `round(max(floor, 内容高) + 页边距)`；`duration + 17 ms` 后检查内容是否到位，还差就每 17 ms 重试，
    最多 4 次。减少动效时 `duration` 为 0，不建立 hold。目标由 `begin()` 从调用方传入。
  - **两个面板回退到逐帧跟随内容**：词汇面板筛选、年度面板调色板恢复
    `height: column.implicitHeight + 页边距`，窗口每帧跟着内容变，`Main.holdCorner` 每帧保持着右下角。
    移除 `ShadowCard.reserve`、面板的 `HeightHold` 与只为预尺寸服务的 `Controller.wordCounts`。
  - 回退的原因不是 resize 次数，而是**卡片在窗口里移动**：面板以右下角为锚，窗口变高时 y 同时改变；
    为了让卡片的可见底边在过渡期间保持不动，卡片必须在预尺寸的窗口里每帧下移、缩短（reserve）。
    窗口固定而卡片在窗口内连续移动，在真实的 Windows 透明窗口上读作闪烁。旧的逐帧跟随虽然 resize
    更多，卡片在窗口内的位置始终是 `shadowMargin`，观感反而稳定。
  - 因此预尺寸只适用于**内容朝锚点反方向生长、卡片本身不必在窗口里移动**的表面；底边锚定的面板
    若要去掉 resize，需要另外的方案（例如窗口在锚点之外常驻并配 mask 让透明区穿透），不是本 ADR
    的范围。
- **后果**：
  - 气泡：iOS 悬停展开的原生高度变化从 13 次降到 1 次；贴近屏幕下缘时会在起点被上推一次
    （1 次 y 变化）。最终高度与旧版逐像素相同（224 / 279）。
  - 气泡在过渡的 180–220 ms 里比卡片多出一块透明区域，参与命中测试：点在那里不会穿到下面的窗口。
  - 两个面板保留 8–13 次原生高度变化与旧的帧节奏；视觉与 P0-2 之前一致。测量文档中面板一栏是
    被否掉的试验版本，不能当作当前实现的数字。
  - 被排除的方案：给窗口设 mask（要原生桥，且要覆盖圆角与阴影）；对高度去抖或节流（仍会 resize，
    只是次数少）；把内容预渲染成图片做交叉淡入（内容都不是静态图）。
