# 0185 托盘教学留在引导卡内

- **状态**：accepted（2026-11-16）
- **背景**：首次引导第三步原来是 “试一次”：读者拖选示例里的词，演示气泡就在卡旁出现。托盘这件事原先只在第三步末尾的一行字里带过；读者完成时最容易问的却是 “窗口去哪了”。四个方向在 `ui-prototypes/onboarding-tray-candidates.html` 里做过对照：完成后把向导窗口缩进托盘（A）、让托盘菜单自己升起并逐行点亮（B）、在卡内画一块托盘近景（C）、交给 Windows 的托盘气泡（D）。
  - A、B 都指向真实的托盘图标，但图标由 shell 绘制：应用不能缩放它，也不能替它画外圈；Windows 11 还会把新图标收进溢出菜单（^），动画的锚点可能根本不在任务栏上。两条路要么加一层贴在托盘上的小浮层（新表面，先改 §4.0 并记 ADR），要么放弃图标反馈。
  - D 不依赖图标位置，一条 `QSystemTrayIcon::showMessage` 即可，但外观、位置与时机都由 Windows 决定，Focus Assist 会吞掉它，而且它不打开菜单。
  - C 不新增表面、不依赖真实桌面与图标是否可见；代价是它只能画，不能真的点。
  - 选定 C 后，第一版把它塞在第三步示例区下面：第三步同时承担 “试一次” 和 “看托盘” 两件事，内容拥挤，托盘也打断了试一次的节奏。复核时决定把托盘教学独立成第四步。
- **决定**：
  - 首次引导扩为四步：第三步恢复原来的试一次（完整导语、示例区，不再带托盘说明），第四步只讲托盘。
  - 第四步是一句 “没有主窗口；菜单与设置都在托盘里。” 加一块卡内托盘近景（UI-SPEC 4.19）：30 px 的任务栏条、托盘图标与一张 192×106 的迷你菜单。进入第四步约 0.54 s 后播一次：图标轻弹 180 ms、外圈 220 ms，菜单 180 ms 升起，首行与设置行各亮 440 ms，然后停在展开态。
  - 只播一次：同一次向导里回到第四步仍停在展开态；减少动效时直接停在展开态。整块是示意图，不是可点的菜单，不发请求。
  - 菜单首行取当前托盘状态（与 4.2 同一套优先级，产品标随状态取 `ok` / `warn` / `faint`），语言行取当前界面语言；文案经 `qsTranslate("TrayMenu", …)` 复用托盘菜单自己的条目，不新开一套译名。
  - 第三步的导语、示例区内边距与块间距恢复原值；托盘近景在第四步有整张卡的高度可用。
  - 第三步的演示气泡只属于第三步，离开即收；第四步不带着上一张卡的东西。
  - 近景不画外框：卡片本身就是桌面，任务栏条与菜单直接站在卡上。
- **后果**：
  - 首次引导从三步变四步：`stepCount`、步骤标签、底部 `Next` / `Done` 的出现时机与 `Esc` 的逐级后退一起改；ADR 0148 的三步结构以本决定的第四步为准。
  - 第三步不再需要为托盘挤空间；第四步只有一句导语与一块近景，源语言下不需要滚动。`UI-SPEC` 4.19、`PRODUCT.md`、原型与 qtest 同步。
  - 近景里的菜单是画出来的：`popup` 底、`line` 描边与一枚小阴影，不是真实玻璃，也不随桌面幕布变化；玻璃主题下它仍按 `popup` 档取色。
  - 被排除的 A、B、D 与原型保留在候选页做对照。托盘图标本身仍然不能 “表演”：以后若要指认真实图标，得先解决溢出菜单的可见性，单靠动画不够。
