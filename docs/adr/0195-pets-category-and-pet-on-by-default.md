# 0195 宠物分类取代拓展，桌面宠物默认开启

- **状态**：accepted（2026-11-18）
- **背景**：宠物系统已经成熟，复习提问（ADR 0142）这一核心入口由桌面宠物承载，而设置里的
  “拓展” 分类只放着桌面宠物，名不副实；宠物默认关闭又意味着读者要先找到开关，复习提问才能用上。
- **决定**：
  - 分类改名 Pets / 宠物：显示名、路由 id `extensions` → `pets`、文件
    `SettingsExtensionsPage.qml` → `SettingsPetsPage.qml` 一并改，不留 “界面叫宠物、内部叫拓展”
    的半截状态。分类摘要仍是 “Desktop companion”，开关标签不变。
  - 桌面宠物默认开启（`PetStore::enabled` 缺省 `true`）。宠物只接收事件类型，读不到屏幕文字、
    选区或释义（`SECURITY.md`），默认开启不扩大隐私边界，复习提问开箱即用；读者仍可在宠物分类关闭。
- **后果**：
  - `PRODUCT.md` / `UI-SPEC.md` / 五份 README / marketing 的 “默认关闭 / 扩展” 同步为
    “默认开启 / 宠物”；旧 ADR 里的 “拓展页 / 扩展分类” 是当时的名称，不回改。
  - 缺省只影响没有 `enabled` 键的新配置：已有读者的开关与所选宠物照旧，不被强行打开或换宠。
  - 首启即出现宠物（启动时已开启则原地出现，`UI-SPEC.md` 4.15）；宠物缺失或被拒时按 ADR 0043
    回退到随包默认宠物 mochi。
  - 被排除的选项：保留 “拓展” 分类名（只放宠物，名不副实）；维持默认关（把核心复习入口藏在开关后）。
