# 0068 开发面：用命令驱动界面状态，不碰鼠标

- **状态**：accepted（2026-10-18）。新增构建开关 `LENS_ENABLE_DEV_SURFACE`，默认 OFF，出厂构建不含该代码。
- **背景**：这个项目要长期维护，性能复测会反复做，而今天能做复测的唯一办法是截屏定位加注入鼠标
  （`scripts/qa/ui-*.ps1`）。这条路有三个绕不过去的毛病：
  - **抢鼠标**。低层钩子的回调跑在安装它的线程上，注入事件期间这台机器上的人不能正常用机。
  - **位置不确定**。托盘图标被 Windows 收进溢出面板、宠物在 `settings.json` 里的位置已过期、DPI 缩放让逻辑像素
    与物理像素差 1.25 倍。2026-10-18 的内存调查为此在托盘图标上折了三次，最后改走 “右键宠物”。
  - **没有完成信号，也看不到内部状态**。只能 `sleep 3` 再采样，于是把 “释放完成” 读成 283.9 MB（实际 260.0）；
    只能从 CPU 反推幕布发布了几次；只能读 `settings.json` 猜生效主题 —— 有一轮因为主题没恢复，整批数据作废。

  仓库里已有同类形态：`LENS_ENABLE_QML_DEBUG` 打开 `QT_QML_DEBUG`，`main.cpp` 据此读
  `LENS_QML_PROFILE_SCENARIO` 并调用 `ProfileScenario.qml` 的步骤。但它在 QML 调试构建里、剧本写死、
  无回读，且调试构建不能用来量内存（项目自己在 `CMakeLists.txt:74` 注明它改变插桩）。

- **决定**：
  - **独立开关**。`option(LENS_ENABLE_DEV_SURFACE ... OFF)` 定义 `LENS_DEV_SURFACE`，只在 `src/app` 内编译
    `dev_surface.cpp/.h` 与 `DevSurface.qml`。不复用 `LENS_ENABLE_QML_DEBUG`：量内存必须用发布优化配置，
    而 QML 调试会改变插桩。
  - **两条通道，一张命令表**。启动参数 `--dev-script=<file>` 逐行执行；本地管道 `--dev-pipe=<name>` 驱动运行中的
    实例。两条通道走同一个执行器，管道只在编译时开了且显式传名时才创建。
  - **只做两层，不做系统输入层**。状态层（`surface show|hide|hide-all`、`setting set`）与钩子层
    （`selection x,y,w,h "text"`），不做 “移动指针、注入 `mouse_event`”。今天量到的 80 线程、幕布发布、
    释放滞后，全在前两层。
  - **每个命令调真实入口**。`surface show settings` 调 `Main.qml` 的 `showSettings()`，
    `setting set theme` 调 `AppController::setTheme()`。不复制摆位、不复制业务分支，否则量的是另一个程序。
  - **`state` 一次给全**：可见表面、窗口数、生效主题、每个表面的 `serial` 与发布次数、live 数量、
    每个窗口的首帧计数，一行 JSON。
  - **等待语义不进产品**。产品只回答 “现在是什么状态”，`settle`（私有字节在若干次采样内不再变化）由 harness
    判断 —— 那是测量侧的知识，产品侧不该懂。
  - **选区注入带文本**。`selection` 命令同时给坐标与文本，管线从 “文本已知” 那一点进入，跳过剪贴板读取。
    真实路径仍然走 `CaptureDuty::beginSelection()`，只是多一个可选文本参数。

- **后果**：
  - **被测二进制与出厂二进制不同**（多一张命令表、一个可选管道）。报告必须记构建配置与开关状态；
    开关不传参时零运行时成本。这与 2026-10-18 那份报告 “跨构建不并排比较” 的规矩一致。
  - **开发面可能和真实路径分叉**。命令走状态层，绕过了低层钩子与命中测试，所以它不能替代像素与观感验证：
    `ui-capture.ps1` 仍负责 “卡片对齐、阴影、图标画出来没有”，`TEST.md` §5 要写明这条分工。
  - **多一处要维护的接口**。每加一个表面，命令表要同步。约束是动词不超过十个，超出的走
    `lens_qtest_surfaces`，不要让它长成第二套 UI API。
  - **gated 代码会腐烂**。CI 需要一个 `-DLENS_ENABLE_DEV_SURFACE=ON` 的构建跑冒烟用例，否则半年后它编不过。
  - **命名要避开 `PROBE` 与 `console.log`**：`.githooks/pre-commit` 的 `PROBE_PATTERN` 会拦 `src/` 下含这两个
    串的文件。这条规则本身也要改：它假定 “`src/` 里的临时物都要删”，而开发面是常设的。
  - 排除的选项：**通用鼠标键盘驱动**（不确定性来自窗口位置、DPI、任务栏行为，工具解决不了）；
    **HTTP/RPC 服务**（本机测量工具，命名管道够用，加协议层只是多一处要维护）；
    **运行时开关代替编译开关**（编进去就会泄漏，只是时间问题）；
    **用 QTest 替代**（offscreen 不建 D3D 设备，量不到驱动线程，两者互补而非替代）。
