# 0104 次数一律写「次」，词数只指去重词汇

- **状态**：accepted（2026-10-24）。五轮 critique 的修复流②（状态诚实包）随本 ADR 落地。
- **背景**：同一个单位词 "words" 背后有两种语义。查阅次数（pop）数的是事件：今日弹词、年度总和、
  托盘 tooltip 的 "Today N words"。去重词数（dedup words）数的是词汇量：词汇弹窗标题、统计弹窗
  “历史累计”。PRODUCT.md 的「词汇列表去重」行写 “统计历史累计仍是弹词次数”，UI-SPEC 4.7 写
  “历史累计与词汇弹窗同值，都是去重后的词数”——两份权威文档互斥，实现跟了 UI-SPEC，而年度弹窗
  又把年度次数标成 "%1 words"（YearWordsPopup），与统计的 “历史累计 30 词” 同屏互打脸
  （critique P1）。需要一个口径把三处钉死。
- **决定**：
  - **次数（pop）一律写「次」/ lookups，永远不写 words**：托盘菜单统计行、托盘 tooltip、统计弹窗
    首屏标题、年度摘要的年度总数，全部改用 lookups。已有先例是年度日期行的 "%1: %2 lookups"。
  - **「历史累计」（All time）= 去重词数**，与词汇弹窗标题同源（`Controller.words.length`），维持
    UI-SPEC 4.7 与现有实现；PRODUCT.md 改过来，不是实现改过去。理由：词汇是一个集合，不是期间
    统计量——“学过多少个不同的词” 是读者对 “历史累计” 的直觉，事件数会随同一词的反复查阅膨胀，
    交给 “次” 表达。
  - **年度摘要双口径并列**：右侧写 “%1 lookups · %2 words”（年度查阅次数 · 词汇总量）。两数并列
    本身解释了去重：845 次查阅落在 30 个词上。第二口径取词汇总量而非 “年度去重词数”——词汇量
    没有期间语义，为它再造一个 365 天窗口的去重计数（数据也不存在）只会和词汇弹窗的全量标题
    打架。
- **后果**：
  - UI 文案里 "words" 从此只指去重词汇；写次数的地方再出现 words 视为 bug。检查口径：
    托盘菜单统计行、tray.cpp tooltip、统计弹窗标题行、年度摘要行。
  - PRODUCT.md「词汇列表去重」行与 UI-SPEC 4.2 / 4.6 / 4.7 / 4.8b 的示例文案随本 ADR 改。
  - 花费弹窗的 “日均” 口径（分母天数）不在本 ADR 内，仍由 critique P3 跟进。
