# 0009 手选文本按形状分流，已知状态只作标注

- **状态**：accepted
- **背景**：读者主动选中的词可能已经忘记；按已知词库或档位过滤会忽略明确的查词请求。把包含候选词的整段都当成 word，也会让句子翻译只解释其中一个词。
- **决定**：显式选区按形状分成单词、实体和句子，已知与已掌握只作标注。自动扫描将来才按状态跳过。句子保留翻译与解释两个预设，实体共用一个预设；具体语义由 `API.md` 定义。
- **后果**：分类、词汇状态和模型任务各自独立。档位仍由词频近似，考试词书的替换留在 `TODO.md`。
- **修订（2026-10-27）**：“形状决定通道” 只对翻译与解释成立。复制抽屉的三项（纠正拼写、纠正语法、句子拆解）由读者按下的动作选择通道，形状只决定动作是否可用：单个 token 可纠正拼写，英文句子可纠正语法与拆解，多词名称短语与中文不展开（`docs/adr/0129`）。因此分类仍在动作之前完成，但通道不再只由形状给出。`API.md` §1 的 “前三条通道由选区的形状决定” 一句随之改写。
