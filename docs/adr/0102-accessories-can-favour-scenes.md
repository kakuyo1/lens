# 0102 配饰可以偏爱场景：sceneWeights 是性格而不是开关

- **状态**：accepted（2026-10-24）
- **背景**：ADR 0096 让大小与配饰按宠物 id 记忆，ADR 0099 又给了每只宠物九件配饰，但它们只改变像素：摘下眼镜，宠物照旧按同样的概率去同样的地方。ADR 0093 已经用 `mood` 表让时段与语境倾斜抽景，ADR 0094 的 `behavior` 块又只有一只宠物一份；读者给宠物戴上的那件东西，没有任何行为后果。
- **决定**：
  - **`accessories.json` 增加可选的 `sceneWeights`**：一个对象，键是场景 id，值是正数乘子。没有这个字段的配饰与从前逐字节一致。
  - **只乘在抽景上**：待机抽景的权重是 `sceneWeight(mood) × 已佩戴配饰的 sceneWeights 之积`；它只倾斜概率，不保证、不锁定，也不越过 “同一个场景不连续出现” 的排除规则。摘下配饰，下一次抽签就恢复。多个已佩戴件偏爱同一场景时相乘。
  - **权重是配饰数据，不是每只宠物的行为块**。把 `behavior` 的抽景部分做成按穿搭重建状态机的运行时会牵动整个机器；场景权重只在抽签那一刻读一次，是纯乘法，代价小得多。
  - **校验按包格式惯例**：`sceneWeights` 必须是对象；每个值必须是有限正数，至多 4；一个配饰至多列出 8 个场景；键必须是该宠物已有的动作，否则整只拒绝。类型错、非正数为 `BadAccessory`，越上限为 `TooLarge`。
  - **只有宠物真能演的场景会生效**：场景属于应用，只有随包宠物有；设置页只展示该宠物四个场景里被偏爱的那些。第三方包的 `sceneWeights` 照常通过校验与保存，但包没有场景可去，因此暂不产生行为。
  - **七只随包宠物各给四件配饰写权重**：强偏好 3、次一级 2.5、第二场景 2（如猫头鹰的阅读镜同时偏向书堆与电脑）。具体条目在配方里，渲染器原样带进 `accessories.json`。
  - **设置页说清楚**：佩戴带权重的配饰时，配饰区下方出现一行 11 px 弱字——“圆框眼镜：常去埋骨头”——每个已佩戴的带权重件一行；摘下即消失。它不写入设置，下一次打开由当前穿搭重新算。
- **后果**：
  - 场景抽签从此有三个乘数来源：时段与语境（ADR 0093）、宠物脾气里的基础概率（ADR 0094）、当前穿搭（本 ADR）。三者互不覆盖；权重只影响下一次待机抽景，正在播放的场景不会被打断。
  - 两个偏爱同一场景的配饰可以叠到 16 倍；保留其他场景的最小概率，因此仍是彩票而不是脚本。
  - 宠物包格式 v1 只增不改：旧包照常装载，不 bump 版本。外部包的 `sceneWeights` 目前只是被接受、被保存，没有可见效果，这一点写进包格式文档，避免作者以为它会生效。
  - 不新增美术、不改存档结构；换宠、换装与重启都不需要迁移。
