# 0153 OCR 作为设置目录的一级分类，快捷键分类撤销

- **状态**：accepted（替换 “快捷键” 一级分类；不新增分类数，目录仍为八项，依旧一屏可见）
- **背景**：读者要改在线 OCR，原来要点三次：取词与弹窗 → OCR 引擎 → 在线 OCR。返回键也有缺陷：子页只存一层路由，在线 OCR 按返回会回到取词与弹窗，而不是 OCR 页。快捷键分类只有两行，截图键属于 OCR，悬浮取词键属于取词，两者按 “输入方式” 而不是 “所控制的功能” 归类，于是 OCR 的入口散在三处。
- **决定**：
  - “快捷键” 一级分类撤销，目录仍为八项。
  - 新增 “OCR” 一级分类，承载截图开关、截图键、手动截图模式、本地引擎与识别语言、测试，以及两个子页：在线服务、本地引擎路径。
  - 悬浮取词切换键移到 “取词与弹窗”，与触发通道同页。
  - “OCR 引擎” 链接行从取词页删除，入口改为目录里的 OCR 一级分类。
  - 子页返回回到上一层：在线服务与本地引擎路径都返回 OCR 分类，而不是取词页。
- **后果**：
  - 在线 OCR 从两次点击到达：OCR → 在线服务。原来是三次。
  - 控件本身不变：外观、绑定与 `objectName` 都沿用原来的 QML，只改所在页面与顺序。测试按 `objectName` 查找，因此只改了分类名与实例化的页面。
  - 本地引擎路径从 OCR 页的长列表移到子页，OCR 分类首屏只剩引擎、语言与测试。
  - 测试与快照变化：`settings-shortcuts` 快照改为 `settings-ocr`；`settings-capture` 快照的内容变了（少 OCR 开关、多悬浮键），基线需要重新生成。
  - 文档同步：UI-SPEC 4.4 的分类表与子页表、GLOSSARY 的悬浮取词条目、PRODUCT 的热键说明。
  - 被排除的方案：
    - 把 OCR 凭据并进 “模型服务” 的 API 配置。两者都是密钥，但读者找的是 OCR，不是云服务；入口不会减少。
    - 在 OCR 页直接展开在线服务表单。能省一次点击，但页面变长，草稿提交依赖 `closeChild` 的顺序，第一版不改。
    - 把 OCR 与模型服务、同步合并成 “服务” 一类。需要改分类数与 ADR 0032 的前提，且 “服务” 的含义会模糊。
