# 0194 生涯统计页挂在关于页下，全量聚合成 KV 表

- **状态**：accepted（2026-11-18）
- **背景**：ADR 0180 落地了事件流与聚合，但读者在关于页只看得到行为数据的字节数，看不到记录
  变成了什么。读者要的不是逐条原始日志，而是一张游戏生涯统计式的计数表：查词多少次、选区与
  悬浮各多少次、自动扫描多少次、OCR 多少次、复习与模型请求如何，跨整个保留期合计。
- **决定**：
  - 入口是关于页的生涯统计链接行（标签 + 本地大小 + chevron），打开 `about/career` 子页。
    不新增一级分类——关于是目录末尾的唯一例外（ADR 0032）；也不新增表面，仍是设置浮层，
    表在面板正文里滚动，与其余设置页同一套滚动与焦点规则。
  - 表是 KV 行：左标签、右等宽数值，零值也列；六组（General / Lookups / Verdicts /
    Scan & OCR / Review / Model）。计数口径全部来自事件登记表：查词按 `src` 与 `verdict`
    细分，判定按 `to`，复习按 `result`，模型按 `kind` 与成败、token 合计；时长类
    （`uptimeMs`、`scan.durationMs`）求和后读作分钟或小时加分钟。
  - OCR 此前不在登记表里，数不出来：新增 `ocr.capture` 事件（`mode` local/online、`ok`），
    只在读者手动截图的完成点记录——本地成功与失败两出口、在线完成分支；探测、测试、
    RapidOCR 检测与自动扫描帧不记（自动扫描由 `scan.session` 计）。登记表加事件是
    ADR 0180 既定的扩 schema 路径，旧客户端读到了也忽略。
  - 聚合在 `core/telemetry/career`（Qt-free，`buildCareer` / `buildCareerFromLog` /
    `careerJson`），按月一次 pass 累加，不驻留原始事件；门面对 QML 只加一个
    `Q_INVOKABLE career()`，先 flush 再读，开页与手动刷新各调一次，`cleared` 信号触发重读。
    不随每次 flush 自动重算——2 秒一批的写盘会反复重读全部月份。
  - 清除动作从关于页移进子页，复用面板的确认卡与既有文案；清后全表归零。页底一行弱字
    说明记录只留本机、加密副本去读者自己的同步账号。行是读屏静态文本（标签 + 数值），
    刷新与清除各为一个 Tab 站。
- **后果**：
  - 关于页的行为数据行由 “大小 + 清除” 改为链接行；UI-SPEC 4.4 的关于页规格与子页面表、
    PRODUCT 的存储节、GLOSSARY 的生涯统计条同步更新。
  - 计数是保留期内的合计：12 个月轮转删掉的月份不再计入，生涯表会随之回落；这是保留策略
    的既有代价，不为统计另留永久副本。
  - `ocr.capture` 只从落地本版起记；此前的 OCR 使用没有事件，表里那两行从 0 开始。
  - 被排除的选项：按月逐条的原始日志页（读者要的是合计不是明细，且全量明细进视图的内存
    与首帧代价高）；新增一级分类（破坏 ADR 0032 的目录纪律）；每次 flush 自动重算（卡顿）；
    为统计另存永久聚合副本（与 ADR 0180 的 “原始事件即来源” 相悖）。
