# 0056 动作条形态是读者的设置

- **状态**：accepted
- **背景**：选区动作条一直是同一条横向长条。它够用，但形态本身没有表达任何东西，而不同读者的选区场景差得很远：在窄栏里读时，侧边还有空位；在宽页里读时，上方有空位；有人只想要最少的存在感，有人愿意让这三个动作有一点性格。2026-10 的设计对照（`ui-prototypes/selection-bar-variants.html`）试了二十来种形态，留下四种备选：页边签、手牌签、吊牌签、扇面。原来的横向长条没有被淘汰：它是读者已经熟悉的样子，也仍然是默认。
- **决定**：把形态做成 “取词与弹窗” 页的一项设置（`selectionBarStyle`，`bar` / `tab` / `hand` / `tag` / `fan`，默认 `bar`），五者即时切换、随同步走。窗口、玻璃、三项动作、通道判定与 “不抢焦点” 的契约仍是一份；身体拆到 `qml/selectionbar/` 的五个组件里，由 `SelectionBar.qml` 的 Loader 选一个。落点按形态各自计算：经典长条的卡片左缘贴松手点、按 “气泡位置” 上下翻；页边签贴松手点右侧，放不下翻左；手牌签与扇面以松手点为轴、按 “气泡位置” 在上下之间翻；吊牌签的孔位贴松手点，细线在上缘或下缘，下方放不下翻上。经典长条只保留原有的项内按压，其余四种各有自己的出场与按压手势，都从 `Tokens.motion` 取时长；减少动效时归零。
- **后果**：设置项、同步白名单、默认值与下拉预览都多一处要跟着改；预览卡是这五种形态的缩略画，不实例化真正的动作条窗口（那个窗口的玻璃会去采预览卡背后的桌面，画出来是错的）。鼠标钩子给出的锚点是松手点而不是选区矩形，所以手牌签与扇面是以松手点为轴摊开，而不是严格居中于整段选区；要严格居中就得让钩子把拖选的矩形一并送出来，这一版没有为它改原生链路。扇面的玻璃是一整片 `GlassSurface` 经 `ShaderEffectSource` 取出、由 `fan.frag` 按五边形裁切，扇骨、轮廓与沿边的白色高光画在它上面；经典长条、页边签与吊牌签仍走普通圆角玻璃卡片。
