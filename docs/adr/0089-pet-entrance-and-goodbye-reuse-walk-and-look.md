# 0089 宠物的进出场复用行走、张望与爱心

- **状态**：accepted（2026-10-23），应用层已接入。原型见 `ui-prototypes/pet-prototype/ceremony.html`。
- **背景**：宠物开启、关闭与换宠时，窗口原来都在同一帧出现或消失。动作状态机会表演阅读、生气与打盹，却没有机会表达 “从边上回来” 或 “走到边上告辞”。原型证明现有 `walk`、`look_around`、`encourage` 已经够用，读者也定了三件事：新宠默认也张望、爱心足够当告辞、换宠同一边交接。
- **决定**：
  - **开启**从离 home 最近的左 / 右工作区边缘完全屏外走入，到 home 后播一轮 `look_around` 再站定。**换宠**时旧宠走到同一个边缘并完全出屏，新宠从同一边走入并张望。**关闭**走到最近边缘，张望、播 `encourage` 的爱心，再走出屏幕后才隐藏窗口。
  - **窗口级行为**，不新增美术，也不新增角色。控制器复用 `PetWander` 的步态路径（去掉 home 椭圆夹取），按约 300 px/s、850–2600 ms 移动；状态机新增 `playRole()`，让控制器在空闲时播放角色映射的单次动作。张望与爱心仍然是宠物数据里的角色动作。
  - **不是设置项**。启动时已开启的宠物原地出现，“入场” 属于把宠物打开这个动作；已经在边缘躲藏的宠物关闭时直接收起；系统或应用关闭动画时退化为瞬时显隐。
  - **打断的归属**：学习事件让正在进场的宠物落到 home（换宠则先完成）再演事件；告辞不因学习事件回头。拖动抓住宠物当前位置，告辞途中被抓住的松手后收起。屏幕变化与改大小由窗口回收逻辑接管。
- **后果**：
  - `enabled` 与 “窗口在场上” 必须分开（`shown`）：关闭的瞬间开关就是关、宠物项灰化，但窗口还要留到告辞结束。QML 的宠物窗口因此绑定 `Pet.shown`。
  - 换宠在旧宠出屏后加载新宠，期间窗口停在屏外；选择器用 pending id 显示新宠，不因晚一拍加载而回跳。窗口在仪式中的尺寸变化由仪式接管，`fitOnScreen` 让路。
  - 没有 `movement.walk` 的宠物包不走仪式，直接出现 / 消失；`look_around` 与 `encourage` 是角色闭集里的必需项，所以有行走的包一定有张望与爱心。
  - 开发面新增 `setting set petEnabled on|off`、`setting set pet <id>` 与 `state.pet`，这条行为可以不用鼠标、不靠截图验证（ADR 0068、`docs/qa.md`）。
