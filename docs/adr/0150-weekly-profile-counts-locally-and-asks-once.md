# 0150 本周画像的计数在本地算，解读只在按下按钮时发一次

- **状态**：accepted（2026-11-01；2026-11-06 观察语言改为跟随界面语言）；“摘要逐字预览” 与 “结果在面板内显示” 两条由 `docs/adr/0151` 部分取代
- **背景**：统计弹窗回答 “查了多少”，不回答 “查的词什么样、该往哪使劲”。读者想看一周的查词形状——新词比例、重查、词性、时段、常查的词——这些大多能从本地历史直接算出；只有 “该怎么做” 那一段需要模型来写。把整周历史发给模型既违反发送最小化，也让一次打开面板变成一笔费用。
- **决定**：
  - **计数全部本地算，且是纯函数**（`core/document/reading_profile.h`，Qt-free）。窗口是本周一到今天，按本地日期，两端都含。新词按已知库推导（ADR 0147），不看弹词时的戳记。重查指同周内被查两次及以上，一个词只算一次。词性取缓存中的词性，没有缓存的单独计数、不猜。时段取弹词分钟的本地小时。打开面板不发请求。另有两项行为计数只在面板上显示、不进摘要：按弹词自己的解释语言算出的母语解释占比，以及完成的母语一瞥次数（后者按日累计）。
  - **解读是一次性的按钮动作**：`Channel::Profile`，不流式，`max_tokens` 512，请求里只有摘要文本。回五句以内的观察与建议，语言跟随界面语言，与解释语言无关。失败与拒答各给一句原因，不出通知。
  - **发送的内容就是面板上显示的那段摘要**，逐字列在按钮下方。摘要只含计数、比例、词性分布、每小时的查阅数，以及前五个词的词头。不含句子、选区、释义、弹词分钟，也不含密钥。词头照常过 `maskSensitive`，与其他通道一致。
  - **按次计费**：解读的 token 记入当日与模型桶，计入每日预算。预算到顶时按钮禁用，不发请求。
  - **结果不落盘**：解读只留在内存里，且只属于产生它的那一周，换周即失效。不入缓存，不入同步，不写进设置文档。
- **后果**：
  - 词头会离开本机，但只在按钮按下之后，且只有前五个。这是本设计唯一新增的出站内容，`SECURITY.md` 与 `API.md` 同步记录。
  - 摘要结构固定、没有原文，读者可以在面板上逐字核对发出的内容。
  - 被排除的方案：（a）每周自动生成解读——违背按次计费与默认不出网；（b）把整周历史发给模型——超出发送最小化；（c）本地用规则拼 “建议”——模板口吻重，且要维护一套文案判定，收益不抵成本。
  - 计数与解读分开，所以面板在无密钥、无预算、离线时依然能读；只有最后一段依赖模型。
