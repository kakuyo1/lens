# 0180 行为事件按月分文件同步，不进设置文档

- **状态**：accepted（2026-11-15）
- **背景**：周报、年报与功能使用报告需要一个统一的行为事件流。现有 `StatsStore` 的
  `history` / `daily` 是功能定制的窄记录，只覆盖查词与 token；`settings.json` 是单文档
  全量重写，还带着解释缓存与 API key，装不下高频事件；`lens-sync.json` 的合并只往返
  `known/deleted/history/daily/settings` 六个键，未知顶层键会被旧客户端丢掉。
- **决定**：
  - 本机事件写成 `%APPDATA%\Lens\events\events-YYYY-MM.jsonl`，一行一个事件，按月
    轮转，保留 12 个月；不进 `settings.json`，不与设置文档共用一次保存。
  - 事件字段由 `core/telemetry/event.h` 的登记表决定：未知事件与白名单外的字段在写入
    时拒绝；词条记明文 lemma，前台应用名记进程名并由设置项 `recordForegroundApp`
    控制。每轮记录先入队，2 秒或 64 条批量写盘，退出前 flush；崩溃最多丢约 2 秒。
    设置 General 页的行为记录组只放这一个开关，缺省开、不同步。
  - 云端走独立文件通道，不进 `lens-sync.json`：每设备每月一个
    `lens-events-<dev8>-YYYY-MM-r<NNNN>-<sha1-8>.json.enc`，用同步的派生密钥与 KDF
    参数封存（AES-256-GCM），与主副本放在同一个 gist / WebDAV 目录。文件列表就是
    索引；已关闭月份通常只上传一次，当月每天最多一次，手动同步立即上传。文件名里的
    hash 是本月明文 JSONL 的 SHA-1 前八位，内容不变则文件名不变，内容变化则版本号
    加一；上传成功后旧版本进入删除队列。
  - 对账在本机 `state.json` 记 `uploaded`（月 → 文件名、hash、版本、上传日）与
    `pendingDeletes`。`state.json` 丢失或损坏时，用本地月份与远端列表重建：同名文件
    的最高版本且 hash 与本机月文件一致时直接采纳，不重复上传。过期月份、已清除的
    月份与旧版本删除本设备名下的远端文件；另一台设备的文件不动。`deleteAll` 只在
    读者删除云端副本后置位，删除所有设备的事件文件后才清掉。
  - 事件通道只在主同步成功后运行，主同步失败不影响它，它失败也只记日志，不改变
    主同步的错误码与重试。GitHub 与主文档共用 gist；WebDAV 的目录列举用
    `Depth: 1`，删除事件文件是显式动词。下载取每设备每月最高版本，封存在内存里
    打开，v1 不落远程明文副本。
  - 关于页显示 `%APPDATA%\Lens\events\` 的本机大小；清除删掉本地月份、把已上传
    文件排入删除队列。12 个月保留由本机轮转与过期删除共同维持。
  - 本机事件流由 `core/telemetry/report` 聚合：注入本地日历后按日/周/月、5 分钟
    空闲会话、时段直方图、前 N 个词、功能与应用榜输出，Qt-free，供之后的周报 /
    年报与功能使用报告使用。报告界面不在本次范围；开发面的 `telemetry report`
    应答与下载 API 是报告数据进入界面前的入口。
  - 保留期内全部原始事件上云；过期月份由本机设备删除自己名下的远端文件。
    不新增出站目的地，不做第三方上报。
- **后果**：
  - 同步要从单文件扩成多文件列举、上传、下载与删除；GitHub gist 的多文件数量与总容量
    上限、文件 PATCH 删除语义需在实现时实测，触顶的退路是年度文件或云端只留聚合。
  - 当月文件在月末前会随版本重传，单文件可达数 MB；若流量不可接受，改为仅月末上传，
    代价是云端当月明细有延迟。
  - 事件文件含词条与前台应用名，敏感度高于现有 `history`；`SECURITY.md` 的出站表与
    本地数据节、`PRODUCT.md` 的存储形状表必须同步更新。
  - 主同步文档格式保持 `format: 1`，旧客户端不因事件文件改变行为；代价是事件通道
    自己承担失败重试与保留清理。
  - GitHub 的 gist 文件数与总容量上限、PATCH 未提及文件保持不变、`null` 删除文件
    的语义仍需在真实 gist 上按需核对；触顶时退路是年度文件或云端只留聚合。
  - WebDAV 的目录列举依赖各服务器对 `Depth: 1` 的支持；不支持的服务器的退路是
    退回只追加、由删除云端数据统一清理的做法。删除云端副本时 `deleteAll` 先落盘，
    断网或服务拒绝后下一次主同步成功会继续删，不会把事件文件留在服务器上。
  - 被排除的选项：把事件塞进主同步文档（重传整份大文件、旧客户端丢键）；只同步聚合
    （失去逐条明细，无法支撑之后的细粒度报告）；复用 spdlog 的 JSON sink（受日志级别
    过滤、轮转策略与诊断混流约束，schema 不稳）；把事件的加密或上传放在
    `core::sync::merge()` 内（主文档与事件节奏不同，合并规则不应知道事件）。
