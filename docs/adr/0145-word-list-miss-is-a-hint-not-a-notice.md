# 0145 单词表悬浮查无缓存时，提示贴在单词旁，带 “现在解释”，不弹通知

- **状态**：accepted（2026-10-30，修订：同日先前版本的提示不接收指针、不带按钮，已推翻）
- **背景**：词汇弹窗的悬浮复习只读缓存、不发请求。当前解释语言下没有缓存的词，原先弹一张居中的通知卡（4.5），写明没有已存释义，并给一枚 “现在解释” 按钮。悬浮的人只是在读一行，却被拉到屏幕中央；通知卡还要按键才能收。
- **决定**：这种情况改为一行提示，贴在单词旁，外观同解释气泡（同一张卡、同一套令牌、同一条 10 px 间距），带一枚 “现在解释” 按钮。按钮是这条路径上唯一会发请求的地方，由读者按下才发，悬浮本身不花钱。提示接收指针：指针在提示上时它保持，离开单词与提示两者才收。判定同复习卡，由提示自己按几何位置上报（`holdWordHint`），不靠悬浮事件，因为提示的透明阴影会抢走单词的悬浮。定位复用复习卡的规则，从 `SurfaceHost.placeReviewCard` 抽出 `placeAgainstWord`。
- **后果**：`ExplanationDuty` 新增 `wordHint` 属性、`wordHintChanged` 信号与 `holdWordHint`，`notice` 不再承载这一情况。“鼠标离开单词即消失” 放宽为 “离开单词与提示两者才消失”，这是为了让按钮够得着，是本决定的代价。`Notice.qml` 的动作胶囊仍只给首次运行引导用。被排除的方案：居中通知（读者被拉到屏幕中央，已被否决）；提示不接收指针（按钮够不着，等于没有按钮，即先前版本）；悬浮即发请求（花不花钱不由读者决定）。
