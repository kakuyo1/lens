# 0076 宠物按自己的步态闲逛，走到边缘会躲起来，躲着也能举牌

- **状态**：accepted（2026-10-20），应用层已接入（2026-10-21）。原型见 `ui-prototypes/pet-prototype/walk.html`，实施记录见 `docs/pet-idle-and-motion.md` 第 8 节与根目录 `PET-WANDER-INTEGRATION-PLAN.md`。
- **背景**：宠物待机时一直站在原地，动作虽有随机流，身体却不移动。七只随包宠物已经有各自的性格，读者希望它们动起来时也有各自的走法，而不是共用一条滑行路径；走到屏幕边缘时还应有一层 “躲进去偷看” 的行为。复习牌在躲藏时是否还能用，取决于举牌本身：牌子已经有左右手与内外侧的选择，宠物窗口不必移动也能举；真正要决定的是躲藏状态要不要让复习提问进入。
- **决定**：
  - **移动是窗口级行为**。宠物窗口就是精灵大小，不放大透明窗口；闲逛只在桌面窗口、真正待机时发生，以读者放下的位置为 home，活动范围是窗口宽度的 10–60%（随包宠物 24–46%）。两次闲逛之间累计 120–300 秒的真正空闲时间；阅读、复习、点击、拖动、悬停或指针停在宠物窗口上会重抽这次等待，宠物自己的短待机动作只暂停计时，否则每 20–90 秒一次的待机动作会让长等待永远到不了。拖动落点更新 home，闲逛位置不写回设置。
  - **每只宠物有独立步态**。新增循环动作 `walk` 与 `edge_peek`；`walk` 负责身体，控制器负责窗口路径与节奏。随包七只：小狗 `trot`、麻薯 `hop`、猫头鹰 `hop`、猫 `pounce`、幽灵、水母与云 `float`。步态、范围与两个动作名放进 `animations.json` 的可选 `movement` 块，宠物包可以不带；不带时该宠物不闲逛，带 `walk` 但缺 `edge_peek` 时只闲逛、不躲藏。`walk` 与 `edge_peek` 都是循环动作，不映射任何角色，也不进 `idlePool`；只有控制器能播放它们。
  - **边缘躲藏**。一次 `walk` 结束、窗口正好贴住当前屏工作区的左/右边缘时，有 70% 概率躲进去。窗口按宠物的**墨迹边界**滑出屏幕，只留下约 34% 的可视身体，循环 `edge_peek`，并让窗口每 3.6 秒向内探一次。没有超时、没有自动醒来；单击不结束，只有读者拖动并把宠物拉回工作区内一段才结束。系统事件（屏幕被移除或工作区改变）可以取消躲藏并把窗口夹回安全位置，这是环境结果，不是宠物自行结束。
  - **躲着也能举牌**。复习提问的可用条件从 “状态机 idle” 改为 “状态机 idle 或正躲在边缘偷看”；躲藏不算提问的阻塞，也不是提问的结束，反应或阅读先放完。`ReviewAsked` 让状态机进入 `ask`，窗口留在边缘，牌子沿用现有的左右手与内外侧选择，用内侧那只手；回答、90 秒超时或关闭后，宠物回到 `edge_peek`，躲藏继续。若读者把宠物拖出来，躲藏结束，问题留在新位置继续。
  - **躲藏时暂停悬浮与注视**。宠物只偷看、举牌或被拖出；牌子自己的悬浮小卡不受影响。
- **后果**：
  - 窗口会有一段时间停在屏幕工作区之外。`fitOnScreen`、`keepOnScreen`、`savePosition` 必须知道躲藏状态，不能把窗口自动夹回；拖出时也不能把躲藏位置写回 home。
  - 举牌在躲藏时会用到宠物窗口内的手。接入时按内侧手的握点计算：若该手会落在屏幕外，窗口在 `ask` 期间临时向内让到握点离边缘 16 px，问题结束、宠物回到 `edge_peek` 时再退回原隐藏位置；躲藏状态不变。没有新增 edge-ask 美术。
  - 第三方包需要自己提供 `walk` 与 `edge_peek` 才能获得新行为；没有这两个动作的包保持现在的被动待机，不会滑动或躲藏。
  - 新增动作名要进设置页的动作药丸与四份翻译；`walk` 与 `edge_peek` 不是角色，角色的闭集不变。
