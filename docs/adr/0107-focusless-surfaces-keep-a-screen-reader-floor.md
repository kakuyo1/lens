# 0107 无焦点浮层保留读屏地板

- **状态**：accepted（2026-10-25）。
- **背景**：DESIGN.md 的 Do 写着“所有可点击元素有焦点态”，而选区动作条、解释气泡、通知卡与更新卡按交互契约使用
  `WindowDoesNotAcceptFocus`：它们出现在读者正在读的文本旁，抢走焦点会改变下一次注入复制键的去处。没有例外记录时，
  每轮评审都会把这条规则重新判成违规，动作条本身也一直没有 `Accessible` 角色与名称。
- **决定**：
  - **不接管焦点**。这四类浮层继续使用 `WindowDoesNotAcceptFocus`，不设 `Tab` 站与焦点环；它们不是可以走进来的窗口。
  - **读屏地板是每个可按目标都有角色、名称与按压动作**。动作条五形体的每个动作、气泡的判定 / 关闭 / 语言切换 / 链词、
    通知的动作胶囊、更新卡的按钮都满足这一条；实现由各自组件和形体负责，不依赖窗口焦点。
  - **键盘路径按表面另算**：气泡与动作条由全局取词手势触发，动作条的指针优先是产品选择；更新卡保持指针操作。
    这条例外只免掉焦点环，不免掉读屏能力。
- **后果**：
  - DESIGN.md 的焦点态 Do 增加这一处明确例外，指向本 ADR；以后新增无焦点浮层必须同时补齐 `Accessible` 三件套。
  - 键盘专用读者仍无法用 Tab 走进动作条或气泡；这是保持“不打断读者原窗口”的代价，不再被误记为遗漏的焦点态。
