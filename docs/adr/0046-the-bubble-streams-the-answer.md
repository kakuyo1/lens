# 0046 气泡随答案流式长出

- **状态**：accepted
- **背景**：解释请求此前一次拿到整份回答才画卡片，读者从取词到看见字要等模型把整段写完；而模型的回答本来就是逐字生成的。四个通道的请求体在 `data/llm/request.*.json`，`stream` 一直写 `false`——协议数据是 “线协议即数据”，所以打开流式是一次数据改动加上一条新的读取路径。
- **决定**：
  - 请求打开 `"stream": true` 并带 `"streamOptions": {"include_usage": true}`，让最后一帧带回 token 用量（否则花费记账会静默变成 0）。DeepSeek 文档确认支持；不认这个字段的服务商在目录里用 `requestOverrides` 把它置 `null` 去掉，与 `thinking` 走同一条通路。
  - 传输按 SSE 组事件：字节缓冲到事件终止符才解码，所以被拆开的转义、`data:` 行与 UTF-8 码点不会被读成半截。第一个 `data:` 负载决定这是流还是整份 body，因此测试桩与缓冲型代理走回原来的单 body 路径。
  - 流结束时把攒下的文本**重新拼成一份普通 chat 信封**（`choices[0].message.content` + `finish_reason` + `usage`），交给原来的 `parseExplanations()` 校验。校验、缓存、已会标记、统计与花费全部只认这一份完整结果：**画一半，存整份**。
  - 只读 `results[0]`：扫描批次里卡片画的是第一个被命名的词，其余结果照旧在整份答案到达后入库。字段只在值闭合后才画；标题取读者自己的选区，不取模型的回声。
  - 预览只对 “还在飞的那一次请求” 生效（`ExplanationQueue::liveSubject`，与 `settled()` 共用同一条陈旧规则），所以逐字的更新不会给读者已经离开的词画卡片。正被拖动的卡片不被长出来的内容拉回锚点。宠物不逐帧反应：预览静默，只有整份答案到达时它才动一次。
  - 流中途断掉（`finish_reason: length`、没有 `finish_reason`、传输错误）走**原来的失败通知**，不新增状态。
- **后果**：
  - **信任边界移动**：`SECURITY.md` 原来的承诺是 “模型回复先按预期形状校验再使用”，现在到达中的文字先画出来，卡片上的预览因此未经校验；缓存、统计与已会标记仍然拿不到未校验的东西。这是读者可见的取舍，已写进 `SECURITY.md`。
  - 每个 chunk 都可能重绘卡片，代价在 QML 侧的绑定与布局；只有 “卡片会画的字段真的变了” 才发预览，填空的 chunk 不发。
  - 服务商差异：`stream_options` 不是所有兼容端点都认，而不认的端点会把整份请求判成 400——那会让那一家彻底不能用。因此只有 **DeepSeek**（官方文档已核对，也是读者在用的一家）带这个字段；目录里其余 8 家在 `requestOverrides` 里把它置 `null` 去掉，代价是那几家的花费记账为 0（`parseUsage` 会写警告，不是静默）。要把某一家打开，删掉它那个 `null` 即可；若日后有服务商报出 400，也可以改成 “被拒后去掉该字段重发一次”，现在不做。
  - 用量在中断的流上拿不到（最后一帧没到就是没有），这一批的记账为 0，与整份 body 路径上 “服务商不回 usage” 时一致。
