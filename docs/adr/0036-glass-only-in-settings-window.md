# 0036 玻璃主题只作用于设置窗口

- **状态**：accepted
- **背景**：玻璃主题的色表原来挂在全局的 `Tokens` 单例上，所有表面读到的都是玻璃值。第一阶段只做设置窗口，但设置窗口与气泡、统计、词汇、托盘菜单等表面可以同时可见，它们读的是同一张表。玻璃一开，这些卡片都会变成透明。QML 单例没有按窗口作用域的办法，把开关放在 `Tokens` 里只能全局生效。
- **决定**：
  - 色表拆成两个单例，共用一份实现 `components/TokenTable.qml`。`Tokens` 不开玻璃，供所有非设置表面读，玻璃主题在其中按晴朗白昼渲染；`SettingsTokens` 开玻璃，供设置窗口读。
  - 设置窗口本身，以及只在设置里出现的组件（下拉、滑块、热键框、路径框、玻璃层、宠物预览），直接读 `SettingsTokens`。
  - 设置与其他表面共用的组件（`ShadowCard`、`Segment`、`Switch`、`SwitchRow`）新增 `tokens` 属性，默认 `Tokens`；设置窗口的调用点显式传入 `SettingsTokens`。
  - 非设置表面的圆角一律 18 px；液体主题的 22 px 只属于设置卡片。
- **后果**：
  - 设置一侧约 180 处读取改为 `SettingsTokens.`。新增的表面默认读 `Tokens`，不会误成玻璃。
  - 共用组件若在设置里漏传 `tokens`，它会退回晴朗白昼：不报错，表现为设置窗口里一块不透明的底。目前没有逐组件的回归测试，只有 `tst_phase2e` 的值断言。
  - 第二阶段若要让第二张表面也玻璃化，两个单例就不够用了。届时改为每个窗口持有一份 `TokenTable` 实例，由窗口根沿组件树传下去。本决定是为了当前只有一个玻璃窗口而选的最短路径。
  - 被排除的选项：在 `Tokens` 内加玻璃作用域（QML 单例无法按调用方区分）；把 `tokens` 沿整棵树逐层传递（要改动设置之外的几十处调用点，本阶段不做）。
