# 0176 词汇弹窗的搜索行是主动查词入口

- **状态**：accepted
- **背景**：四条取词路径（扫描 / 选区 / 截图 / 悬浮）全部是指向屏幕上已有文字的被动入口。被动路径够不到的地方——PDF 阅读器与视频字幕尚未接入、扫描白名单之外的应用、OCR 关着——读者手里只有键盘，没有一条路能问这个词是什么。TODO 与既有 ADR 从未裁决过要不要键入入口；0145 把词汇弹窗划成了 “悬浮绝不发请求、按下胶囊才发” 的表面。
- **决定**：
  - 入口落在词汇弹窗：分段筛选之下加一行常驻搜索框。不加热键、不加新窗口——0002（无主窗口）与 0008（入口收缩到有意手势）的取向不变。`ui-prototypes/words-search-candidates.html` 的三个候选里选了 A（常驻行、过滤优先）。
  - **过滤优先，查词是落空时的出路**：键入即本地过滤（词内子串、大小写不敏感），**查询挂起分段筛选**——搜索跨整个词汇表，分段控件置灰（45%）且不响应，清空查询后读者的分段原样回来；查询不进导出与统计。落空的唯一含义是词表里真没有这个词：列表给一行提示，带 “现在解释” 胶囊；**Enter 只在落空时发**——词表里已有的词，行内悬浮 400 ms 的已存释义免费（0145），回车重问就是重复计费。分段的初版与查询叠加，结果分段外的已收词读成落空、提示行的胶囊会引诱对词表里已有的词再付一次费，故改为挂起。
  - **请求与选区取词同权**：走解释通道的 Selection origin（`explain()`），入 history 与统计、过预算门（预算到顶走 explainLemma 同一条通知）；卡片锚在搜索行，不在上次复习位。“悬浮绝不发请求” 的边界不动——按胶囊与按 Enter 都是读者按下的。
- **后果**：
  - 词汇弹窗高一行；面板关闭即清空查询，重开是整表。
  - 主动查词不在阅读现场手边（要先打开词汇弹窗）——接受：它不是阅读流内动作，是整理与回查时的入口；真要随手输入的场景，留给以后的独立提案。
  - “Enter 不重问、落空才发” 是本卡钉住的行为：以后要改成回车永远发解释（候选 B 的语义），需要新 ADR。
