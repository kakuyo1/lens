# 0169 宠物目录按文件夹指纹复用：没变就不重扫

- **状态**：accepted
- **背景**：拓展页每次打开都在 UI 线程同步重扫两处宠物文件夹（`SettingsExtensionsPage.qml` 的 `Component.onCompleted: Pet.picker.refresh()` → `scanPets`），对每只宠物跑的是整包校验 `PetAssets::load`：目录树遍历、逐 PNG 读头、逐文件 `fs::canonical`、idle/peek 精灵表整张解码再逐像素求墨迹框。2026-11-09 在本机 Debug 树实测（7 只随包 + 16 个已装包）：一次重扫约 900 ms（随包 530–667 ms、已装 367–404 ms），文件没变时这次重扫的结果与上次完全相同；打开拓展页因此有明显卡顿。
- **决定**：
  - `pet_catalog` 新增 `scanStamp()`：两处根文件夹的 `last_write_time`、每个包文件夹自己的时间、每个包内被读取的五份文档（pet.json / animations.json / anchors.json / accessories.json / sign.json）的时间，按目录序拼成可比较的指纹（本机 140 项）。
  - `PetController` 在启动扫描前记下指纹；`refresh()` 先取新指纹，与存档不同才 `scanPets` 并清明信片缓存，相同则直接返回——启动那次扫描同时就是页面第一次打开的数据源，第一次进入也不重扫。
  - 指纹未变时连 `catalogChanged` / `settingsChanged` / `frameChanged` / `outfitChanged` 也不发：问它的是刚建好的页面，绑定在构建时已读到当前值，发射只会让整页绑定在布局时重算（dev surface 实测该页打开 274 → 246 ms，其中约 4 ms 是指纹）。
  - 指纹在扫描之前取并原样存档：扫描期间落下的改动让下一次进入多扫一次，而不是被永久漏掉。
  - 扫描本身的完整校验（包内文件数与体积上限、路径逃逸、表尺寸、保留 id）一行不动——那是被拒包列表与安全边界，只在指纹变化时付一次。
- **后果**：
  - 打开拓展页的主线程成本从整包重扫约 900 ms 降为一次指纹（实测 4.1–4.4 ms）；目录未变时 qtest 中 `refresh()` 从 556–563 ms 降到 1.9 ms。
  - dev surface 端到端（Debug 树、宠物开启）：打开拓展页 274 → 246 ms，余下是页面自身构建（宠物预览、动作 / 场景 / 配饰药丸、类型下拉），同一面板的通用页作对照约 136 ms——Debug 的 QML 构建偏慢，且这部分与两处文件夹无关，本卡不动。
  - 拷入、删除、改名包（父目录时间变）与就地编辑包内文档（文档时间变）仍被下一次进入发现，`UI-SPEC.md` 4.4 的 “有变化才重扫” 由此成立。
  - 只覆盖重画图片、不动任何 JSON 的原地修改不移动指纹：包内新美术在该宠物被选中加载时读取，选择列表本来也不显示它。
  - 明信片缓存的清空时机从 “每次 refresh” 收窄到 “真正重扫”，目录未变时不再丢弃重读。
