# 0123 一场场景由一个舞台 module 拥有

- **状态**：accepted（2026-10-26）
- **背景**：ADR 0049 的场景、0093 的抽签权重与两个事后语境、0101 的入场编排、0102 的配饰偏好，此前散在四处：抽签是 `loadPet` 里一个 34 行的 lambda（心情 × 配饰偏好、不重复、加权抽），入场时间轴与帧是 `sync()` 那 196 行的一部分，两个事后语境是控制器上两个 `time_point`，外加一处 `QTime::currentTime()` 直读。13 个入场字段在 4 处重置，看门狗那处只清一部分。完整抽签没有测试——只测了两个权重函数；入场要真窗口，最长等 3 秒。
- **决定**：新增 `src/app/pet/pet_stage.{h,cpp}`，一个无窗口、无时钟、无 QObject 的 `PetStage`，拥有抽签、入场时间轴、帧与两个事后语境。
  - 抽签：`draw(offers, mood)` 收一份 `Offer{名字, 心情表, 配饰偏好}` 与那一刻的心情，给出一个场景或什么都不给。骰子在构造时注入，上一个场景由 module 自己记住；`notePlayed()` 收设置页直接点的那一场，`lastPlayed()` 供测试与调用方读。
  - 时间：`readingBegan()` / `readingEnded()` / `returnedHome()` 收单调时钟的读数，`mood(now, minuteOfDay)` 给出那一刻。长读阈值与两个余晖时长是 module 的常量，它自己不读任何时钟——两个时钟都由控制器读、再交进来。
  - 入场：`beginEntry(scene, pose, inkTop)` 收场景、跳与落要抱着的待机姿势（帧数、fps、是否循环、当时那一帧）与墨迹上沿；`tick(step)` 吐 `EntryStep{frame, landed}`——`frame` 是道具透明度与抬升、前后层、两个身体的透明度、位移与缩放，`landed` 表示这一刻落地并该放粒子。`landEntry()` 立即落地且不留粒子（减少动态），`stopEntry()` 连场景与粒子一起忘掉，`reset()` 换宠时用。
  - 帧：`frameOf(scene, frame, feet)` 给出该帧的位移、缩放与舞台对齐（宠物自己的脚减目录的脚），索引越过数据时读最后一帧。
- **后果**：
  - 控制器里 13 个入场字段与 3 个事后语境字段消失；4 处重置变成 1 处，`checkHealth` 不再只清一半。`sync()` 的入场分支从约 100 行降到约 30 行，剩下的是 sheets、anchors 与 URL 的发布。
  - `pet_stage_test` 的 24 个值用例覆盖完整抽签（权重、配饰偏好、不重复、唯一场景、无场景、设置页点过的场景）、两个事后语境与余晖边界、三种入场的帧、弧顶按墨迹上沿封顶、落地与粒子、`landEntry` / `stopEntry` / `reset` 的边界，以及帧与对齐。
  - 行为不变，两处边界写进了 module：落地后 `sceneId()` 仍记着这一场，否则每帧重播入场，减少动态关掉后也会重播；帧索引越过场景数据时读最后一帧并继续显示道具，而不是把整场退成中立——`perFrame` 与动作帧数不一致时，前者比后者不闪。
  - 被排除的方案：把抽签留在 lambda 里、只给入场加用例，仍测不到不重复与偏好叠加；让 module 自己读 `QTime`，它就同时拥有两个时钟，“时间从外部注入”失效；把窗口或状态机放进 module，它就不再是值进值出。
- **ADR 关系**：0049 的场景、0093 的心情与两个事后语境、0101 的入场编排、0102 的配饰偏好成为 module 的行为；0101 的“控制器拥有时间轴”仍守——持有 module 的仍是控制器。QML 的 `entry.active` 守卫留着当防御，不再承担正确性。
