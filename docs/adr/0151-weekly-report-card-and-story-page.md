# 0151 周报告卡片与小故事：解读结果全屏呈现，故事从本周查词里成篇

- **状态**：accepted（2026-11-01）。部分取代 `docs/adr/0150` 中 “摘要逐字预览” 与 “结果在面板内显示” 两条。代码已落地；第 2 条的事实键与第 5 条的抽词方式见 `docs/adr/0152`。
- **背景**：`docs/adr/0150` 把解读结果放在统计子面板里，摘要也逐字列在按钮下方。读者要的是一张能单独看、不挤在统计面板里的报告，并且想读一段用自己本周查过的词写成的小故事。摘要不再需要在按钮下显示。
- **决定**：
  1. **结果以全屏居中的报告卡片呈现**，版式取 `ui-prototypes/report-card-c-evidence.html`（候选 C，已选定）。按下 “解读本周” 后，画像面板收起，报告卡片以等待态立即打开，结果到达后原地填入（沿用 `docs/adr/0146` 的做法）。
  2. **每条观察右侧挂一枚依据药丸**，写出它依据的数字。药丸的数字由应用从本地事实给出，模型不写数字（`PRODUCT.md` 原则 2：本地判定，模型只解释）。
  3. **图表不用数据色**：柱用 `muted`，峰值柱用 `ink`。图表不引入第二个色相，与 `DESIGN.md` 的 “唯一语义色” 规则一致。
  4. **解读的摘要照常随请求发送，但不显示**：面板上不再出现摘要，也不再出现解读的正文。
  5. **报告卡片底部的 “重新解读” 换为 “小故事” 按钮**。点它进入小故事页：LLM 从本周查过的词里挑 10–15 个词（本周不足 10 个则全用，可以少于 10）写一段故事，正文约 100–300 词，本周查过的词在底部画虚线。
  6. **小故事页与报告卡片同一张卡、同一尺寸**：正文在卡内滑动阅读，卡片不会因为正文变长。页内有返回按钮，回到报告卡片。两页之间有过渡，过渡时长取 `Tokens.motion`。
- **后果**：
  - **出站内容增加**：小故事请求会把本周查过的所有去重词头发出去，不止前五个。解读摘要仍只含计数、比例、词性分布、每小时的查阅数与前五个词头。`SECURITY.md` 与 `API.md` 在实现时同步更新。
  - **“可预览” 的承诺在摘要上撤回**：`PRODUCT.md` 原则 3 “隐私是边界” 的 “发送前可见” 不再覆盖解读摘要。这是读者明确要求的取舍，代价是读者在按下按钮前看不到将要发出的文字。
  - 报告卡片与小故事只存在于内存中，只属于产生它们的那一周。两者都按次计费、计入每日预算，不入缓存，不入同步，不写进设置文档。
  - 小故事的 “10–15 个词” 与 “100–300 词” 是读者给的目标范围，两者都按 “约” 理解。
  - 被排除的方案：把摘要留在面板里（读者要求去掉）；把小故事写入缓存（读者未要求，且随周变化、没有复用价值）。
