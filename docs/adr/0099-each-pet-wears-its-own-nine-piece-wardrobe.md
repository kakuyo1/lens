# 0099 每只宠物有自己的九件配饰

- **状态**：accepted
- **背景**：七只随包宠物的配饰长期共用一套 id：短耳猫与后加的三只共用九件，小狗只有七件，麻糬与猫头鹰各有一套。共用件只按格子画，碰到不同轮廓就出现镜孔偏高、围巾压在嘴上、领结悬在云底这类错位；同一顶帽子戴在七只头上也无法按各自的头形收边。2026-10 的试穿页为每只画了三头、三脸、三身共 63 件，逐只按真实锚点合成，选定为正式美术。
- **决定**：七只随包宠物全部改为各自九件，头、脸、身各三件，共 63 件；每只的套装按自己的头形与身体画，不再四只共用一整套（同名的圆墨镜与雾围巾仍各画各的）。小狗从七件补到九件。旧共用件与小狗旧件退役，`accessories.json` 里不再出现。每件仍是独立 PNG，按自己槽位的锚点跟随，不做独立骨骼；可穿动作仍由配方 `except` 生成。渲染器新增 `pixel` + `canvas` 的像素画法，让不落在 3 px 网格上的描边按画布像素落点。
- **后果**：
  - 七只各 9 件而非 “共用九件 + 小狗七件”，配饰 PNG 从 61 张变为 63 张；设置页每个槽位多到三枚芯片。
  - 旧存档里已退役的配饰 id 在装载时被丢弃，宠物回到该槽位空着；配饰没有迁移表，也不把旧件映射到新件。
  - 玩具包格式不变：外部包仍可给任意数量（上限 32）的配饰，id 由包自己命名；随包宠物的九件不是格式要求。
  - 新增 54 条界面标签，四种语言都要翻译；配饰 id 本身仍不是界面文案，包作者的 id 不翻译。
  - 美术流水线可以画 1 px 描边，配方文件比纯格子版更长；`render_pet.py` 的 `canvas: true` 只影响配方输入，输出仍是 88 × 88 的 PNG。
