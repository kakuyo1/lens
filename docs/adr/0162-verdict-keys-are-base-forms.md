# 0162 判定库的键取词的原形

- **状态**：accepted
- **背景**：判定库按 lemma 键（GLOSSARY），但 `lemmatize` 的平局裁决是词频——“crumpled”（27436）比它的原形 “crumple”（45613）排得靠前，铅笔按钮判掌握时存下的键就是 crumpled。覆盖是单向的（`formsOf` 只向基词方向展开）：掌握 crumpled 退役不了 crumple/crumples/crumpling，词汇弹窗还把存键原文显示出来，读者看到一个灰色、拼写古怪的行。
- **决定**：
  - **键一律取原形**：新增 `core::baseFormOf`——不规则表回答基词（多基按词频取一，与 lemmatize 同），否则取放宽后缀规则的第一个词干，否则词本身；**不做频率平局裁决**。mark（）（铅笔按钮、气泡、弹窗胶囊共用的入口）与读者词表导入都经它落键；UI 面上 verdictChanged 仍发扫描认识的形式，铅笔按它删线、重判经 formsOf 命中基词键。
  - **存量键一次迁移**：`KnownStore::rebaseMarks` 在启动时把每个键映到原形，动了才保存；同基冲突时掌握压已会，读者删过的基词保持删除，旧键带走墓碑——同步不会把表面形式的旧键盖回基词键上。
- **后果**：
  - 词汇弹窗与导出从此显示原形（crumple 而非 crumpled）；弹窗 “无历史行” 的稀疏样式（无时间、0×，ADR 0159 / UI-SPEC 4.8）不因此改动。
  - 另一台设备上旧键的合并依赖墓碑；同步两端的键在各自迁移后归于一致。
  - baseFormOf 不是 lemmatize 的替代：档位查询、缓存键、词表查询仍走 lemmatize 的频率裁决，只有判定键走形态学原形。
