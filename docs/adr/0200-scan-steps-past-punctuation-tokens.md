# 0200 走词越过标点 token，不在句点上原地打转

- **状态**：accepted
- **背景**：SumatraPDF 会把行尾、页尾的句号当成独立的词单元。`Move(Word, +1)` 落在句号上后，读取器在句号的框里做 `RangeFromPoint` 再 `Expand(Word)`，扩回的是**前一个词**——于是 `step` 每步都返回同一个词。TrackCore 的游标不前进，不断给同一个词分配新跨度（真机日志里跨度每秒 +756、可见词数持续增长），下一行和下一页永远读不到；缩放（重排）或重新聚焦（重建轨道）才会恢复。多页 PDF 在真机上稳定复现。
- **决定**：`stepByBox` 每次 Move 后先看移动后范围的文本；没有字母（数字与标点都算）就沿同一范围继续 Move，最多 8 个 token；有字母的词才用 `RangeFromPoint` + `Expand(Word)` 取词柄。空框或点查询失败仍报 awaiting（ADR 0199）；`Move` 到文档两端返回 0 仍是结束。行中句号与页尾句号都按这个顺序越过。
- **后果**：行尾/页尾标点不再阻塞走词；连续标点最多越过 8 个后按 awaiting 重试，不会把文档判成结束；同一个词不再重复分配跨度。Chrome 与 Notepad++ 的 `step` 不走这条路径。此修正没有自动化用例（需要真实的 Sumatra 提供者），由 ADR 0197 的探针与真机验证覆盖。
