# 0031 宠物从随包提供的几只里选，不做用户导入

- **状态**：accepted（补全 ADR 0030 中 “选择哪一只宠物” 一项）
- **背景**：桌面宠物有了第二、第三只之后，设置里需要一个选择入口。读者能拿到的选择有两种：在开发者随包的宠物里挑，或导入自己的宠物包并自编动作。PRODUCT.md 原先写 “没有选角色的入口”，UI.md 却已经画了下拉框，两处不一致。
- **决定**：
  - 每只宠物是随包的一个目录 `data/pet/<id>/`，目录名即 id。设置里只存 id，键为 `pet`，默认 `dog`。
  - 下拉框列出随包的 id。显示名用 `qsTranslate` 按 id 对照，跟随界面语言；没有对照的 id 显示原始 id。
  - 切换即时生效。切到数据有误的宠物时不保存这个 id，宠物留在原来那只，错误写入日志。
  - 不做导入与自编动作。
- **后果**：
  - 新宠物只能由开发者随包发布，读者没有导入入口。目录名成为对外稳定的 id。
  - 已保存的 id 若在随包数据里消失，启动时宠物关闭，设置里也看不到下拉框，只能改 `settings.json` 才能恢复。这里不做回退：随包数据缺失是开发者的问题，不是读者能修的问题。
  - 显示名放在 QML 而不进数据文件，数据因此不带语言。代价是每种界面语言都要补一条 `.ts` 翻译，补译之前新 id 显示原始 id。
  - 被排除的方案：导入宠物包。它要校验任意外部的 JSON 与图片，还要守住隐私边界（宠物只接收事件类型），代价远大于收益。
