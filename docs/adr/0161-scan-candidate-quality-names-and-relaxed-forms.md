# 0161 扫描候选质量：句中大写即人名，词形覆盖放宽而 lemma 不放宽

- **状态**：accepted
- **背景**：4fcb1b0 之后扫描仍泄漏两类候选。其一，人名判定是 “全页从头到尾都大写才算名字”，页面上任何一处小写——URL、署名、话题标签——就把名字放行成生词（日志里 maga、dong、lai 反复画线），词表尾部还混着大量小写拼写的名字；名字集又是从 “无裁剪的最大文档” 读的，iframe 重的页面会读错文档。其二，后缀规则有长度护栏（-ed/-ing 只还原 5+ 字母、-er 6+、-est 7+），把基词极简单、曲折形却排 4600+ 名的词挡在覆盖之外（日志画线 oldest 4644，其基词 old 排 189；nicer 5740→nice 196 同类）。但 corpus 明确钉住 “读者单独选中什么就解释什么”（nicest→nicest、used→used、offer 不是 off 的比较级），护栏不能简单拆掉。
- **决定**：
  - **句中大写即人名**：句子边界是 `.!?` 与换行（换行让列表项、标题的首字母大写不作证据）；一个词只要在句中被大写过一次，整页按人名丢弃——正文里的小写不再放行它。原规则（全页大写）对 “只在句首大写” 的词仍然生效，ADR 0155 记录的句首误伤口径不变。
  - **名字集读自被跟踪的文档**：TrackState 的名字读取改用 track 自己持有的页面 pattern，fresh search 只在 track 还没有页面时兜底。
  - **词形分流**：`lemmatize`（决定 lemma 标签）保持严格护栏——选择路径解释读者选中的形式，corpus 原样；`formsOf`（只服务于档位判定与判定库覆盖）用放宽规则（-ed/-ing 到 4 字母、-er 5、-est 6），档位与读者判定因此按词基覆盖曲折形。放宽引入的假还原（自身是原形、词干恰好也是词）由 keepAsIs 承接：seed/feed/weed/shed/liver/sheer/meter/digest/offer/peter/water/forest，按 “样例抓到一个加一个” 的既有模式增长。
- **后果**：
  - 句中大写的生词（引用标题、行内小标题）会在该页被当人名丢弃；列表项因换行即句界而不受影响。这是学习召回换名字抑制的取舍，PRODUCT.md 的硬过滤边界随之更新。
  - 系统枚举（词表全量、三个类、底座 3000）显示放宽后的假吸收集中在 -er/-est 的五六个字母段；吸收方向（自身高于底座、假词干低于底座）的词在 keepAsIs 名单内，名单外的长尾按既有模式续补。
  - 前台切换的扫描失效从 “每 250 ms tick 一次” 改为 “离开页面一次”：lens 卡片盖在浏览器上、短暂的前台抖动不再反复重建 track、不再把掌握按钮从读者指针底下拆走（UI-SPEC 4.20 的三种立即收起事件原样）。
