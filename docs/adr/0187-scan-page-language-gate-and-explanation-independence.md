# 0187 扫描加页面语言门，并与解释通道解耦

- **状态**：accepted（2026-11-16）
- **背景**：ADR 0186 换表后，本机日志的真实候选里仍有法语 12、拼音 9、缩写 15、专名 4 被画线——这些在任何英语词典里都是合法条目，换表清不掉，0186 明说交给 “紧随其后的语言门”，但语言门一直没动工。另一桩旧症：气泡一出现在 Chrome 上方，整页虚线与路标就收起，要等下一次稳定读取才回来。TODO 把它记成 “抓图指纹”，可截图指纹扫描路径早已退役（见 CHANGELOG 1.0.0-beta）；当前 UIA 扫描下没有任何指纹门控，真因是 `AppController::refreshCaptureGates()` 把 “解释在忙”（`busyLabel` 非空）当成扫描暂停条件，于是每次查词、每次 Alt 路标预取都把整页线拆掉。
- **决定**：
  - **语言门** `capture::pageLanguageOf(text)` 落在 `page_alignment`，与 `nameSet` 同源、复用 `pageWords` 的分词。三态 `Unknown / English / Foreign`：CJK 字符（汉字、假名、谚文）多于 ASCII 字母 → Foreign；字母词不足 50 个 → Unknown；否则英语功能词占字母词的比例 ≥ 14% → English，否则 Foreign。功能词表约 150 个，内嵌为函数内静态集合，不引外部数据。
  - **阈值有据**：代表性语料实测英语散文 64%、英语技术页 37%、法语 6%、西语 5%、德语 1%、意大利语 3%、拼音 2%。14% 在英语与外语两侧都留裕度；50 词下限让设置清单、标题页这类短文本落到 Unknown。
  - **TrackCore 挂载**：在名字集刷新的同一份文本上算 `foreign_`，不额外读页。外语页停走词、停画线，但锚点读取与名字刷新照常，页面转回英语时走词与画线即恢复，无需重新 acquire；Unknown 一律当英语（失败开放）。判定翻成外语时记一条 `held: the page reads non-English` 诊断。
  - **扫描与解释解耦**：`refreshCaptureGates()` 的扫描暂停只由预算驱动，去掉 `busyLabel` 项。扫描走 UIA、在自己的线程上读页，与解释通道无共享资源，解释在忙不再收线。
- **后果**：
  - 非英语页整页不画线，英语技术页保留；短页、空读、坏字节都失败开放，不误伤英语页。
  - 查词与 Alt 路标预取期间虚线不再消失——核心学习动作不再惩罚整页标记。
  - 语言门每 5 秒随名字集重判，SPA 改写语言能跟上；CJK 多数规则覆盖中、日、韩页。
  - 英语页上的缩写与小写专名残留不在本 ADR 内：那是词级噪声，语言门管的是整页语言，二者正交。
- **被排除的做法**：
  - 用 OCR / 截图指纹判语言：扫描已不走像素，且指纹路径已退役。
  - 引外部语言检测库（CLD3 之类）：功能词占比已足够分离，不值得为此加依赖。
  - 把语言门做成设置开关：读者要的是默认干净，失败开放已兜住边界，不加开关。
  - 给气泡加抓屏排除来修收线：真因是 busy 暂停，抓屏排除治不到这条路径。
