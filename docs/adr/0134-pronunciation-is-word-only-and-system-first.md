# 0134 发音只做单词，系统合成器优先

- **状态**：accepted；尚未实现，本轮只定契约。取代 [ADR 0010](0010-model-ipa-without-speech.md)（“音标随模型释义返回，暂不提供发音”）。
- **背景**：0010 当时用 “不接 TTS” 关掉发音，理由是避免引入本地音标库及其数据与许可维护。现在要补的是**单词发音**这一个动作，不是朗读——句子、实体、译文与拆解卡都不需要它。读者机器上的系统音色又参差不齐（本机 SAPI5 只有 `Zira` 与 `Huihui`），而通用合成端点对任意句子返回 500（2026-10-28 实测），把范围放大到 “朗读” 只会换来一个不可靠的功能。
- **决定**：发音只挂在单词卡的 headword 上，一次读一个词。设置里两个开关：**自动播放**（缺省关，打开后取词弹出的单词卡出现即读一次，同一词不重复）与**口音**（美式缺省 / 英式）。引擎三档：**系统合成器为缺省**；它不可用时按读者选的兜底走——在线音频（缺省）或本地神经模型，也可以关掉兜底。明确选了在线或本地之后，不在两者之间静默切换（同 ADR 0130 对 OCR 的要求）。本地模型不随包：安装包只带 Apache-2.0 的 sherpa-onnx 运行时，英文音色模型由读者在设置里按口音下载并校验 SHA256，落 `%APPDATA%\Lens\voices\`；不引入 GPL-3.0 的 piper，MIT 主程序不链接 GPL 库。发音不花钱——在线音频无 key、不计费，因此不进每日预算，也不发往解释服务商。
- **后果**：音标行由 “只读” 变成可点，多一枚喇叭与两个状态（请求中 / 正在读）。**自动播放缺省关**：声音比画面更容易打断阅读，且自动扫描会连续弹词，默认出声等于替读者做决定。自动播放只对取词弹出的单词卡生效——设置预览卡、词汇列表悬浮复习卡与宠物作答卡都不自动读，前者是调设置的副产品，后两者是被动表面（悬浮一行就出声，或替读者答出宠物问的词）。在线兜底会把被查的那个词发给第三方音频服务，进 `SECURITY.md` 的出站清单，与图片查询同一档。本地模型未下载时兜底等于不发音，设置页要写明，且不弹错误。系统音色的质量由读者的 Windows 语言包决定，设置页必须显示当前音色名——读者得知道自己听到的是谁。
