# 0113 多义关闭的单义卡用 `Not-the-Sense?` 条目原地换义

- **状态**：accepted
- **背景**：多义解释开着时，SenseRows 的每一行本身就是义项选择器；关掉后卡片只剩最常见的一义，读者读到的是次义（crane 在句里是鸟，卡上只有起重机）时没有回去的路。原型 `word-images.html` 的 B 卡把 `Not this sense?` 放在图片条内部，但没图的词同样有这个问题，且一次只有两义可选。
- **决定**：多义**关闭**的单词卡底部放一整行 `Not-the-Sense?` 条目——左标签、右侧下一个待换义项的一个英文单词。点击把卡片原地换到下一义（释义行、路标行、展开着的图片条一起换），换义不重锚窗口、不重放打字；条目的右侧每次预告下一义，到头轮转回最常见释义。下一个更常见的义由新增的**义项通道**（`data/llm/request.sense.json`）按需逐个买：输入一词加已给出的义项清单，输出至多一义，`senses` 空数组即 “没有更多” 的正答。悬停条目即预取下一次点击要换的义，点击因此通常瞬时。
- **代价**：换义走 `senseSwapped` 信号直改卡片属性，**不**重走 `bubbleChanged` → `Bubble.show()` 那条路——那条路每次都向锚点重放放置，会把读者拖开的卡拽回去；代价是 duty 必须让 payload 与换义后的卡片保持一致（静默重写 payload 的义项行与条目字段），否则判定已会/新词这类刷新会把义弹回首义。买过的义项按 “解释语言 + 词” 记在会话内存里（与一瞥同款），不进缓存文档；词删除时随缓存一并作废。模型答不出新义（空 `senses`）且手上只有一义时整行收掉，不留死按钮；与 “没送到” 的区分靠 usage 是否为零。词性（`pos` 字段）随同一次单词请求免费带回，只加显示开关。
- **后果**：多义开着时条目不出（行即选择器，两者并存是两个义项 UI）；换义请求受每日预算门，到顶时点击安静地什么都不换。会话内存意味着重启后已买的义要重新付费——按义项买一小笔，与把全部义项塞进主请求让每个读者都为没点的义项付钱相比，是更便宜的默认。换出的义项不携带词源 / 例句 / 搭配，卡上这些块仍画首义的：它们是词的上下文，不是义的。母语一瞥跟着循环走：中文母语直接用该义随义项通道买下的中文对（免费），其余母语的 peek 输入带 `sense:` 行只问该义、会话行按 “母语 + 词 + 义号” 记。词汇表悬浮复习卡的收回从 “指针离词即收” 放宽为 “指针离词与卡两者即收”——否则卡底这条目永远点不到；代价是指针在卡上时卡多留一会儿，面板关闭仍强制收（`dismissReviewNow`）。
