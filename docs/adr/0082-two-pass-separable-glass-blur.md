# 0082 玻璃模糊改成两遍可分离高斯

- **状态**：accepted（阶段 6；改写 ADR 0070 的单趟 25 点模糊，其余不变）
- **背景**：流光玻璃、模糊 15、1920×1080@100% 下，卡片后的文字页与细节上出现细密的横竖交织纹，像一层织纹或摩尔纹，读者读作“条纹严重、不够柔”。单趟着色器每轴只有 5 个抽样点，点距约 10.4 px，预滤波读的是“一个抽样点宽”的 mip；mip 的盒式滤波阻带太弱，高于抽样率的细节被折回可见的纹理。用实际壁纸加 20 px 文字行复现：单趟结果的拉普拉斯能量 0.54，有效边缘宽度（10–90%）31 px。
  - 单纯加密抽样不解决：单趟 9×9 的能量 0.25，但边缘只有 28 px（反而更锐），每像素 81 次取样，约为单趟 5×5 的 3.2 倍。
  - 只加 LOD 偏置能压到 0.23，但仍是单趟，纹理没有消失。
- **决定**：
  - 拆成两遍：新 `glass_hblur.frag` 把幕布沿 x 模糊成一张幕布大小的 mip 纹理，`glass.frag` 再沿 y 模糊、加饱和与折射、切圆角。两遍都是每轴 9 个抽样点，点距 0.95σ，权重固定（`exp(-(0.95i)²/2)` 归一化）。
  - 两遍的 mip 都比抽样间距粗 **0.75 级**：预滤波不再是一个抽样点宽，而是约 1.5 个，阻带被压下去；这是纹理消失的关键，不是抽样点数量。
  - 横向那遍覆盖整张幕布而不是卡片，纵向那遍在最外一圈抽样和折射仍有 112 DIP 的幕布余量可读。纵向那遍的 `origin` 仍是卡片在幕布中的位置，所以拖动卡片只改一个 uniform，不重做横向纹理。
  - 两张纹理都保持 `mipmap: true`；模糊与饱和仍是 uniform，滑块拖动不重载图片。总模糊约名义值的 1.2 倍（两遍各加一层盒式预滤波），同一档位比改前柔约 10%；UI.md 3.1c/3.1d 的“100% 即 60 px”仍是名义刻度，不改。
- **后果**：
  - 同一张复现图：纹理能量 0.54 → **0.027**，有效边缘 31 → **34 px**；文字页成为均匀的柔面，横竖织纹消失。
  - 成本：横向那遍覆盖幕布（约卡片 + 224 DIP），每像素 9 次取样；纵向那遍每像素 9 次加位移图 1 次。合计约 22 次/像素，比原来的 26 次少；代价是多一道离屏 pass 和一张幕布大小的 RGBA8 mip 纹理。500×700 的卡片约 3.6 MB，只在卡片画幕布时存在。
  - 两张纹理的 mip 每帧各生成一次（Qt 的 `ShaderEffectSource` 每次渲染后 `generateMips`）；GT 710 上未量帧时。
    离屏 GPU 核对（`QQuickRenderControl` + D3D11，跑的是本轮真实 `.qsb`，1000×620 文字页，模糊 15）已确认新链路
    平滑、旧 5×5 的横竖织纹清晰复现；没有动真机桌面截图，`GlassSurface.qml` 的接线仍要在发布前的真机视觉 QA 里看一次。
  - 横向纹理在幕布空间，卡片在幕布里移动时它不变；只有换幕布或改模糊才重画，所以拖动不会多付一遍。
  - 折射仍作用在模糊之后，顺序不变；直通（模糊 0）不画幕布也不建这两张纹理，行为不变。
  - 没有新增表面、字符串或设置项，`UI.md` 与 `PRODUCT.md` 的刻度不变。
- **被排除的选项**：
  - 单趟 9×9：实测更锐、每像素 81 次取样，GT 710 上多个玻璃表面可能掉帧。
  - 5 taps + LOD 偏置：一行改动、纹理减半，但仍是单趟，大半径时纹理回来。
  - CPU 高斯金字塔：每帧发布 2.25 MB 的幕布时在 CPU 重建 mip，成本比一次 GDI 读取还高。
  - 只调大默认模糊：会把稀疏抽样的纹理一起放大，不是修法。
