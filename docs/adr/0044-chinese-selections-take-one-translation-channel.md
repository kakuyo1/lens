# 0044 中文选区走一条译文通道

- **状态**：accepted
- **背景**：中文选区此前按形状分流：二字词落不到任何词表，够不着动作条；整句落进句子通道，拿回来的是 “用英文通俗解释这句话”，而不是这句话的英文。词、专名、整句三种形状各有一套提示词，而读者从中文里要的东西只有一样。
- **决定**：选区含汉字时，形状不再参与判定，整段走新的译文通道（`data/llm/request.translation.json`）：一套提示词、一个 `default` 预设、一份只要求 `en` 的响应 schema，气泡只画那一行英文。
- **后果**：译文恒为英文，`es` / `ja` 读者也拿英文——输入是中文，读者的解释语言恰好是那个不可能对的答案；输出也只有一份，省下把中文原样回显的钱。判据是汉字（U+3400–U+9FFF），假名、谚文、全角标点都不算，日文与韩文选区仍按形状分流。含汉字的选区不再受最小词长门槛：门槛数的是字母，而二字词照门槛算永远弹不出动作条。样例集里那条中文夹一个英文词的混排段落，期望由 Word 与 `mixed` 改为 Translation——读者选中它要的是整句的英文，不是其中那一个词的释义。
