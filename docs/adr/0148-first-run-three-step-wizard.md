# 0148 首次引导升级为三步向导

- **状态**：accepted（2026-10-31）。部分取代 ADR 0144：0144 的首启通知卡与托盘首行常驻不变的部分见下。
- **背景**：0144 的首启引导是一张通知卡，动作直达设置 › 模型服务，之后读者要自己在设置里找齐三件事——选档位、选服务商、贴 key——完成后也没有 “试一下”。新读者的转化路径太长，且卡片本身没教任何东西。
- **决定**：首启引导改为三步向导（新表面 `onboarding`，UI-SPEC §4.19，复用设置面板的壳组件）：① 选人群与档位；② 选服务商并贴 key（DeepSeek 保持默认，附一句费用预估）；③ “试一次”——面板里给一段两行英文示例文，读者拖选其中的词，面板旁浮出该词的演示气泡（走设置预览卡同一机制，本地样例，零请求）。三步内容即时写入（与设置面板的行语义一致）；`ONBOARDING.done` 是唯一的例外，完成或跳过时才写，两种结局等价——跳过即 “已引导过”，此后不再弹任何首启引导。
- **后果**：
  - 0144 的通知卡不再承担首启引导：`kNoticeIntentApiKey` 意图链（常量、`showNotice` 参数、表面属性、Main 的路由分支）随之退役，通知卡只剩失败类语义。0144 的另一半——缺 key 期间托盘菜单首行常驻、tooltip 模式位替换——原样保留。
  - `launchPlan`（core/domain/onboarding.h）的判据不变，写入时机变了：未引导且缺 key 的启动只弹向导不记录，记录交给向导的 `finish()`；已有 key 的读者照旧只记录不弹。编译开关 `LENS_FORCE_ONBOARDING` 改指每次启动弹向导，同样不记录，`finish()` 在强制模式下不写。
  - 0144 曾以 “打断过重” 否决首启自动开设置窗口；向导不是裸设置面板而是带解说的引导面，三步都可跳过，这条判例不再约束它。落选方案：通知卡保留、由卡上动作进向导（没点卡的读者看不到向导，转化弱）；跳过后回落弹单卡（读者连看两个引导面）。
  - 向导第三步的演示气泡是第二张 preview Bubble 窗口，glass sheet 键 `onboardingPreview`（一张幕布只属一扇窗，docs/adr/0041）。
