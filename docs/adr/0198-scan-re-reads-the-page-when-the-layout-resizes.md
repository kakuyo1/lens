# 0198 缩放或重排后，扫描按锚点重读整页词框

- **状态**：accepted
- **背景**：虚线按 “锚点词框 + 各词相对锚点的偏移” 摆放，这套模型只适配滚动（整体平移）。页面缩放或文字重排改变的是词与词之间的距离与尺寸，锚点词框的宽高会变化，而偏移还是旧布局的，离锚点越远错得越多。Chrome 的网页缩放与 SumatraPDF 的页面缩放都会触发；真机上两者都复现。
- **决定**：
  - 每步读到的锚点词框与上一步相比，宽或高相差超过 1 px 即判为页面重排（1 px 留给取整抖动）。
  - 判为重组后保留锚点（词柄与 id 都不换，候选仍在），把跨度清到只剩锚点，重读锚点的裁字框；游标回到锚点、`wordsSeen_` 清空，让走词按新布局重新读入并重新领取 id（判定按 surface 缓存，不重复过滤）；遮挡判定一并清空。定位与滚动时词框尺寸不变，走的仍是原来的平移路径。
  - 重排那一步线先收起（未 settle），随后三步内按新布局重新画出。
- **后果**：
  - 缩放与重排后虚线重新对齐，Chrome 与 Sumatra 共用这一处修复。
  - 连续缩放时每步都会重读一段（最多前后各 12 词）；线在缩放过程中收起，停稳后画出。
  - 窗口缩放若引起重排、但锚点词的尺寸恰好不变，不在本修复的判定内；记在这里的边界。
  - 被排除的方案：按锚点词框的宽高比例直接缩放偏移（纯缩放可用，但 Chrome 的文字重排不是等比缩放）；重排时丢掉整页重新取页（搜索与名字重读更贵，锚点也丢了）。
