# 0034 玻璃背景取自抓屏，不用系统材质

- **状态**：accepted（渲染部分由 ADR 0037 取代：模糊、饱和、折射改在 C++ 中计算，`MultiEffect` 与着色器不再使用；抓屏取背景的决定不变）
- **背景**：设置里的雾面玻璃与流光玻璃，原型里用 CSS 的 `backdrop-filter` 实现，效果依赖浏览器对背后像素做模糊与位移。
  QML 没有等价的通用能力：`MultiEffect` 只能处理同一窗口里的 item，不能直接读取窗口背后的桌面。
  另外两条路被考虑过：Windows 11 的系统亚克力（DWM 材质），以及抓屏后交给 Qt 的效果链。
- **决定**：
  - 玻璃的背景由应用抓屏得到，复用 `capture_duty` 已有的 `QScreen::grabWindow`，把玻璃卡片所在区域的桌面画面送进 QML。
    抓屏前卡片要先隐藏，参照 `Mask.qml` 的 `settleMs`，否则玻璃会把自己截进背景。
  - 雾面玻璃的模糊、饱和度用 Qt 6.9 的 `MultiEffect`（`blur`、`saturation`）完成，参数按视觉接近标定，不追求与 CSS 的核一致。
  - 不使用 DWM 系统亚克力。它只在 Windows 11 生效，模糊与饱和由系统决定，设置里的旋钮会失效，且材质自带噪点，与 UI.md 3.1c 的 “无噪点” 冲突。
  - 流光玻璃的折射不能由 `MultiEffect` 完成，需要 `ShaderEffect` 加自写片元着色器，位移图由 C++ 生成。
- **后果**：
  - 玻璃背景会随桌面变化而过期。拖动或桌面变化时需要重新抓屏，这会带来 CPU 与 GPU 的开销，抓屏频率要单独定。
  - 抓屏会拍到读者的桌面内容。玻璃只使用卡片所在区域，画面不落盘、不进日志，也不随其他遥测上传。
  - 125% DPI 下 `MultiEffect` 会重采样离屏贴图，`docs/QML.md` §3 记录的问题同样适用于玻璃背景，需要真机看过再定。
  - 流光的着色器工具链未定：Qt Creator 自带的 `qsb` 是 6.10.1，而仓库的 Qt 前缀（`config/paths.default.json`）是 6.9.0，版本是否匹配尚未验证。（2026-10-12 探测：6.10.1 的 qsb 产出的 `.qsb` 能被 6.9.0 的 offscreen 运行时加载并编译，出图与 D3D11 后端未验证。）
    在确认能编译并在 6.9 运行之前，流光可以延后，雾面不受影响。
  - 像素级一致不是目标。原型的底图是人造的，真机背景是读者的桌面；验收方式是参数一致，并由人眼并排对看。
  - 实现要在两个场景上单独验证：`QT_QPA_PLATFORM=offscreen` 下无法看到观感，只能断言参数与时长；真机观感靠人看。
