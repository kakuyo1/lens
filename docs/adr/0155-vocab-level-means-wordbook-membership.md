# 0155 档位改为 “读者已会的词书”，影响扫描、选区取词与释义链

- **状态**：accepted
- **背景**：档位（`level`）现在只是词频阈值（`rankForLevel`，`src/core/domain/filter_core.cpp`），对扫描几乎没有影响。一次扫描日志的 153 个不重复候选，在 CET-4 档时全部画虚线，因为它们的词频排名都超过阈值 5000。`data/wordbooks/` 已有八份按档位划分的词书（来源与许可见 `data/wordbooks/NOTICE.md`），可以按书判断读者是否已会。
- **决定**：
  - 档位的含义改为 “读者已会的词书”。每档 = 底座 ∪ 自身词书。
  - 底座 = B1-B2 书 ∪ 词频前 1000，所有档位共用。词频前 1000 补上口语与功能词（`gonna`、`yeah`）等不在词书里的高频词。
  - 词书组合：B1-B2 = b1-b2；C1-C2 = c1-c2；CET-4 = cet4；CET-6 = cet4 ∪ cet6；TEM-4 = tem4；TEM-8 = tem4 ∪ tem8；IELTS = ielts ∪ cet4；TOEFL = toefl ∪ cet4。
  - 只影响三处：扫描虚线（只画 New 候选）、选区取词挑哪个候选（Word 选区优先取 New）、释义链点线（不在档位内的词画点线）。
  - 不写入已会库：档位不回写 known-set，换档位可逆，词汇列表与统计不变。`level` 仍随设置同步。
  - 词书不进模型请求，沿用 `PRODUCT.md` 的 “档位只影响本地” 规则。
  - 缺词书文件：该档只剩底座，记一条警告，不阻止启动。
  - 换档位后扫描结果立即失效，虚线按新档位重画。
- **后果**：
  - 同一批 153 个候选（`logs/lens.log` 中不重复的扫描候选，已复现），按实现的判定：CET-4 档虚线 112 条，TEM-8 档 80 条（旧的词频阈值下 CET-4 档全部 153 条都画线）。候选多为人名与稀有词，下降幅度有限；候选质量问题仍在 `TODO.md`。
  - 词书规模不随档位单调：CET-6（8345 词）比 CET-4（7122 词）大，TEM-8（13364 词）最大。这是词书本身的规模，UI 文案不能暗示 “档位越高词越多”。
  - 释义链的点线反而减少。对 199 条缓存的英文释义（共 2416 个词）实测，八档的点线数都少于旧词频阈值：CET-4 档 146 → 77，TEM-8 档 67 → 47。原因是 B1-B2 书与词频前 1000 之外的常见词现在都在档内。
  - 取代：`docs/adr/0078-definition-chain-drills-in-place.md` 后果中关于 `rankForLevel` 的一条；`src/core/domain/filter_core.h` 里 `minFreqRank` 的 “not settled” 说明。0078 的其余决定不变。
  - `GLOSSARY.md` 的档位条目里 “known-set 预置” 的说法与本决定不符，实现时改。
  - 实现已完成：词书加载与判定（`loadWordbooks`、`difficultyForLevel`）、三处接线、`data/preview.json` 的样例（原有 11 个不在词书里的样例词已替换）、测试，以及 `PRODUCT.md` / `UI-SPEC.md` 4.4 的更新。
  - 被排除的做法：
    - 把整本词书写入 known-set：换档不可逆，同步会把词书带到其它设备，词汇列表与统计都会改变。
    - 只用自身词书、不设底座：B1-B2 书以外的高频口语词会被当成新词画线。
    - IELTS 与 TOEFL 只用自身词书：托福读者会在大量 CET-4 词下看到虚线。
