# 0129 复制文本悬浮展开抽屉，只列适用的项

- **背景**：复制文本很少被用，而设计想在它上下展开新动作：纠正拼写、纠正语法、句子拆解。UI-SPEC 4.10 原先规定三项一律可用、不做适用性灰化。后两项只对特定形状有意义，若仍一律可用，就要对不适用的选区给出无效结果或一段说明，动作条会变得难读。
- **决定**：复制文本悬浮展开抽屉，抽屉只列当前选区适用的项，不适用的项不画（不灰化）。适用规则随选区形状：单词列纠正拼写；句子列纠正语法与句子拆解；多词的名称短语与中文选区不展开；单个 token 列纠正拼写，不论分类器把它归为词还是实体。翻译与解释保持一律可用。五种动作条形态各画一种抽屉（原型 `ui-prototypes/selection-bar-expand.html`）。
- **后果**：三项 “一律可用” 的契约改为：翻译与解释一律可用，复制文本一律显示，抽屉按形状适用。读屏按压复制文本即展开抽屉，抽屉的每一项是 `Accessible` 按钮；窗口不接管焦点，抽屉没有键盘入口。纠正拼写与纠正语法引入两个新通道，由复制抽屉的动作选择，不由形状决定，因此 `docs/adr/0009` 的 “形状决定通道” 要在落地前修订（本 ADR 不修订它）。两个通道的呈现：修正后的文字，改动的词加下划线（`UI-SPEC.md` 4.10 纠正的气泡）。另有一处冲突：`classifySelection`（`src/core/domain/filter_core.cpp`）把词表外的单个 token 归为实体，拼错的 `recieve` 实测如此。若适用规则按分类器结果判定，纠正拼写就永远看不见拼错的词。因此适用改按 token 数判定：单个 token 适用，多 token 的名称短语不适用。这一条待实现时用真实选区验证。
