# 0043 读者可安装只含数据的宠物包

- **状态**：accepted（在 “导入宠物包” 一项上取代 ADR 0031 的部分决定）
- **背景**：ADR 0031 把 “导入宠物包” 列为被排除的方案，理由是它要校验任意外部的 JSON 与图片，还要守住隐私边界；`PRODUCT.md` 与 `GLOSSARY.md` 同样写着不做用户自定义。到 1.3.2，宠物已经是纯数据（JSON + PNG）：动作名与配饰都由宠物自己的文档给出，加载器整只拒绝。产品决定改为支持读者侧扩展，前提是包不执行代码、校验有明确契约。现有校验的缺口（G1–G5）已在本次提交中修复。
- **决定**：
  - 读者把宠物包放在 `%APPDATA%\Lens\pets\<id>\`，应用在打开设置的扩展分类时扫描该目录。
  - **包只含数据，应用不执行包内的任何代码**：不加载 DLL、不执行脚本、包内不放 QML。隐私承诺（宠物只收事件类型）继续由 `PetEvent` 在类型层面保证；这条同时排除了 “包能读取事件之外的数据”。
  - 契约、上限、校验规则与拒绝原因见 `docs/pet-package-format.md`。它是第三方作者的规范文档，也是校验实现的依据。
  - 随包 id 保留：外部包与随包 id 相同时拒绝该外部包。`id` 限 `[a-z0-9_]`，比较不区分大小写。
  - 外部包的显示名（`name`）不进翻译；去掉控制与格式字符、做 NFC 归一后显示。来源标记由应用绘制，包无法影响。
  - 首次选中某个外部包时弹一次确认，确认前不启用。确认按包记录，落在设置文档 `PET.confirmed` 的一个 id 数组里；包被删掉后该条不清理，重新放回不再弹。
  - 外部包缺失或被拒时回退到随包默认宠物，不进入 “宠物关闭且选择器也消失” 的死角。
- **后果**：
  - 需同步 `PRODUCT.md`、`GLOSSARY.md`、`UI.md` 与 `SECURITY.md`。新增读者可见文案已跑 `lupdate` 与 `lrelease`，补齐 4 份 `.ts`；`README` 的四个语言版本各加一句说明。
  - 校验的性质从 “开发者自己的数据” 变成 “信任边界”。缺口（路径逃逸、无上限、整数溢出、表情索引、`idle` 硬编码）由 “已知问题” 升级为落地前必须先修。
  - 被排除的方案：**代码插件**（DLL、脚本、包内 QML）。它能让包绕过隐私边界，而项目没有签名体系——安装包只校验 SHA256、不证明发布者身份，见 `SECURITY.md`。
  - 被排除的方案：**应用内解压 zip**。它要另写一整套解压安全规则（zip slip、解压炸弹、条目数、重解析点），而收益只是省掉读者一次手动解压。包以目录形态分发，压缩与解压由读者用系统工具完成。
  - 被排除的方案：**包市场或托管**。托管会让维护者从 “提供工具” 变成 “分发内容”，责任性质改变，见 `SECURITY.md` 的 “范围” 一节。
  - 已知边界：包是第三方内容，未经审核也未签名。应用只保证不执行代码并按规定校验，不保证包的外观与行为符合预期。
