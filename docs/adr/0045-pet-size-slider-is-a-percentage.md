# 0045 桌宠大小改成百分比滑条

- **状态**：accepted
- **背景**：桌宠大小此前只有四个整数档（×1–×4）。台阶的来由是像素方正：精灵按最近邻绘制，非整数倍率下每个源像素分到的目标像素数不等，图会 “发毛”（改动前的 UI.md 3.1 写作 “只取整数档”，`StepSlider` 的注释当时也复述了这条理由）。读者要更细的档位，且要改成百分比。
- **决定**：滑条走百分比：`0–100`、步进 1、显示 `N%`，`0` 即原来的 ×1、`100` 即 ×4，倍率 `1 + 3N/100` 连续取值。设置键随之从 `PET/scale`（1–4）换成 `PET/size`（0–100）：旧值 3 与新的 3% 用同一个键分不出来，所以启动时把旧值按 `round((s − 1) × 100 / 3)` 换算一次、写下新键并删掉旧键，读者原有的大小不丢。宠物包格式不动——`pet.json` 的 `scale` 仍是 1–4，只在读者没动过滑条时充当默认值（随包的 `"scale": 3` 即默认 67%）。
- **后果**：
  - 像素不再方正。非整数倍率下最近邻绘制让像素宽度不等，这是换细档位付出的代价，已在 `PetScene.qml` 的注释里写明。
  - 默认从 ×3 变成 ×3.01（67%），差一个像素量级。
  - 改大小会移动宠物窗口，但只做最小位移。窗口从左上角向右下长大，越过当前屏工作区的边时贴回该边，任何倍率下整个窗口都留在工作区内，新位置随即写回设置（`PET/position`）；缩小不移动。此前这条写的是 “不移动窗口，贴边时可能有一部分在屏幕外，拖回来即可”，实机上贴着屏幕边放大确实把宠物丢出了工作区，读者按 bug 报回（2026-10），故反悔。窗口整体大于工作区时钉在工作区左上角，当前上限 ×4 只有 352 px，正常屏幕碰不到。
  - 百分比读数只是滑条位置，不是 “自然尺寸的比例”：100% 画出来是 ×4 而不是原尺寸。这是读者给的刻度（一档 0%、四档 100%），未改。
