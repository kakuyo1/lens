# 0033 例句开着时，缺例句的缓存条目重新购买

- **状态**：accepted
- **背景**：例句是单词解释的又一项可选附加内容，由设置开关控制，与词源同形（同一次请求、同一份缓存条目、开关不进缓存键，见 ADR 0019）。但例句的情况与词源不同：词源缺失可以合理地表示 “这个词来历不明”，而例句缺失只可能意味着 “这条缓存是在开关关着时买的”。两者在缓存里看起来一样，都是字段不存在。
- **决定**：
  1. 缓存条目里的 `example` 用三态表达：字段不存在（`std::nullopt`，即买的时候没问）、空串（问过，模型没给）、非空（有句子）。
  2. 例句开关开着时，缓存条目若为 `nullopt`，视为未命中，重新请求，并把新结果写回。空串视为已命中，不重买。
  3. 请求发出时的开关值随 `ExplanationBatch` 携带，回包时以它决定是否存例句，而不是读回包时的开关。这样一次付费买到的例句不会因为回包前关了开关而被丢掉。
  4. 画卡片时仍读当前开关：关了就不画，条目保留，再开即用。
- **后果**：
  - 这一条推翻了 ADR 0019 对例句的适用：0019 说 “关闭时抓过的词，打开开关也不补”，那是词源的规则。例句打开后会为 “缺例句” 的词重新付费，代价是读者第一次打开例句开关后，已解释过的词会再买一次。这是有意的，读者打开例句就是为了要它。
  - 空串与缺失分开存，`cacheGet` 的契约因此多了一个分支。被排除的方案是统一用空串表示两者：实现更简单，但会让 “开着却永远没有例句” 的词被当成已付费的答案，永远静默不显示。
  - 悬浮复习（`reviewWord`）只读缓存、不发请求，不适用本规则：它对缺例句的词只是不画例句块。
