# 0070 模糊与饱和进着色器，幕布回原生分辨率

- **状态**：accepted（阶段 2；改写 ADR 0039 的 “模糊与饱和在 C++ 中计算” 与 ADR 0040 的 “1/4 分辨率”，ADR 0069 的直通不变）
- **背景**：阶段 0 的实测（`docs/metrics/runtime-performance/glass-capture-capability-2026-10-19.md`）把两件事定了价：
  - 同一节奏、同一区域，读全分辨率只比读 1/4 贵 17%，而 CPU 模糊在 1/4 上约 2.1 ms、全分辨率上约 41.6 ms。也就是说，
    1/4 降采样存在的唯一理由是喂饱 CPU 模糊；它本身正是 “模糊拉到最低仍然很糊” 的来源（ADR 0069）。
  - 每次滑块变化都换图片 URL，整张幕布重新加载、重新上传纹理。这是第二道墙，但它与模糊无关，留给阶段 3。
  所以这一步只做两件事：模糊与饱和搬到 GPU，幕布直接读屏幕分辨率；顺带把幕布的采集区域从窗口四周 160 DIP 收到 112 DIP，
  并把拖动时的重取挪出 GUI 线程。
- **决定**：
  - **模糊在 `glass.frag`**。五次一维高斯沿两轴各一遍，共 25 个抽样点；一维权重是 0.079、0.244、0.354，抽样间距取
    1.155σ，使五个点的二阶矩等于一个 σ。每个抽样点读取 mip 链上的一层，该层一个纹素恰好是一个抽样间距；mip 自己那点
    盒式预滤波把有效 σ 抬到约 1.05σ，与原来的三次盒式对齐。`ShaderEffectSource` 因此打开 `mipmap: true`。
  - **模糊与饱和是 uniform**，不再进图片 URL。`blur` 是百分比（100 即 60 DIP），`saturation` 是百分比（100 不改变），
    两者与 `refraction`、`radius` 一样由 QML 绑定。滑块变化只重画卡片，不重新加载、不上传新图，滑条拖动时那类闪烁随之消失。
  - **幕布回原生分辨率**（`SheetScale::Full`）。图片服务不再调用 `blurredPicture`，直接返回采集到的画面；
    `picture.setDevicePixelRatio(request.scale)`。`blurredPicture` 与它的用例保留，作为阶段 5 软件回退档的实现，不删。
  - **采集区域收到窗口四周 112 DIP**（原 160）。模糊由着色器在幕布里算，不再需要把卡片外 160 DIP 的桌面读进来；
    112 是 72 DIP 的拖动余量加 40 DIP 的迟滞。面积实测：1.16 Mpx 25.5 ms、0.56 Mpx 15.1 ms，约省四分之一到四成。
  - **拖动时的重取不在 GUI 线程上做**。`GlassSheet::followDeferred` 把读取投进幕布共用的单线程池，一次只允许一张在途；
    在途期间这张幕布的 live 刷新跳过，其余表面照常轮转。旧幕布在新图落地前继续显示，`generation_` 丢弃过期结果。
    这条是为 112 DIP 的迟滞准备的：小幕布在拖动中会重取得更勤，同步读会把每次重取变成一次 20 ms 的拖动卡顿。
  - **幕布必须不透明**。GDI 的 DIB 第四个字节是 0；`Format_RGB32` 在 Qt 看来没有 alpha，但纹理上传会读那个字节，
    于是整张幕布透明、`coverage` 归零、玻璃什么都不画（实测表现为卡片只剩 live 桌面）。`readDesktopRegion` 在拷贝前
    把每个像素的第四字节置 0xFF。
  - **权重写成下标的函数**，不从一个 `vec3` 里动态取。qsb 烘出的 HLSL 没有把动态索引的常量向量完整带过去，
    模糊一度整片发白；`weight(int)` 用分支返回三个常量，Debug 与 Release 都验过。
- **后果**：
  - 取图请求的 CPU 从约 2.1 ms（CPU 模糊）降到 **0.0~0.1 ms 中位**（实测，一次摘要窗口 129 次请求）；桌面读取在本机
    应用节奏下**中位 18.5 ms**、p95 约 26 ms，与阶段 0 同一场景的约 20.0 ms 接近（面积用例里同一块 1.16 Mpx 的幕布
    是 25.5 ms）：分辨率升到原生，面积同时收小，两者大致抵掉。
  - 内存：原生幕布图 690 × 815 × 4 约 2.25 MB（1/4 时约 0.14 MB）；两块离屏纹理的尺寸本来就是窗口设备分辨率，
    mip 链再各加三分之一。**估计每个活动表面多 4 MB 左右**，落在 2026-10-18 玻璃增量 0~23 MB 之内；没有单独复测。
  - 帧率不动：67 ms 的定时器与每帧换 URL 的交付路径都还在阶段 3。这条改的是画质与 CPU 账，不是帧率上限。
  - 观感：与 CPU 基线在模糊 10、40、100 三档并排截过图，Debug 与 Release 各一组；同档下花叶的软硬与颜色一致。
    大半径时最外侧的抽样点会碰到幕布边缘，此时幕布离卡片仍有 138 DIP，受影响的只是卡片最外一圈；默认 10% 远未到。
  - 未做：WARP、远程会话与纯集显笔记本上的 GPU 模糊代价；真实内存增量；阶段 3 的活纹理交付。
- **被排除的选项**：
  - 两级可分离高斯走 `ShaderEffectSource` 链（原计划的 B 案）：每个槽位多 1~2 块离屏纹理，且新槽位在离屏纹理就绪前
    不能显示（或要额外保持轮换槽的渲染），而 25 点 mip 高斯在实测三档上已经与 CPU 基线一致。真要修大半径的带状纹理，
    再走 B 案。
  - 保留 1/4 幕布再放大：模糊最低时的糊正是这么来的。
  - 保留 160 DIP 边距：模糊已不在图里算，多出来的面积是纯粹多付的读价；112 已经覆盖 72 DIP 的余量与拖动迟滞。
  - CPU 模糊继续留在主路径：一次 2.1 ms、每秒 15 次，且挡住 30/60 次的任何路线。
