# 0139 一场仪式与一次闲逛各由一个 module 拥有

- **状态**：accepted（2026-10-30）
- **背景**：ADR 0117 / 0118 / 0123 已把抛掷、躲藏与场景交成值进值出的 module，`PetController` 里还剩两台编排最大的状态机：入场 / 换宠 / 送别的 8 个阶段与 13 个字段，以及闲逛的等待 / 迈步 / 停顿与 8 个字段。`Hiding`、`canvas × scale` 与 `setHome` 也在多处复算，场景属性由入场与帧两处各发布一遍。
- **决定**：新增 `src/app/pet/pet_ceremony.{h,cpp}` 与 `pet_stroll.{h,cpp}`，都是无窗口、无时钟、无 QObject 的 module。仪式拥有阶段、走路、角色与换宠时序，控制器交进窗口与角色时长，按 `Step` 播放位置、走路循环、角色、换宠加载与落点；闲逛拥有等待、步数、停顿和边缘躲藏的掷骰，时间由调用方给、几何仍借 `PetWander`、指针压制自己的等待。同时把可见 sliver 的几何并回 `PetHide`，home 与最近屏规则收进 `PetPlacement`，场景属性只剩一个发布函数。
- **后果**：行为不变，仪式 14 例、闲逛 8 例、躲藏 14 例与 placement 的 11 例都是进程内值测试；控制器退为 adapter，`PetController` 对 QML 的属性接口本轮不动，`pose` 单值化留作 0139 之后的接口收缩。被排除的方案：只给控制器补端到端用例，仍要真窗口且等数秒；把阶段塞进 `PetStage` 或 `PetWander`，会让舞台或几何同时拥有窗口状态与时机。
- **ADR 关系**：0076 / 0089 的仪式行为、0095 的躲藏几何、0100 的 home 归属成为 module 的输入事实；0117 / 0118 / 0123 的 “module + adapter” 在宠物这里收尾。
