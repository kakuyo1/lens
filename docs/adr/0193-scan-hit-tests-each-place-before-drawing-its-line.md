# 0193 扫描落线前做遮挡命中测试，被盖住的词位不画线

- **状态**：accepted（2026-11-18）
- **背景**：读者报告 Chrome 里自动扫描 “看穿” 遮挡控件：一列单词底部被对话框盖住，扫描仍发现被盖的词，虚线画在对话框上方。复现页 `scripts/qa/fixtures/scan-occlusion.html`（词列 + 底部固定对话框 + 纯色浮板）在真机坐实：基线截图里被盖词的虚线站在对话框上。根因是 UIA 无障碍树只报告 “渲染出了哪些文字”，不关心 z-order：`TrackCore` 经 `Page::read()` 拿到的词框对被盖词照样有值，整条管线（TrackCore → ScanSession → 铅笔层）没有任何遮挡过滤。悬浮取词不受影响，因为它走 `ElementFromPoint`——屏幕自己的命中测试，尊重遮挡。
- **决定**：
  - **缝上加可见性判定**：`Page::visible(word, box)`，缺省 true——没有命中测试机制的读者（Scintilla）看不见浮层，判不了的位置保留线。UIA 适配器实现：在词框**下四分之一**处（字母内、靠近线位；中心点会漏掉 “下半被盖、线正落在控件上” 的词）做 `ElementFromPoint`；命中即词自己的 enclosing element（每词读一次缓存）则可见，两次 COM 答复常见情形；否则取命中元素的 `RangeFromChild` 文本 _scope_，用 `CompareEndpoints` 判词范围是否落在其中——落在对话框自己的文字里即被盖；`RangeFromChild` 失败即无文本控件盖在上面。命中持有词但不是其自身元素时是祖先容器：紧矩形（高 ≤ 2 倍词高、宽 ≤ 4 倍词宽）是词的链接/span 包装，判可见；页级大矩形是被无障碍树剪枝的无文本控件，判被盖。
  - **策略留在 TrackCore**：每个 span 一条 `SpanSight`（词柄 + 结论 + 结论时刻）。落线前 `applySight` 只保留判过且可见的词；没判过的位置这一帧不画，等判它的那一步——线永远不会站在没看过的控件上。首判每步最多 8 处（`kSightChecksPerStep`）保出线节奏；复查拿积分预算（见下条）：密集页几百个词位若全按 750 ms（`kSightRefresh`）复查会饿死锚点读，复查周期随词数与命中成本自然拉长。静止页上对话框开合，线随复查收起与恢复。页面真滚动即全部失效重判；重锚只换参照系、词的屏幕位置不变，结论保留。读词撞上滚动的那一步（整块丢弃）禁止新判（`mayCheck=false`），旧结论照滤——不把旧位置的词露出来。
  - **成本门与预算**：缝上 `Page::sightCost()` 报适配器自己的命中耗时均值；均值是**页实例自己的 EMA，不被壳的每秒 drain 清零**：第一版读共享累加器，drain 每秒把它归零，成本门于是每秒重开一次、放几个贵探针再关上，placed 集合在 “滤过/全量” 之间 1 Hz 振荡——铅笔层整屏闪烁，读者报告的就是它。均值又带**时间暖机**：页实例出生 1.5 s 内的探针不计入也不报价（浏览器建树冷启时网页的点查询也要十几 ms，按计数暖机避不开）。复查不拿固定次数，拿**积分预算**：每步按步时的 30%（`kSightSharePercent`）积信用，一次命中花掉它自己的实测成本——2 ms 的读者约 120 次/s，多窗 Chrome 里实测 10 ms 的读者约 29 次/s（对话框响应约 3 s），都不饿死锚点读、也不振荡。二值门只留给极贵读者：>12 ms（`kSightCostCeiling`，PDF viewer 实测约 20 ms）整趟跳过判定、保留修复前行为；阈值曾设 3/4 ms，把多窗 HTML 的 10 ms 稳态误判成贵读者而关掉过滤，故改为预算制 + 高天花板。
  - **帧门改比 id 集合**：锚点框每步重读有 ±1 px 抖动，几何比较会让静止页每秒发 1–3 帧空转；id 集合相同即不发，几何更新搭实质帧的车。
  - **仪器化沿用 ADR 0188**：`Op::Visible` 分项计时进 `scan read cost` 行，`TrackReport.sightChecks` 进 `scan track` 行。
- **后果**：
  - 真机 Chrome（复现页，1080p）：命中测试单次约 1.9 ms；稳态约 120 次/s（90 词 / 750 ms），合计约 235 ms/s，占跟踪线程约 23%；步耗时 avg 0.7 → 4.5 ms、max 约 23 ms（8 连判的 burst，壳的节拍夹取兜底），仍在 16 ms 预算内。首线 133 → 151 ms。
  - 三连拍坐实动态：对话框盖住时其上无虚线、对话框自身文字的线保留；点 Accept 关闭后被遮新词（avocado、cashew、pistachio）的线长回；重开即再收起。滚动后重判正常。
  - 确定性臂：`ops_last_added` 94 → 110（37 词），每词上界 3 → 4 次缝调用（step + read + 落线前命中）；`TrackCore.*` 13 例全绿，含新用例 `ACoveredPlaceDrawsNoLineAndTheVerdictFollowsTheControl` 与滚动丢块不变量。
  - PDF 标签（Chrome 内嵌 viewer，192 span）：成本门首秒学会后即收敛到 0 次命中，步耗时回到走词基线（read+step 约 790 ms/s，与修复前同量级），0 lost、无丢页风暴；HTML 复现页 108 span：156 次/s、步 avg 5.8 ms、max 15.1 ms。
  - **残留**：纯色无文本浮板仍会漏——Chrome 的无障碍点命中对无文本节点直接 “穿透” 返回下层文字，身份信号不存在；像素差分也认不出整词盖住的均匀浮层（没有期望渲染可比）。高成本读者（点查询 >12 ms，如 PDF viewer）整趟不做遮挡判定，保留修复前行为。两者要修都需 DOM 级访问（CDP/扩展）或更便宜的命中信号，超出扫描 “只读应用暴露的文本” 的边界（ADR 0154）。带文本的遮挡控件——读者报告的那一类——已覆盖。
- **被排除的做法**：
  - 每帧全量命中：每词每帧 2–6 次跨进程 COM，百倍于复查节奏的开销，无 correctness 收益。
  - 网格探针找遮挡矩形再几何裁剪：矩形随滚动过期（固定浮层与页内浮层运动规律不同），小浮层漏探，复杂度换不来更准。
  - 截屏像素比对：没有 “词应该长什么样” 的期望渲染，均匀浮层整词盖住时差分无信号。
  - 读词时判一次不复查：对话框在静止页上开合会留下过期的线，违背刷新稳定性。
