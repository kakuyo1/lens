# 0053 小卡是独立小窗口，举牌时宠物不挪动，手的位置从效果图量

- **状态**：accepted（2026-10-17）。与 `ui-prototypes/pet-review.html` 一致，除一处有意偏离：悬浮收起的 120 ms 延迟（见决定第 2 条）。
- **背景**：展开的小卡要放在牌子的外侧，而左侧展开需要窗口左边有空间。若把小卡并进牌子窗口，展开时窗口会变宽或左移（悬浮中移动窗口会让离屏的事件循环不返回，见 ADR 0050 的 “悬浮中不翻边”），收起时窗口的透明部分会挡住下面的窗口（UI.md §4.13 禁止留下透明的点击死区）。宠物靠近屏幕边缘时，若挪动宠物，就改变了用户放置它的位置。手的像素位置又需要和代码里的几何常数对齐，常数一旦和图不一致，牌就会脱开手。
- **决定**：
  - 小卡是独立的小窗口，和作答气泡的做法相同。牌子窗口只包住牌和杆，它的尺寸在起问时定好；位置随 ask 帧的握点移动，不因悬浮而改变。
  - 小卡只在悬浮时出现：指针停在牌或小卡上即保持展开，两者都离开后 120 ms 收起。原型是离开即收起，没有延迟；但牌与小卡之间有 10 px 的空隙，指针穿过时会先离开牌子，原型里的小卡就碰不到。120 ms 是为这道空隙留的桥，属于对原型的有意偏离。小卡窗口不收焦点，与牌子一样排除抓屏。
  - 宠物窗口不因举牌移动。牌与小卡按侧别让开空间：默认左手；左侧的外侧与内侧小卡都放不下，才换右手；两侧都放不下，取溢出少的一侧。仍然放不下时，牌子夹进屏幕内，可能与手脱开，只在屏幕窄于宠物与牌之和时发生。“屏幕” 指宠物所在屏幕的工作区，即原型里的视口，留 16 px 边距。
  - 牌子窗口逐个 ask 帧跟随手的握点移动（4 帧，约 4 Hz），不做平滑插值。
  - 手的位置从效果图量，不新增数据字段。装载时取 ask 效果图每一帧的墨迹左上角作为拳头原点；握点 x 为原点加 4.5（拳头中列），y 为原点加 3（与原型的 gripX、gripY 一致）。左右两张图各量一次。以狗为例：右手第 0 帧原点（79，48），握点（83.5，51）；左手原点（30，48），握点（34.5，51）。
- **后果**：
  - 牌子窗口每 ask 帧重定位，窗口移动次数变多（约 4 Hz）。是否在 Windows 上闪烁，要在真机上确认（visual-qa）。
  - 多一个窗口。它的生命周期跟随牌子：起问时创建或显示，作答或超时时收起。
  - 被排除的方案：窗口 mask（要经原生桥设置，验证成本高，且离屏测试不可靠）；展开时移动窗口（悬浮中不移动窗口）；挪动宠物（改变用户放置的位置）；数据里新增手的坐标字段（和效果图重复，容易不一致）。
  - 原型 `ui-prototypes/pet-review.html` 已经改成不挪舞台，与本决定一致。
