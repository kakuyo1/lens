# 0078 释义链在同一张卡内逐层下钻

- **状态**：accepted
- **背景**：读到释义里的生词时，读者想直接查它，而不是切回原文重新选词。释义是受控词汇写的，但超出词频档位的词仍会出现，需要一个在解释层面就能下钻、又不改动选区通道的办法。原型 `ui-prototypes/english-in-english.html` 场景 1 与 `chain-choices.html` 给出了几种画法，这里定下取舍。
- **决定**：
  - 下钻在同一张卡内原地换内容，卡顶给面包屑与返回键；下钻后卡顶画两条栈边，提示下面压着上一层。不另开窗口。
  - 释义里序号超过词频档位的词画点线，词表里查不到的词也画线。只有点线词可点，每次点击只为该词发一次解释请求（ADR 0060）。档位只看词频序号，不看已会标记。
  - 多义解释开着时，每一行释义都用同一套点线与下钻。
- **后果**：
  - 受控词汇要求改 prompt、schema 与缓存：下一层要有义项路标与搭配，解析与缓存都要加字段；受控释义会牺牲一点细腻。
  - 词表里查不到的词也画线，人名和拼错的词会被点开，可能查出一条不靠谱的释义。
  - 每次下钻计入每日预算。
  - 点线由档位决定，而档位到词频序号的映射（`rankForLevel`）尚未定，映射变了点线位置跟着变。链接位置不进缓存，显示时计算，换档位即生效。
  - 栈边占卡顶一截，摆放时要把它算进去。
  - 多义的每一行也要能下钻，`SenseRows` 要改成同一套渲染，改动面比单义大。
  - 点线只认英文：释义不是英文时（解释语言为 `zh` / `es` / `ja`）没有档位可以判断，本版不画点线，也就没有下钻入口。
