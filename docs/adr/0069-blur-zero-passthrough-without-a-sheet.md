# 0069 模糊为 0 且无折射时不画幕布：直通实时桌面，采集只留给文字色

- **状态**：accepted
- **背景**：读者反馈两条：雾面与流光把模糊拉到最低，卡片背景仍然很糊；帧数停在 15 次/秒，换到 RTX 4060 上也一样。
  实测把两条都归到了同一处：糊来自 `kSheetScale` 的 1/4 降采样（幕布只有设备分辨率的四分之一，再由着色器拉伸铺满），
  不是来自模糊参数本身；15 帧来自 GDI 读屏的 CPU 预算，与显卡无关，所以纯集显的机器反而觉得一样流畅
  （`docs/metrics/runtime-performance/glass-capture-capability-2026-10-19.md`，ADR 0040 末条复测）。
  而 blur=0 且折射=0 的时候，卡片要看的 “背景” 就是桌面本身：这 14 个玻璃窗口本来就是逐像素透明的顶层窗口
  （各窗口根 `color: "transparent"`），流光的 panel alpha 是 0，雾面是 40% 白 —— DWM 每帧已经把实时桌面合成好了，
  再抓一份 1/4 分辨率的画面拉伸铺上去，是花 10~25 ms 一次去把同一个东西做糊做慢。
- **决定**：
  - 规则只写一处：`qml/components/GlassRule.qml` 单例，函数 `passthrough(mode, frostedBlur, liquidBlur, liquidRefraction)`。
    雾面只看自己的模糊；流光要模糊与折射同时为 0，因为只要还在折，就得手里有桌面这张图。画的那一半
    （`GlassSurface`）与决定要不要读的那一半（`GlassHost`）都读这一个函数，两处各写一遍迟早会飘。
  - 命中时卡片不画幕布：`sheetUrl` 与 `mapUrl` 为空（不请求、不加载、不上传纹理），`ShaderEffect` 不可见；
    底色 fill、描边 rim 与圆角照旧由 `Rectangle` 画，阴影与出现动效都不变。实时桌面从窗口自己的透明处透出来。
  - `GlassHost` 关掉 live 刷新。仍然在 “系统已把这个窗口排除出抓屏” 的分支里调一次 `follow()`：幕布盖不住窗口时
    会重取一次，用途只有一个 —— 判卡片上的文字该用深档还是浅档（ADR 0035）。
  - 没有被排除出抓屏时，直通**不采集**。那条路径取图要先 `opacity = 0` 把卡片隐掉再截（ADR 0038），
    而直通时卡片正显示着实时桌面，为了取一张自己并不画的图把卡片弄空白一下，是净损失。
  - 滑条跨过 0 那一刻立即生效：`GlassHost` 监听 `passthrough` 变化重新走一次 `capture()`，不停在 Save 后面。
  - `GlassSheet.live` 升为 QML 可读属性（READ live NOTIFY liveChanged），供测试与后续档位读 “这张幕布在不在刷”。
- **后果**：
  - 文字色不再跟随卡片背后的视频。它在卡片出现时、以及窗口移动到幕布盖不住时重判一次；背后亮度剧变时可能出现
    深字压深底，靠卡片自己的 fill 垫着。这是本条明确接受的代价 —— 把它跟上去的开销正是这一档要省掉的开销
    （ADR 0040 的 15 次/秒预算没变，直通是绕开它，不是把它调快）。
  - 系统拒绝排除抓屏的机器（Windows 10 2004 之前）在直通下完全不判文字色，用色表默认的深字档。
  - 排除的代价不变：直通期间这张卡对截图与屏幕共享仍然不可见（ADR 0038 / 0041）。
  - 观感要真机核对：雾面在 blur=0 时是 40% 白压在**清晰**桌面上，模糊原本替文字垫的那层底噪没有了。
    2026-10-19 先把 qtest 跑绿，观感由读者在真机上确认。
  - 测试：`tst_phase2e` 新增 `test_blurAtZeroLetsTheLiveDesktopThrough`，断言 `passthrough` 翻转、两个 URL 变空、
    `live` 关掉、窗口不透明度不被改动。offscreen 平台不支持设窗口不透明度，那条断言在 qtest 里只覆盖 QML 侧属性，
    实际有没有闪仍要在真机上看（`TEST.md` 第 5 节）。
  - 被排除的选项：给直通单开一个开关（多一个设置项，而滑条拉到 0 已经是这个意思）；把 live 留着但不画
    （省不掉那 10~25 ms 一次，正是这条要省的）；只在流光做直通（雾面同样成立，规则按 mode 分支即可）。
