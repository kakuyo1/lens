# 0030 动作名由宠物数据给出，状态机只认产品定义的角色

- **状态**：accepted
- **背景**：桌面宠物的动作原先是一个封闭的枚举（11 个值），动作名表、加载器与待机池都写死在代码里。要接入第二只、第三只宠物，每只都要有自己的动作，且比狗多（每只不少于 11 个，外加几个只由空闲计时挑选的额外动作）。枚举只能在代码里加值，每只新宠物都要改代码。
- **决定**：
  - 状态机的词汇是 `Role`：产品定义的 11 个情形（待机、阅读、思考、庆祝、鼓励、睡觉、点击反应、拖拽、张望、打哈欠、伸懒腰）。这个集合封闭，由产品决定。
  - 动作名是宠物数据里的字符串，代码里不再有枚举或名字表。
  - 每只宠物的 `animations.json` 多两项：`roles`（角色 → 动作名，伸懒腰可以缺省）与 `idlePool`（只由空闲计时随机挑选的单次动作，可以为空）。`returnTo` 指向角色，因为阅读与睡觉这两个保持状态就是角色。
  - 事件到角色的映射仍在代码里，不进数据。读者看到的触发规则对所有宠物一致，宠物数据不能新增触发。
- **后果**：
  - 新增动作名不需要改代码；新增角色（产品层面的新情形）仍需改代码。
  - 数据错误依旧整只宠物拒绝。校验的依据从 “名字属于枚举” 变为 “名字属于本宠物”。
  - 被排除的方案：把所有额外动作名加进共享枚举。它能工作，但每只新宠物都要改代码，动作名也就属于代码而不属于美术。
  - 尚未决定：选择哪一只宠物（注册表与设置下拉框）。这需要先定显示名的本地化方式，单独做。
