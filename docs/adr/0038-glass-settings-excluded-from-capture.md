# 0038 玻璃主题期间，设置窗口排除抓屏，不再为抓屏透明

- **状态**：accepted（取代 ADR 0035 中 “抓屏前窗口透明 120 ms” 的做法，仅限支持排除抓屏的系统；其余不变。文中为异步加载设的双槽已由 ADR 0071 换成单张活纹理）
- **背景**：ADR 0035 为了不把设置窗口自己截进背景，每次抓屏前让窗口透明 120 ms。拖动结束或窗口移动后，这一次透明就是读者看到的闪烁。两次闪烁已降为一次，松手后的那一次仍在（2026-10-13 用户在真机上确认）。
- **决定**：
  - 玻璃主题开启、设置窗口显示期间，对窗口调用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`。抓屏时窗口保持不透明，抓到的是窗口背后的桌面。
  - 主题切回非玻璃，或窗口隐藏时，清除该标记（`WDA_NONE`）。
  - 系统拒绝（Windows 10 2004 之前）或窗口尚无原生句柄时，退回原来的做法：抓屏前透明 120 ms。
  - 实现：`GlassBackdrop::keepOutOfCapture` 只在 Windows 平台生效，不为清除标记而新建原生窗口。离屏平台始终走透明路径，因此离屏测试的行为不变。
- **后果**：
  - 玻璃主题开启期间，设置窗口对所有截屏与屏幕共享都不可见，包括读者自己的截图。2026-10-13 读者选择了这一代价。
  - 2026-10-13 的探针在 GDI 屏幕抓取中确认排除的窗口消失，但底图是黑的，因此透出内容未得到验证。真机上需确认玻璃里显示的是窗口背后的桌面。
  - 宠物窗口仍由 `pet` 模块排除抓屏，两者互不影响。
  - QA 反过来要它可见：设 `LENS_QA_VISIBLE_IN_CAPTURE` 后 `setExcludedFromCapture` 一律返回 false，全部
    表面（含宠物）留在截图里，`scripts/qa/ui-capture.ps1` 才有东西可拍（`TEST.md` 第 5 节）。默认不设。
    调用者那条 “系统拒绝” 的警告此时照写，紧跟在 QA 警告后面，别当成 Windows 的错。
- **第二轮（2026-10-13，真机反馈）**：排除生效后，两处仍有问题，已一并处理。
  - 滑条拖动时玻璃不断闪。原因：`GlassSurface` 的单个 `Image` 换了 `source` 后，异步加载完成前是空白的。改为两个 `Image` 轮换：新图加载进隐藏的那个，就绪后再切换，屏幕上的那张从不被重新加载。`tst_phase2e` 的 `test_glassStaysOnScreenWhileItsBlurLoads` 检查这一点。
  - 拖动卡片时玻璃要等松手才变。原因：只在松手和移动结束时抓屏。窗口已排除抓屏，因此拖动时窗口背后的幕布随之移动，只在靠近幕布边缘时重抓（见 ADR 0039；此前的 “每 100 ms 重抓” 已被取代，它仍有 100 ms 的延迟）。未排除（回退路径）时不这样做，因为每次抓屏都会让卡片透明。
  - 切换排除状态时写一条日志（`glass_backdrop.cpp`），系统拒绝时写警告，便于确认当前走哪条路径。
