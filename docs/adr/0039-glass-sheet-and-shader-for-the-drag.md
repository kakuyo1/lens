# 0039 玻璃取一张比窗口大的桌面“幕布”，拖动时由着色器逐帧定位、折射并切圆角

- **状态**：accepted（取代 ADR 0037 中“QML 只显示 C++ 处理好的图像”的部分；模糊与饱和已移到着色器、幕布回到原生分辨率，见 ADR 0070；幕布在拖动之外的定期刷新由 ADR 0040 补充）
- **背景**：ADR 0037 让 C++ 每次参数变化或抓屏都输出一张处理好的玻璃图。拖动窗口时，每次更新都要抓屏、模糊、再异步加载，玻璃比卡片慢一到两帧，拖动越快错位越明显。桌面在拖动中没有变化，变的只是窗口的位置，所以不必为每一帧重抓。
- **决定**：
  - 抓屏改为一张幕布：窗口四周各多抓 160 DIP，并裁到所在屏幕内。C++ 在抓屏时做一次模糊与饱和（`blurredPicture`），幕布本身不带圆角，也不做折射。
  - 窗口移到离幕布边缘不足 72 DIP 的位置时才重抓（`GlassBackdrop::follow`、`covers`），拖动期间抓屏次数很少。幕布边缘若在屏幕边缘上，该侧不需要余量。
  - `shaders/glass.frag` 每帧做三件事：按窗口在幕布中的位置取样；液体主题用位移图偏移采样；用带符号距离切卡片圆角。位置由 `GlassSurface` 中窗口的 `x`、`y` 绑定给出，拖动时不必调用 C++。
  - 幕布与位移图各用两个槽位轮换，新图就绪后才切换，屏幕上的一张从不被重新加载（同 ADR 0037 的“双缓冲”，本次新增幕布的部分）。
  - 位移图仍由 C++ 按卡片尺寸生成并缓存。
- **后果**：
  - 恢复了 `qsb` 与一个着色器（`glass.frag`），ADR 0037 中“不再依赖 `qsb`”的前提失效。着色器的运行时编译在离屏平台不可见（离屏不渲染，`ShaderEffect` 停在 Uninitialized），只能在真机上确认。运行日志中若出现 QML 警告，说明编译失败。
  - 玻璃主题开启期间，设置窗口仍对截屏隐藏（ADR 0038）。幕布取的是窗口背后的桌面，不含窗口本身。
  - 幕布比窗口大，每次重抓要模糊约 1.2 MP 的图（DPR 1.25 时），在工作线程上约 40 ms。重抓之前，旧幕布仍覆盖窗口，所以不出现空白。
  - 模糊超过 100% 的 3σ 时，幕布边缘的模糊会有误差。默认 10% 时没有影响。
  - 角与折射的几何不再有 C++ 单元测试，由着色器与真机观感覆盖。`GlassMath` 的 gtest 只覆盖模糊、饱和与位移图。
