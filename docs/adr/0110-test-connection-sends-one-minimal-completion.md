# 0110 测试连接发一条最小补全

- **状态**：accepted
- **背景**：Lens 是 BYOK 产品，key、地址或模型任何一处不对，都要等到第一次取词失败才暴露。设置里已有保存状态，但没有一个能主动验证整条连接的动作；`GET /models` 只能验证地址与 key，验证不了模型本身，而有些兼容端点并不提供这个接口。
- **决定**：API 配置页提供 “Test connection”。它发一条非流式、`max_tokens` 为 1 的 `chat/completions`，内容只有 `ping`，让服务在同一请求里检查地址、key 与模型。结果只使用固定句（成功、key 被拒、地址或模型不存在、无法到达、200 但不是模型响应），不转发传输层原话，也不回显 key。一次只允许一条探针在飞；key、地址或模型改变会撤掉旧结果，旧探针的答案只用来释放按钮，不显示在新配置旁。
- **后果**：探针不是免费的，但只花一条最小请求的量；这是第一次取词失败之外的已知小额成本。服务若拒绝 `max_tokens: 1` 或要求供应商特有字段，探针可能误报，供应商的 `requestOverrides` 会随请求一起带上以降低这种风险。固定句比传输层原话粗，代理证书错误也只会显示 “无法到达”，但换来的是 key 与地址细节不会从错误路径漏出。不做自动重试：读者按下一次，得到一次答案。
