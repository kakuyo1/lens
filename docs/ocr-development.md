> 日期：2026-10-28。代码核对基点：`dbc7c81`。
> 状态：目标方案已获批准；A–F 已部分实现，逐阶段真实/替身/未验证证据见 §17 与
> [OCR 基线与接入验证](metrics/ocr-baseline-2026-10-28.md)。本文其余章节仍是目标契约，不因代码存在而自动成为已验证能力。
> 取舍记录：[ADR 0130](adr/0130-local-and-online-ocr-are-separate-modes.md)、[ADR 0133](adr/0133-offline-ocr-ships-tesseract-and-rapidocr.md)。

## 1 目标、范围与交付边界

本次要解决的是 “读者能选择适合自己的 OCR，并明确知道截图是否出站”，不是把 Lens 扩成通用 OCR 工作台。

产品默认值与回退边界由 [PRODUCT.md 的 OCR 约定](../PRODUCT.md#ocr-约定2026-10-28-部分交付)拥有；出站与凭据规则由 [SECURITY.md 的 OCR 安全约定](../SECURITY.md#ocr-security-contract-implementation-in-progress)拥有。本文定义如何实现和验证这些约定。

### 1.1 首轮交付

| 能力 | 交付内容 |
|---|---|
| 本地自动选择 | 使用随包 Tesseract |
| 本地明确选择 | Tesseract 与通过适配验收的 RapidOCR-json |
| 安装包 | 继续随包带 Tesseract 及英文数据；不捆绑 RapidOCR、PaddleOCR 或它们的模型 |
| 可选引擎 | 优先验证 RapidOCR-json；PaddleOCR-json 保留为下一适配项，不假装两者任意版本通用 |
| 在线识别 | 独立配置，用户主动框选后确认上传，仅接入一个经过核实的协议 |
| 结果契约 | 文本、可选版面、可选置信度、实际后端、语言与运行诊断 |
| 设置界面 | 模式、引擎、语言、路径或端点、独立凭据、检测结果与实际使用状态 |
| 安全验证 | 未授权零上传、扫描零在线调用、无内容日志、密钥隔离、取消与过期结果丢弃 |

### 1.2 不随首轮交付

- 不做引擎商店、插件脚本、自动下载模型。
- 不做云端自动扫描、字幕模式、UI Automation。
- 不做多引擎并行投票、基于置信度的自动付费重试。
- 不做完整 OCR 编辑器、批量图片、PDF、表格恢复、手写识别专项。
- 不把点词高亮、扫描行级差分、纠词和校对条绑进多引擎上线条件；这些是后续独立迭代。
- 不改解释模型、解释语言、现有词表判定和解释缓存的语义。

## 2 当前实现与必须改变的地方

以下是代码事实，不是将来的默认值。

| 当前位置 | 当前行为 | 本方案要求的变化 |
|---|---|---|
| `src/capture/ocr_engine.h` | `OcrResult` 只有状态与文本；`OcrEngine` 提供阻塞识别与探测 | 引入结构化结果、能力与有界执行契约 |
| `src/capture/ocr_engine.cpp` | 每次启动 Tesseract，PNG 经 stdin，固定 PSM 3，语言由数据目录决定 | 保留隔离进程，增加 TSV 与按输入形态的参数策略 |
| `src/capture/scan_pipeline.cpp` | 归一化文本连续三次相同；稳定且像素未变时不再 OCR；已有冷却 | 首轮保留稳定规则，只替换输入结果来源 |
| `src/app/duties/capture_duty.cpp` | 截图与扫描共用单任务和 Tesseract 状态；detached worker、25 ms 轮询 | 分开截图／扫描可用性，统一任务所有权，增加上传确认前状态 |
| `src/app/app_controller.cpp` | 设置投影含 Tesseract 状态；截图热键先查全局 OCR 状态 | 按来源与当前模式检查就绪状态，不能由 Tesseract 不可用禁用在线截图 |
| `src/core/domain/settings_table.h` | 只有 Tesseract 两个路径；同步为显式白名单 | 增加本机 OCR 设置，凭据不进入普通设置表 |
| `src/app/qml/settings/pages/SettingsCapturePage.qml` | Tesseract 路径直接放在取词页 | 改为 OCR 配置子页面，首屏保留就绪／失败摘要 |
| `src/app/qml/capture/Mask.qml` | 蒙版隐藏后等待 120 ms 抓取选区，识别后直接翻译 | 保留抓屏约束，在线路径在抓取后增加上传确认 |
| `installer/stage_ocr.cmake` | 复制英文 traineddata、exe、DLL，不复制 TSV 配置文件 | 从安装产物验证 TSV，不依赖开发机额外文件 |
| `src/llm/llm_client.cpp` | 解释专用 Qt 网络请求、独立响应协议 | 只参考传输习惯，不把 OCR 请求塞入解释客户端 |

当前扫描不会每秒无条件堆积识别任务；空白已折叠，稳定与冷却也并非空白。扫描实体目前只计数提示，不发实体解释请求。不要以调研中这几项过度概括作为重写依据。

## 3 模式、语言与路由

### 3.1 两个独立配置轴

`ocrMode` 决定手动截图走本地还是在线；`ocrLocalEngine` 决定本地路径的引擎。自动扫描始终只读本地配置，不因手动截图选择在线而暂停或改成在线。

保留 `ocrCapture` 与 `autoScan` 两个现有开关，缺省仍关闭。默认引擎策略不等于默认开启截图或扫描。

| 请求来源 | 模式 | 实际选择 | 失败处理 |
|---|---|---|---|
| 手动截图 | 本地 | `ocrLocalEngine` | 按本地回退表处理 |
| 手动截图 | 在线 | 当前在线配置 | 固定错误；用户可重新发起本地截图，不自动改模式 |
| 自动扫描 | 任意 | `ocrLocalEngine` | 本地错误或暂停；绝不创建上传请求 |
| 本地检测 | 任意 | 被检测的本地引擎 | 不改当前引擎，不读真实桌面 |
| 在线检测 | 任意 | 当前在线配置 | 显式提交合成样图，不改当前模式 |

### 3.2 本地自动与明确选择

自动策略只使用 Tesseract，不因为目录中发现 RapidOCR／PaddleOCR 就擅自运行。

| 本地结果 | 自动策略 | 明确选择 |
|---|---|---|
| 资源缺失、语言缺失、启动失败 | 报告不可用，不换引擎 | 报告原因，不回退 |
| 运行失败或到时限 | 返回错误，不自动换引擎 | 报告错误 |
| 成功但无文字 | 返回无文字 | 返回无文字 |
| 用户取消、配置改变、请求过期 | 结束整次请求 | 同左 |

明确选择 Tesseract 或可选引擎也不静默回退。路径未配置、运行程序消失或模型失效时，保留用户选择并显示不可用，不能悄悄写回自动。

结果同时记录 `requestedEngine` 与 `actualEngine`；界面可显示实际后端。

### 3.3 识别语言独立于解释语言

识别语言回答 “图里写的是什么语言”；解释语言回答 “解释用什么语言”。两者不联动，切换中文界面也不改变 OCR 语言。

首轮本地语言选项为 `en`、`zh-Hans` 与 `zh-Hans+en`，分别代表英语、简体中文和中英混排。新配置缺省 `en`；不提供未经证明的 “自动识别全部语言”。

- Tesseract：英语用 `eng`，简体中文用 `chi_sim`；混排用 `chi_sim+eng` 并要求两份模型可读。显式选择一种语言而资源不齐时报告缺失，不把中文静默丢掉。
- 可选引擎：语言能力由已验证的模型组合决定；没有证据不声明可识别某语言。
- 在线：仅列所选服务与所选档位已支持的语言，使用独立 `ocrOnlineLanguage`；不沿用本地语言枚举假定能力相同。

不使用 “先以 eng 识别，再根据输出中文占比选择中文模型” 的规则：首次识别可能已经丢失中文。

### 3.4 旧配置迁移

首次发现尚无 `ocrConfigVersion` 的旧配置时，只做本机迁移，不启动网络：

1. Tesseract 路径非空的旧用户保留明确 Tesseract 选择，避免升级后绕过用户安装的引擎。
2. 数据目录含中文与英文模型时迁移到混排；仅中文数据时保留原中文能力作为迁移状态，提示补充英文数据后再切混排，不覆写路径。
3. 未自定义路径、仅使用随包英文的用户采用本地自动策略。
4. 在线模式一律不从历史解释服务配置推导；不复制解释 API key、端点或模型。
5. 迁移完成后写入版本；已迁移配置不再按磁盘上的文件猜测用户意图。

仅中文旧配置的迁移状态应由明确的 `zh-Hans` 语言值表达，设置页可选择中文；不是在运行时通过隐藏分支假装混排。新安装的缺省与常用项仍为英语 / 中英混排。

## 4 模块设计与依赖

### 4.1 数据流

```text
手动热键 → 蒙版 → 原始选区图像
                    ├─ 本地 → 本地路由 → 本地后端
                    └─ 在线 → 上传确认 → 在线后端
                                      ↓
                               统一 OCR 结果
                                      ↓
                           本地分类 → 现有解释通道

白名单前台窗口 → 本地采样／稳定门 → 本地路由 → 本地后端
                                              ↓
                                      本地过滤 → 单词解释
```

本地后端与在线后端共享结果类型，不共享可以被扫描任意调用的上传入口。扫描模块不接收在线客户端或上传授权对象。

### 4.2 职责分配

| 模块 | Interface 与职责 | 不应知道 |
|---|---|---|
| OCR 结果 | 数据类型、坐标、能力、状态 | QML、屏幕、配置文件、HTTP |
| 本地 OCR | 检测本地资源，按语言识别，取消、清理 | 在线凭据、上传授权、解释模型 |
| 本地路由 | 在既定两级自动策略中选择 Adapter | UI 文案、模型下载、图像内容出站 |
| 在线 OCR | 对已授权的选区执行一个固定协议，解析结果 | 扫描窗口、解释队列、其他服务商 |
| OCR 执行器 | 任务排程、截止时间、资源生命周期、结果投递 | 翻译含义、词表判定 |
| CaptureDuty | 来源准入、冻结配置、确认事务、过期判定、后续分类 | 各引擎原始 JSON／TSV 细节 |
| ScanPipeline | 本地快照稳定、冷却、候选产生 | 系统语言包、HTTP、QML |
| 设置页面 | 配置编辑、状态、明确动作 | 密钥读取、引擎进程管理 |

建议本地实现留在 `src/capture/`；在线实现置于新增的 `src/ocr/` 目录，建立 `lens_ocr` target，依赖 `lens_capture` 的结果类型与 Qt Network，由 `lens_app` 组装。`lens_capture` 不增加 Qt Network 依赖，以依赖方向约束扫描不能触网。

不要为各后端再造一套完整管道。纯解析、坐标还原、路由判定是确定性逻辑；WinRT、子进程、HTTP 是实际变化的 Adapter，适合在这些 Seam 注入测试替身。所有工厂由生产或测试的组装入口调用，不从全局单例查找。

### 4.3 执行 Interface

面向调用方使用异步任务，而不是让 GUI 调用阻塞识别。Interface 的语义如下；名字为拟新增符号，不表示仓库已经存在。

| 操作 | 输入 | 输出与保证 |
|---|---|---|
| `inspectLocal` | 本地引擎配置、语言 | 可用性、能力、资源缺失原因；普通枚举不运行外部程序 |
| `testLocal` | 显式信任后的本地配置 | 对合成图的实际识别结果；可启动一个用户程序 |
| `startLocal` | 本地请求、配置快照 | 一个任务句柄；只有本地副作用 |
| `startOnline` | 手动选区或显式合成检测请求、不可复用的上传授权 | 一个任务句柄；拒绝扫描来源，测试授权只接受内置合成图 |
| `cancel` | 任务句柄 | 幂等取消；是否已出站与是否已清理分别报告 |
| `finished` | 任务标识、结果 | 每次接纳的请求最多投递一次终态；过期结果不得进入消费者 |

C++ 使用数据 struct 表达配置与结果，行为由小型抽象 Interface 承担，具体 Adapter 放在实现文件。C++20 不直接采用 C++23 的 `std::expected`；结果使用具名状态与载荷，或项目已有可用的等价表示，不为这次开发升级语言标准。

## 5 统一输入、输出与坐标契约

### 5.1 输入

| 字段 | 含义 |
|---|---|
| `requestId` | 进程内单调生成的标识，不包含窗口标题、文本或用户 ID |
| `source` | 手动截图、自动扫描、本地检测、在线检测之一 |
| `image` | 原始裁剪后的 QImage；只包含选区，不引用全屏图的可见范围外数据 |
| `language` | 已解析的 OCR 语言策略 |
| `layoutHint` | 未知、单词、单行、文本块、稀疏窗口；不是从高度一个条件武断判定 |
| `generation` | 截图或扫描代次，用于丢弃过期结果 |
| `configRevision` | 已冻结的配置版本；不以“完成时的新设置”处理旧结果 |
| `deadline` | 单调时钟截止时间，覆盖排程后预处理、识别与回退 |

屏幕原点、monitor、DPR 与气泡锚点由 CaptureDuty 的请求上下文持有，不交给在线服务；窗口名称、进程名、屏幕编号也不进入请求体。

### 5.2 输出

| 类型／字段 | 契约 |
|---|---|
| `status` | 成功、无文字、取消、不可用、超时、输入无效、传输失败或协议失败等枚举 |
| `text` | 完整本地识别结果；无效／失败结果不附带可供自动翻译的半截文本 |
| `lines` | 有行结构才填写；无版面不伪造整图大框 |
| 行的 `text`／`box`／`words` | 行文本、可缺失矩形、可缺失词级列表；框层级必须说明 |
| 词的 `text`／`box` | 引擎真实返回的词，不通过按字符均分矩形制造词框 |
| `confidence` | 可缺失的 0 到 1 数值；只表示该后端自身分数，不代表跨引擎概率 |
| `actualEngine`／`languageUsed` | 本次真正运行的后端及语言 |
| `geometryLevel` | 无、行、词；不能由“有任意框”推断为词框 |
| `timing` | 排程、预处理、识别、总耗时；从单调时钟获得 |
| `attempts` | 最多两次本地尝试的枚举结果和耗时，不附原始错误正文 |
| `uploadState` | 未上传、已开始上传、服务结果已返回；取消不把它改回未上传 |

成功意味着文本非空且有效；无文字单独表示。置信度缺失用可选值，不用 `-1`，更不能填 `1` 伪装高可信。若提供平均分，应标明参与统计的词数与覆盖率；无词分数时不生成行均值。

不同后端的行 / 词粒度不同，尤其中文不能假定空格等于词界。外部文本只作纯文本，不解析 HTML，不执行其中的路径、URL 或指令。

### 5.3 坐标

所有公开框归一到 “本次原始裁剪图像的物理像素坐标”，左上为原点，保留浮点精度；范围必须有限、非负、落在图像范围内。几何非法时报告协议问题，不绘制异常大框。

Adapter 内部负责逆变换：去掉白边偏移，再撤销缩放、旋转与二次裁剪；调用方只负责原图到屏幕的映射，不知道后端预处理细节。只有首次点词功能落地时才消费屏幕词框，不提前扩展屏幕 UI。

Tesseract TSV 的行框由真实词框并集得到；RapidOCR 的文本块多边形不能标成逐词框。保留后端阅读顺序，不对整页简单按 y 排序而打乱多栏。

### 5.4 限额

以下数值是首版实现预算，不是服务商性能承诺；只能在有测量证据与文档更新后调整。

| 对象 | 首版上限 |
|---|---|
| 原始图像 | 边长 8192 px，QImage 内存 128 MiB；同时检查后端自身更低的限制 |
| 预处理图像 | 仍受同样内存与边长限制，放大前用宽类型计算，不在分配后检查 |
| 识别文本 | 65536 个 UTF-16 代码单元，拒绝无效 Unicode 与嵌入 NUL |
| 结构化输出 | 4 MiB，最多 2000 行、20000 个词／块，JSON 嵌套深度最多 16 |
| 子进程 stderr | 64 KiB；不因超额日志继续无限积累 |
| 本地单次任务 | 总时限 10 秒；两级回退共享该时限 |
| 在线单次任务 | 从确认提交起总时限 30 秒，不随分片到达重置 |
| OCR 并发 | 实际识别最多 1 个；最多暂存 1 个手动请求，扫描不排队 |
| 云端自动重试 | 0 次；用户明确重试最多再发 1 次，然后必须重新框选 |

文本业务长度继续由本地分类入口控制，但超过可消费长度时应先说明，不把前 1000 个代码单元静默翻译成 “完整截图结果”。此处截断行为属于截图改造的验收项，不影响原生选区既有语义。

## 6 本地后端实现

### 6.1 Tesseract

继续采用随包可执行文件或用户选定的绝对路径；不依赖 PATH 搜索。运行时必须独立自足，不能从开发环境借 DLL 或 traineddata。

- 保持 PNG stdin，不把识别内容写入命令行或中间图片文件。
- 输出改为 TSV，参数优先使用明确的 `tessedit_create_tsv` 配置变量，或分发确实需要的 TSV 配置文件；二者选一种后由安装产物测试锁定。
- TSV 按 level 与页 / 块 / 段 / 行组合键归组，词框来自 level 5。非词层的负分不参与置信度；词分数除以 100 映射到统一范围。
- 解析时严格检查列数、数值范围、总行数和字符编码，不用不受限的 split 制造大规模分配。
- PSM 先保留当前基线；在有输入形态依据时选单行 7、单词 8、文本块 6、稀疏 11。不能以 “高度小于 40 px” 跨 DPI 通用判单行。
- 缩放、灰度、反色、白边均作为独立实验因子；只落地可重复改善目标语料的组合。修改 DPI 元数据不等于增加像素信息。
- 使用可取消的有界进程；关闭 stdin、排空输出、超时终止和 wait 清理都计入资源生命周期。

### 6.2 用户安装的 RapidOCR／PaddleOCR

它们不是任意路径指向一个 exe 就能互换的同一种产品。Lens 只支持明确的发行物、协议与模型组合，不承诺兼容 Python 包、所有 ONNX 模型或任意命令行封装。

首轮候选的精确协议与验证门见第 7 节。未通过验收的候选可在文档列出，但不出现在已发布 UI 的可选择列表中。

执行安全要求：

- 程序由用户自行下载；Lens 不运行 pip、安装脚本或下载命令。
- 第一次 “检测并运行” 前说明这是第三方可执行代码，不是像宠物包那样的纯数据。
- 程序路径必须是本机绝对文件路径，不接受 URL、UNC、命令串、`.bat` / `.cmd` ／PowerShell 脚本；参数由 Adapter 生成，不经 shell 展开。
- 工作目录固定为该发行物要求的目录；不让当前文章、图片或服务器响应控制 cwd、参数或模型路径。
- 首轮采用独立子进程且每次任务后退出，不在尚无资源测量时默认常驻。扫描选用该后端时，实际采样服从处理速度，不堆积待识别帧。
- 不把用户模型目录改写成 Lens 的版本；依赖缺失返回固定状态。
- 正常使用不自动对未知程序做 probe；显式检测成功后记录信任的路径及文件摘要。可执行文件或模型配置改变，撤销就绪状态并重新确认。
- 这不是沙箱：第三方程序拥有当前用户权限，Lens 无法保证它不联网或不读取其他文件，必须在设置中说明。

## 7 第一批外部协议适配

以下是依据公开文档与源码选定的首批技术验证目标，不表示已通过二进制安全审计或 Lens 集成测试。增加服务商是增加内置 Adapter，不是让用户填写任意脚本、请求模板或响应 JSON 路径。

### 7.1 RapidOCR-json v0.2.0

验证目标为 `hiroi-sora/RapidOCR-json` v0.2.0 发行物。该版本发布于 2023-09-25，属于旧发行物；选择它是因为协议可查、Umi-OCR 有实际适配，不代表推荐忽略其依赖维护风险。实现前须审核 DLL、模型许可与已知漏洞，不能仅凭 OCR 能运行就批准分发或使用。

- Windows 发行包为 `RapidOCR-json_v0.2.0.7z`，发布元数据大小 73,461,693 字节；这是下载包大小，不是解压内存或 Lens 安装包增量。
- 程序文件名由用户选择，文档出现过横线 / 下划线两种拼法，不把猜测的 basename 当作验证依据。
- 使用 `--models` 指定模型目录，`--det`、`--cls`、`--rec`、`--keys` 指定已验证的组合；首版只接受随验证发行物的完整标准组合，不做任意模型结构推断。
- 不传 `--image_path`，以管道模式启动；等到 stdout 的 `OCR init completed.` 后发送一行 JSON。启动序言计入输出上限，不能无限等待。
- 请求用 `image_base64` 字段，值是 PNG 编码字节的裸 base64，不带 data URI 前缀。以换行结束，禁止在命令行传图片内容。
- `--ensureAscii=1` 让输出转义非 ASCII 字符；解析后恢复 Unicode，不把 Unicode 转义当原始单词。

请求形状如下，其中占位内容只表示图片字节，不是可执行示例：

```json
{"image_base64":"<base64-encoded-png-bytes>"}
```

响应 `code=100` 为成功，`data` 是文本块数组，每块含 `text`、`box` 与 `score`；`box` 是左上、右上、右下、左下四点。`score` 是该块的字符分数平均，不提供逐词分数。`code=101` 为无文字，其他值转固定错误；不要把 `data` 的错误字符串当识别结果。

四边形只映射为文本块 / 行级区域；不按空格分词并均分矩形伪造词框。旋转信息在 Adapter 内保留到坐标变换完成，向当前消费者给出轴对齐包围框并明确几何层级。

该版本未提供退出命令，也没有可靠的 stdin EOF 退出处理。首轮采用 “一次任务一个进程”：得到结果或发生取消后，由 Lens 终止并等待自己创建的进程，不能发送 Paddle 的 `exit` 并假定 Rapid 会退出。将来改为持久 worker，需要另测队列、崩溃恢复、内存与关机，不在首轮自动开启。

来源：[版本 README](https://github.com/hiroi-sora/RapidOCR-json/blob/v0.2.0/README.md)、[主程序](https://github.com/hiroi-sora/RapidOCR-json/blob/v0.2.0/cpp/src/main.cpp)、[发行页](https://github.com/hiroi-sora/RapidOCR-json/releases/tag/v0.2.0)。

2026-10-28 实测：`image_base64` 在 README、Python 示例与 C++ 解析中一致；`code=100/101/205`、四点框、块级 score 与 `OCR init completed.` 均已确认。关闭 stdin 后进程不会退出，1.5 秒内输出约 851,967 行错误，必须由 Lens 终止并等待；模型目录含中文时进程以 `0xC0000409` 在初始化前崩溃。D 的非 ASCII 路径完成条件因此未通过，适配器与 UI 均未交付；完整数据与待选方案见[基线证据](metrics/ocr-baseline-2026-10-28.md#3-rapidocr-json-v020-审计)。

### 7.2 PaddleOCR-json 后续适配

可核查的候选是 v1.4.1 Windows x64 包。它与 RapidOCR-json 的基础输入 / 结果相似，但模型配置、错误码和退出规则不同；Paddle 接受 `exit` 或带 exit 的 JSON，不能据此设计共同的通用 worker 退出命令。

Paddle 暂不作为首版已发布选项。需要时单独实现 Adapter，复用结果验证和排程，不复制一套设置 / 授权 / 扫描管道。版本依据：[发行页](https://github.com/hiroi-sora/PaddleOCR-json/releases/tag/v1.4.1)。

### 7.3 在线服务表

在线识别按服务登记，一家一个 Adapter。表在 `src/ocr/online_providers.cpp`，设置页、配置检查与工厂读同一张表；没有 Adapter 的服务不能入表，工厂对未知协议返回空，不猜一种兼容。新增一家是协议枚举值、Adapter 文件、表行与工厂分支四件事，设置页与 CaptureDuty 不改（[ADR 0136](adr/0136-online-ocr-is-a-provider-table.md)）。

| 服务 id | 名称 | 默认地址 | 凭据槽 | 语言映射 | 状态 |
|---|---|---|---|---|---|
| `baidu` | 百度通用文字识别 | `https://aip.baidubce.com/rest/2.0/ocr/v1/general_basic` | `apiKey`、`secretKey` | `eng`→`ENG`，`auto`→`CHN_ENG` | 已实现，真实往返未验证 |
| `ocrspace` | OCR.space | `https://api.ocr.space/parse/image` | `apiKey` | `eng`→`eng`，`auto`→`auto` | 已实现，真实往返未验证 |

腾讯云、阿里云与 Google Vision 需要各自的请求签名或异步轮询，表项与 Adapter 同时加入，不预先列出无法调用的服务。

端点留空表示服务默认地址，非空是读者的显式覆盖；切换服务会清空地址与全部凭据，不把一家服务的密钥发到另一家的协议上。凭据写入 `OCR-API-KEY` 与 `OCR-SECRET-KEY` 两个固定键，与解释凭据独立。存储语言只有 `eng` 与 `auto` 两个值，`auto` 表示 “服务自己的多语言设置”，含义由各 Adapter 映射，不是 Lens 的自动检测承诺。

#### 7.3.1 OCR.space

首轮用它验证图片授权和几何结果：专用 OCR 接口，参数比视觉模型对话接口更窄。此选择不要求用户购买特定套餐，不宣称服务内部一定不用 VLM，也不宣称其他云 OCR 与其兼容。

协议依据：[OCR.space 官方 API 文档](https://ocr.space/ocrapi)，核对日期 2026-10-28；网站页脚版本号不是 API 协议版本。

| 请求项 | 首轮取值 |
|---|---|
| 方法与官方端点 | POST `https://api.ocr.space/parse/image` |
| 鉴权 | `apikey` 请求头；不放 query 或 multipart 文本字段 |
| 内容类型 | multipart/form-data，由 Qt 构造 boundary |
| 图片字段 | `file`，内存 PNG，固定中性文件名 `capture.png` |
| OCR 引擎 | `OCREngine=2`；不使用已退役的 Engine 1 |
| 版面 | `isOverlayRequired=true` |
| 语言 | 显式英语 `eng` 与服务端 `auto`，其他语言必须先核对协议枚举和样图 |
| 非必要功能 | 不请求可搜索 PDF，不上传远程图片 URL，不请求翻译 |
| 模型名 | 无；设置页不显示模型输入框 |

官方还支持 URL 和 `base64Image`，Lens 不启用，减少额外下载链和 base64 请求膨胀。上传 PNG 字节数硬限 950,000 字节，保守低于文档的免费 1 MB 单文件限制；超过时在上传前拒绝并提示缩小选区，不通过有损压缩偷偷改变可读内容。

服务档位可能有不同限制。免费额度、每日 IP 限流和套餐大小不能被 Lens 写成永久保证；本地次数限制不代替服务商计费。端点的自定义覆盖只表示读者填写了一个兼容 OCR.space 请求与响应的 HTTPS 地址，不会自动兼容其他服务；它同样经过端点展示与凭据重新绑定。

成功处理需要同时检查：

- HTTP 成功，响应为可解析 JSON。
- `OCRExitCode=1`、`IsErroredOnProcessing=false`，单张 PNG 恰有一个成功的 ParsedResult。
- 逐项 `FileParseExitCode=1`；字段在文档示例中可能是整数或整数串，只兼容严格的整数串，不进行任意类型猜测。
- `ParsedText` 为字符串；若空，返回无文字。`OCRExitCode=2` 的部分结果不可直接翻译，整次返回部分识别错误。
- `TextOverlay.Lines[].Words[]` 中读取 `WordText`、`Left`、`Top`、`Width`、`Height`，并验证原始图片坐标；行框为词框并集。
- 该协议没有可依据的置信度字段，统一返回缺失；若文本有效但 overlay 缺失，允许纯文本成功，不开放词框交互。

顶层错误码 3／4、逐项负错误码、HTTP 401／403／429 和传输超时分别映射，不显示 `ErrorMessage` / `ErrorDetails` 原文。明确的字段类型错误、几何越界或超限响应属于协议失败，不能静默当成功。

连接检测采用应用生成的纯文本样图，复用同一 POST 路径并显式告知可能计费；不能用一个 GET 或纯文本 ping 宣称图片 OCR 已验证。样图答案由本地固定数据判定，测试不读取当前屏幕，也不使用用户上一张截图。

#### 7.3.2 百度通用文字识别

协议依据：[百度通用文字识别文档](https://ai.baidu.com/ai-doc/OCR/zk3h7xz52)，核对日期 2026-10-29。百度把鉴权分成两步，Lens 必须自己换取并缓存令牌。

| 请求项 | 取值 |
|---|---|
| 令牌端点 | POST `https://aip.baidubce.com/oauth/2.0/token`，`application/x-www-form-urlencoded`，字段 `grant_type=client_credentials`、`client_id`（API Key）、`client_secret`（Secret Key） |
| 识别端点 | POST `https://aip.baidubce.com/rest/2.0/ocr/v1/general_basic?access_token=…` |
| 内容类型 | `application/x-www-form-urlencoded` |
| 图片字段 | `image`，PNG 的 base64 再整体百分号编码 |
| 语言 | `language_type=ENG` 或 `CHN_ENG` |
| 上限 | base64 后 ≤ 4,000,000 字节；最长边 ≤ 4096 px，最短边 ≥ 15 px；超限在上传前拒绝 |
| 令牌寿命 | 按响应的 `expires_in` 缓存，提前 60 秒失效；只存内存 |

令牌只存进程内存，日志只记状态码与响应字节数，不记令牌、密钥或响应正文。凭据、地址或服务改变即清空缓存；令牌被 401／403 拒绝时丢弃，下一次显式请求重新交换，不自动重试。

成功响应要求 `words_result` 为数组，若带 `words_result_num` 必须与数组长度一致；每项读取 `words`，存在 `location` 时再读 `left`、`top`、`width`、`height`，坐标必须落在原裁剪图内。百度给的是行框，结果 `geometryLevel` 为行；服务省略 `location` 时按纯文本成功，`geometryLevel` 为无（2026-10-29 实测单行答案不带坐标），`location` 存在但格式错误或越界仍属协议失败。`error_code` 按固定集合映射：`216201` 为图片无效，`216202`、`216203`、`216205` 为超出大小，其余（含 `17`、`18`、`19`、`110`、`111`、`282000`）为识别失败；`error_msg` 不进界面，也不进日志正文，错误码写入日志。

## 8 在线上传事务与生命周期

### 8.1 冻结一次用户意图

上传确认绑定一个内存事务，包含原始选区图、精确目标端点、服务商、冻结的凭据与语言、配置版本与请求代次。确认时不重新抓屏，不临时读取另一端点、另一服务或另一组凭据。

每次在线截图都确认，不提供 “以后不再询问”。授权不能从选择在线模式、连接检测、上一次截图或本地失败推导。

事务从取得裁剪图起最多存活 120 秒，包含首次确认、请求、清理与重试决定；这是原图在 Lens 内存中的绝对留存上限。首次确认另限 60 秒；一次可重试请求失败后，只有在底层已清理且仍有事务时间时，才可进入最长 30 秒的重试确认。第二次请求使用新的 requestId 与单次授权，但沿用原图、配置和事务绝对截止时间；每次 HTTP 时限取 30 秒与事务剩余时间的较小值。

确认画面说明两段独立出站：

1. 选区像素将发给 OCR 服务；图中敏感内容可能可见。
2. 识别成功后，必要文字将按现有通道发给解释服务。

如果后续解释配置在等待 OCR 时改变，旧事务不得自动把文本发给新服务；使该事务失效并提示重新发起。用户取消意味着不继续解释，但已开始的上传可能仍由服务商处理和计费。

### 8.2 状态机

| 状态 | 可以做什么 | 退出条件 |
|---|---|---|
| Idle | 接受来源明确的新请求 | 用户触发或本地扫描 |
| Selecting | 蒙版框选；尚无上传 | 取消，或得到非空选区 |
| Captured | 只持有裁剪图，冻结配置 | 本地直接排程；在线进入确认 |
| AwaitingConsent | 显示预览与端点；网络计数必须为零 | 确认、取消、60 秒过期或配置改变 |
| RunningLocal | 本地后端执行 | 成功、无文字、失败或取消 |
| Uploading | 已发送部分或全部请求体 | 成功、失败、超时或取消 |
| Receiving | 校验完整响应，不能提前翻译部分结果 | 完整成功或协议失败 |
| Consuming | 校验代次与解释配置后，本地分类并提交解释 | 交付后释放 OCR 事务 |
| Cleaning | 取消或单次尝试失败后的网络／进程收束 | 可重试且未取消／过期时进入 AwaitingRetry，否则进入 Finished |
| AwaitingRetry | 仅保留原图、配置和固定错误；新的网络次数为零 | 用户确认后再次排程；取消、30 秒或事务到期时进入 Finished |
| Finished | 整个事务终态，不能再次发送或重复投递 | 清理原图与预览引用 |

仅传输中断、单次请求超时或明确的服务暂时错误允许一次人工重试；鉴权、输入、协议、取消、配置变化与事务到期均直接终结。重试不是自动状态转移，旧原始响应与失败任务资源必须先释放。

Waiting 与 Cleaning 不是可无限积累的队列。手动请求优先于扫描；扫描忙时丢帧。在线确认显示期间暂停新的扫描任务；关闭确认后恢复，不复用已过期的扫描文字。

### 8.3 线程与资源

使用执行器拥有的工作线程与明确生命周期替换 detached 每请求线程。QProcess 和 QNetworkAccessManager 在其所属线程创建、使用与销毁；GUI 只提交值与接收排队投递的结果。

WinRT 使用异步完成，不在 GUI 调用阻塞等待。完成回调不得捕获已销毁的 CaptureDuty；取消状态、任务句柄与代次由执行器持有。一次任务逻辑终止后，仍需追踪底层是否清理，不能立即再启动同后端造成重叠。

设置变化、关闭截图、预算暂停、退出应用均使相应事务失效。窗口切换只使扫描结果失效；用户明确框选的截图不因切到别的窗口而自动改目标。模式、后端、语言、路径、端点或 key 变化必须撤销等待中的上传确认。

退出时先拒绝新任务，再取消当前任务、释放预览并等待有界清理；禁止强杀不属于 Lens 的进程。无法证明可有界关闭的后端不能通过接入验收。

### 8.4 HTTP 与计费

- 请求必须使用 HTTPS 与正常证书验证；不提供 “忽略证书错误”。
- 端点为用户直接配置、已展示的完整识别 URL，不从 OCR 返回内容构造 URL；拒绝 userinfo、fragment、带凭据的 query 和非法控制字符。
- 禁止自动重定向，包括同站点跳转；3xx 返回端点配置错误，避免把密钥带到未确认的目的地。
- 使用系统代理策略，不改系统代理，不自动发现或启动代理软件；文档不承诺代理不会看到目的地或解密内容。
- 没有自动重试、并行竞速或跨服务商回退。超时是 “结果未知”，不能推断未计费。
- 用户明确重试需重新确认，使用仍在有效期内的同一裁剪图；不自动重抓桌面。每个事务最多追加一次在线请求。
- 请求体、响应体、解压后的响应均受上限约束；收到超限数据即中止。不能只检查 Content-Length。
- 不信任服务返回的 HTML、错误正文、链接或文件名；通知用本地枚举映射，识别文字作为普通文本。

OCR 服务费用不进入现有按 token 估算的解释账单，不伪造为零。设置与确认页说明 “由 OCR 服务商计费，不计入 Lens 的模型花费统计”；Lens 已知每日预算耗尽时仍拒绝新截图与在线检测，但该预算不是云 OCR 的金额硬上限。真实额度应在服务商账号设置。

## 9 配置、密钥与恢复默认

### 9.1 配置表

所有新增 OCR 字段均为本机设置，不加入同步白名单。路径、服务地址与授权不随账号迁移；词汇导出也不含它们。

| 键 | 类型／缺省 | 写入语义 |
|---|---|---|
| `ocrConfigVersion` | 整数，首轮 1 | 迁移与读取版本，不由 UI 修改 |
| `ocrMode` | `local`／`online`，缺省 `local` | 切换即撤销旧截图事务 |
| `ocrLocalEngine` | `auto`／`tesseract`／`rapidocr`，缺省 `auto` | 明确选择不静默改写 |
| `ocrLocalLanguage` | `en`／`zh-Hans`／`zh-Hans+en`，缺省 `en` | 变更使本地能力检测失效 |
| `tesseractExecutable` | 字符串，空 | 空表示随包 exe，继续使用现有键 |
| `tesseractDataDirectory` | 字符串，空 | 空表示所选 exe 的相邻 tessdata |
| `rapidOcrExecutable` | 字符串，空 | 仅支持协议已锁定的程序 |
| `rapidOcrModelDirectory` | 字符串，空 | 模型组合与程序版本一起检测 |
| `ocrOnlineProvider` | 服务 id（§7.3 表），初始未配置 | 只接受表内 id；切换服务清空地址与全部凭据 |
| `ocrOnlineEndpoint` | HTTPS URL，初始空 | 空表示服务默认地址；不从解释配置复制 |
| `ocrOnlineLanguage` | `eng`／`auto`，初始英语 | 必须为该服务列出的语言 |
| `OCR-API-KEY` | 独立机密，初始空 | `apiKey` 槽；专用写入／清除命令；普通 settings 投影不可读取 |
| `OCR-SECRET-KEY` | 独立机密，初始空 | `secretKey` 槽；与上一行同规则 |

不预建没有实现的 Paddle、NPU 或各家云端字段。若将来某协议确实需要模型名，再由该 Adapter 增加对应配置；不是所有在线 OCR 都有模型选择。

### 9.2 保存与信任

沿用读者 `%APPDATA%\Lens\settings.json` 的本地保存位置，不创建安装目录密钥文件。OCR key 与解释 `API-KEY` 分开，不能隐式共用或因切换服务自动复制。

UI 只能读到每个凭据槽是否已填（`ocrOnlineCredentials` 的 `present`），写入后立即清空输入草稿，返回掩码占位。通用 `setSetting`、开发面 `state`、同步序列化、诊断导出均不得返回 key。交换来的令牌同样不进入任何投影或日志，只在内存中按服务与地址缓存。

端点或服务商改变时，原凭据不自动发送给新地址；清除其有效绑定，要求重新输入密钥。必须由一个专用配置提交操作写入服务商、端点、语言和可选新密钥，并只在整组校验完成后更新执行器快照。普通字段仍按既有即时生效模式编辑，编辑期间不触网。

保存失败要保留旧的有效配置或标成未保存，不能让 UI 显示已保存而网络使用另一份。并发写入与持久化仍走 SettingsSection，新增多键提交语义须有原子可见的单次持久化测试，不把几次独立 set 当成事务。

沿用普通 JSON 意味着本机其他有读取权限的软件仍可读取密钥；文档不得宣称加密存储。DPAPI／Credential Manager 是可另行提出的强化，不作为这次悄悄迁移全部用户密钥的理由。

### 9.3 恢复与删除

- 恢复默认将手动模式设回本地、引擎设回自动、语言设回英文，关闭自动扫描与截图开关，清空自定义本地路径并撤销外部程序信任。
- 解释 key 与 OCR 凭据均不由 “恢复默认” 隐式删除；在线配置可保留但不生效。提供明确的 “清除在线 OCR 配置” 操作，删除服务、端点、凭据和检测状态。
- 清除或修改 OCR key 会取消在途任务；不能保证已上传内容从服务商删除。
- 关闭在线模式释放内存图像，不删除用户下载的程序或模型。
- 不借本次设置变化清空解释缓存、词汇历史或复习池。

## 10 UI 交互开发规格

共用视觉约束继续使用 [DESIGN.md](../DESIGN.md)，设置结构、键盘与主题继承 [UI-SPEC.md §4.4](../UI-SPEC.md#44-设置浮层)。不增加主窗口，不修改字号、圆角、阴影或动效令牌。

### 10.1 设置导航

在 “取词与弹窗” 保留三个通道开关、就绪摘要与一行 OCR 配置入口，复杂字段进入固定尺寸设置浮层的子页面；不能把所有引擎路径堆在首屏。

OCR 子页面顺序：

1. 手动截图模式：本地 / 在线。
2. 本地引擎与识别语言：始终可配置，注明自动扫描只使用这一组。
3. 所选本地引擎的条件字段与 “检测并运行”。
4. 在线配置入口及已配置 / 未配置状态。
5. 实际后端与最近检测结果，不展示文章文本。

本地自动选择时显示 Tesseract 摘要；明确选择时只显示该引擎对应字段。用户安装程序 / 模型用文件或目录选择器，不提供自由命令行。

在线配置页面为服务选择、端点、语言、该服务声明的凭据字段、显式连接检测及清除配置。端点在未填写时显示服务的默认地址；凭据字段由服务表决定，OCR.space 一个 key，百度一个 key 加一个 secret，界面不显示服务没有的字段。切换服务后地址与凭据一并清空，读者重新填写；只有 Adapter 需要时才显示模型字段。

### 10.2 状态不是一个布尔值

设置投影至少分开 `localAvailability`、`screenshotAvailability`、`scanAvailability`、`onlineConfigured` 与 `testState`。

| 状态 | 显示意图 | 是否可执行 |
|---|---|---|
| 未配置 | 缺路径、端点或密钥 | 对应路径不可执行，设置可编辑 |
| 未信任 | 新选择的第三方程序尚未获准执行 | 只允许确认后的显式检测 |
| 检查中 | 一次用户检测在进行 | 检测按钮禁用；不改变其他模式 |
| 可用 | 已验证当前配置 | 可接收匹配来源的请求 |
| 缺语言／模型 | 明确资源名称 | 不替用户安装，允许修改配置 |
| 上次请求失败 | 网络／识别失败的固定原因 | 不把一次超时永久标记为未安装 |
| 配置已改变 | 检测结果失效 | 撤旧成功状态，不自动联网复测 |

在线配置齐全不等于服务器已验证；连接检测只证明该时刻、该配置、该样图的调用成功，不保证费用、隐私、语言全覆盖或未来可用性。

### 10.3 上传确认与取消

新增一张专用于本次上传的轻量确认卡，内容仅为：裁剪图预览、目标服务及实际主机、两段出站与费用说明、确认上传 / 取消。没有修图、OCR 校对或批量功能。

- 确认卡拿到的是已冻结选区图；图像只在内存中，通过请求 ID 的受控图片源显示，不能把 base64 塞进可枚举设置或调试状态。
- `Esc`、关闭卡片或超时均取消；焦点初始落在取消操作，不能因框选结束的回车误上传。
- 卡片显示后暂停扫描，不把卡片里的预览或词识别回 Lens；必要的抓屏排除与表面互斥接线和其他隐私表面一致。
- 上传期间显示可取消状态，不假装进度已到服务商识别阶段；只有真实上传字节可以用进度条。
- 只有第 8.2 节列出的可重试失败才显示重试与取消；单次请求超时不是事务到期。重试仍需明确发送动作，达到次数或事务时限上限后释放原图，只允许重新框选。
- 屏幕变化不刷新预览，配置变化直接使卡失效；不在旧图旁偷偷替换服务商。
- 英语为源语言，所有正式 UI 文案进入五套翻译；本文只规定意图，不维护另一份翻译表。

## 11 安全实施与数据生命周期

### 11.1 数据清单

| 数据 | 留存位置 | 释放／删除 |
|---|---|---|
| 截图选区像素 | Lens 内存；本地后端输入；明确授权的在线服务 | 本机在事务完成、取消、绝对到期或退出时释放；单次失败后的有限重试留存按第 8.1 节，不落盘；外部服务留存按其政策 |
| OCR 原始响应 | 有界内存 | 解析后释放，不进日志、同步或诊断包 |
| 结构化识别文本 | 当前事务／有界本地扫描状态 | 交付或失效后释放；进入解释后的缓存遵循原有规则 |
| 在线密钥 | 用户设置文档及必要运行时内存 | 用户明确清除；不回显、不导出、不同步 |
| 外部程序信任记录 | 本机配置中的路径与摘要 | 程序／模型变化或恢复默认时撤销 |
| 运行诊断 | 后端 ID、枚举状态、耗时、字节数、是否回退 | 沿用现有滚动日志；不得含文本、图片、key、完整路径或完整 URL |

释放引用不是内存取证级安全擦除；Qt 图像与字符串可能有共享副本，崩溃转储也可能包含内容，不能承诺 “任何地方都不可恢复”。

### 11.2 必须覆盖的滥用情形

| 情形 | 必须成立的防护 |
|---|---|
| 设置中选了在线，后台扫描触发 | 扫描依赖不含在线客户端；在线提交门再次拒绝扫描来源 |
| 本地识别低分或失败 | 不申请上传、不请求在线服务 |
| OCR 服务返回“请访问某链接” | 只按文字处理，不追加请求、不打开浏览器 |
| 端点返回重定向或登录 HTML | 拒绝，不透传 key，不把 HTML 当 OCR 文本 |
| 服务报错正文含 key／原始图片 | 不拼接原始错误，固定错误文案 |
| 用户修改端点但沿用旧 key | 凭据绑定失效，须重新输入；旧确认作废 |
| 调试面调用确认动作 | 仅能操作合成测试事务，不得授权真实图像出站 |
| 恶意模型／exe | 首次执行确认、进程限额与终止；明确不是安全沙箱 |
| 取消与成功同时到达 | 在同一状态拥有者处串行裁定，最多一个可消费终态 |
| 服务成功但客户端超时 | 标为结果未知，不自动重试、不能说未计费 |

不记录截图正文的 hash 作为遥测替代：短文本 hash 仍可能被枚举还原，且本任务不需要跨会话图像追踪。

## 12 验证与验收

### 12.1 分层测试

| 层 | 用例范围 | 证据 |
|---|---|---|
| 纯契约 | 状态／回退／语言能力／代次／坐标还原 | 确定性 gtest |
| 解析 | TSV、候选 JSON、在线 JSON；畸形、超限、无文字、无置信度 | 固定人工编写或脱敏 fixture |
| 配置 | 旧配置迁移、非法枚举、路径变化、key 不回显、同步排除 | 私有临时 profile 的往返断言 |
| 排程 | 扫描丢帧、手动优先、取消、清理、旧任务晚回、退出 | 可控的进程／WinRT／网络 Adapter 替身 |
| HTTP | 请求字段、无重定向、大小限制、超时、零自动重试 | 注入网络传输，记录上传次数与字节 |
| UI | 子页、条件字段、键盘、缺资源、确认取消、模式切换、错误状态 | dev surface 与针对性 QTest |
| 真实本地后端 | 安装版／便携版、语言包、模型、路径编码、关闭清理 | 显式启用的 integration／bench |
| 真实在线后端 | 合成样图一次往返与固定语言 | 人工批准的独立 smoke，不进日常 CI |

核心安全验收是可观察的负面断言：未确认时发送次数为 0；扫描时在线次数为 0；取消后解释次数为 0；端点变更后旧事务发送次数为 0。还须用可控时钟覆盖首次确认、失败清理、重试确认与 120 秒绝对到期，断言到期释放原图且不接受迟到授权。不能仅以 “页面按钮灰了” 代替后端准入测试。

### 12.2 图像与连续帧语料

先用约 20 张代表图打通工具，再扩充到 60–100 张；不做各维度完整笛卡尔积。

覆盖浏览器正文、PDF、代码 / 终端、UI 小字；100%／125%／150%／200% 缩放、明暗主题、英语、中文和混排。每张有人工转写、语言与输入来源；先对一小组标注词 / 行框。

另外准备静止、光标闪烁、小动画、滚动、窗口切换的连续帧。静态图只能评估识别，不能证明稳定逻辑、误弹率或 CPU 改善。

素材必须是合成或获准公开的内容，不从真实邮箱、工作聊天或用户桌面批量抓取；在线 smoke 只用合成样图。

### 12.3 指标与退出条件

| 指标 | 判读方式 |
|---|---|
| WER／CER | 按语言、DPI、主题与内容分组；中文以 CER 为主，不混成一个总平均 |
| 行／词框 | 按真实能力统计 IoU 与检出率，缺词框不得当作零误差 |
| 延迟 | 分冷启动／热调用、单引擎／回退、识别／完整截图链路，报 p50／p95 |
| 资源 | 单核占用、整体 CPU、内存峰值、进程／句柄是否回落 |
| 扫描 | 每分钟实际 OCR 次数、有效候选召回、误弹、首次触发延迟 |
| 在线 | 请求次数、上传体积、超时、取消与重复提交，不捏造收费金额 |
| 包体 | 安装 payload 与下载包分别测；保留 Tesseract 不声称省掉其体积 |

早期调研的 WER 降低 30%、误弹降低 50% 等均为待校准目标，不是本方案已证实的结果。首轮可发布条件是关键语言 / 场景不出现无法解释的退化、所有安全断言通过、部署矩阵有证据；具体性能门槛在基线完成后按目标机器锁定。

### 12.4 执行安全与最小测试集

按照 [TEST.md](../TEST.md) 和 [docs/qa.md](qa.md) 的现有入口，逐改动只跑相关 gtest filter 或 QTest case；不要为文档改动运行应用测试。

- 测试 profile、日志、输出与临时路径必须私有，不回退到真实 `%APPDATA%\Lens`；不读写真实密钥。
- 网络替身默认不出站；本地测试服务器仅用测试拥有的 loopback 端口，不为测试放宽产品 HTTPS 规则。
- 不安装系统语言包、不改变代理或系统证书、不占用真实剪贴板或注册全局热键来 “顺便测试”。
- 真实界面与抓屏验证需要明确许可，按 dev surface 优先，截图与鼠标注入只在必要时使用。
- 真实在线 smoke 每次进程默认最多 1 次请求，自动重试为 0；明确服务商、合成素材和可能费用后才运行，密钥在用户 profile 原地读取，不复制到 fixture。
- 真实机器长时间扫描测量须另获批准；第一轮短、单后端、串行运行，不一开始压满 CPU／GPU。

## 14 后续扫描迭代的设计底线

多引擎交付不必等待扫描 v2，但结构化结果必须容纳后续使用。

1. 首次整窗识别建立版面后，比较已有区域像素；只对变化区域重识别，才能真正节省 OCR，而不是整窗识别完再跳过计分。
2. 滚动、缩放、换页、尺寸变化、旧框外新增文字都必须触发重新发现；不能永远只盯旧行框。
3. 全文相似度只辅助页面稳定，真正准备弹出的目标词需要更严格的一致性或独立质量判定，避免长页面掩盖一个词变化。
4. 稳定样本与像素门共同设计，静止页面不能因为跳过后续识别而永远无法达到首次稳定。
5. 像素变化率不是视频分类器，不能直接用固定 15% 阈值封禁滚动页面。
6. 置信度缺失不自动拒绝该结果；阈值按后端分别校准，不能拿 Tesseract 分数与其他模型分数比较。
7. 不用词表编辑距离静默纠正专名；断行修复、连字归一化与真正拼写改写分开评估。
