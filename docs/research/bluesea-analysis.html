可借鉴

借鉴点依据对 Lens 的建议优先级
遗忘曲线分级复习，失败则回退一级 logic.js 的 forgettingCurve 为 5 分钟、30 分钟、12 小时、1 天、2 天、4 天、7 天、15 天、30 天；完成最后一级后标记 done。注释写明“如果多次点没记住，那么就回滚到上个级别”。 Lens 目前只有“已会 / 新词”两态，“已会”永远不过期。这是词汇学习上的主要缺口。可以在 KnownStore 里加一个复习级别与下次时间，复习入口放在词汇弹窗或托盘菜单里，不在阅读时弹出。 高
生词本导入导出（.json 与 .txt） README 第 139–140 行：支持 .json 与 .txt 的导入导出。 Lens 的生词数据目前只能经 gist 同步（PRODUCT.md 第 76 行）。文件导出让读者自己备份，也便于迁移。 中
被动复习：单词弹幕 配置项“单词弹幕开关、数量上限、速度”，默认可调。 这种被动复习与 Lens 的“不打断阅读”相冲突。若要做，只能放在屏幕边缘，默认关闭，并允许读者调整数量与速度。 低
默认关闭中文注解 defaultConfig 中 中文注解: false。 与 Lens 的英文优先一致，可以保持。 已具备
按站点设置黑名单 testBlack() 按 hostname 判断。 Lens 的扫描白名单按前台进程名，粒度不同，思路一致。 已具备

可改进（BlueSea 的问题，Lens 应避免）

1. 已完成的词会被永久删除（已复现）

logic.js 的 getMaterials() 在“隐藏完成复习的单词”为真（默认）时，过滤掉 learn.done 为真的词。随后 addMaterialObj()、updateMaterialObj()、toLearnNext() 都先调用 getMaterials()，再用 setMaterials() 把过滤后的列表整表写回。被过滤掉的词因此从存储中消失。

复现方法：用 Node 加载真实的 logic.js 数据层（截断到 class FunCtrl 之前），以内存版 chrome.storage 替代浏览器存储。脚本未纳入仓库，保存在本机的缓存目录中（文件名 repro.cjs）。结果如下：

场景写入前写入后
1. 添加新词 charlie（隐藏开启，默认）alpha（已完成）、bravobravo、charlie，alpha 消失
2. 完成一次复习 bravo（隐藏开启，默认）alpha（已完成）、bravobravo，alpha 消失
3. 对照：同样添加 charlie，隐藏关闭alpha、bravoalpha、bravo、charlie（数据完整）
4. 撤回已隐藏的 alpha（findIndex 返回 -1）bravo、alpha（已完成）alpha，bravo 被覆盖

对照组说明原因在于“过滤后的视图被当作完整数据写回”。场景 4 的原因是 updateMaterialObj() 对 -1 执行 splice(-1, 1, material)，覆盖了列表的最后一项。场景 4 需要满足“要撤回的词已被隐藏”这一条件，我只在隔离环境中复现了这条路径，没有在浏览器里点击验证。

Lens 的建议：写回的必须是完整数据，不能是视图。Lens 的 KnownStore 也是整文档写回，应当增加一条测试：先标记若干已会词，再保存，检查未显示的词是否仍在文件里。这条检查项尚未在 Lens 中执行。

2. 查询串没有编码（已复现）

background/background.js 第 15–16 行把选中的文字和 appkey、key 直接拼进 URL，没有使用 encodeURIComponent。复现结果：选中 R&D 时，text 参数只剩 R；选中 C# & #1 时，text 只剩 C，appkey 参数丢失。

Lens 的建议：凡是拼接 URL 的地方都用 QUrlQuery 编码。Lens 的 LLM 请求是否经过编码，尚需检查。

3. 用户的 API key 放在 URL 查询串里，并发往作者的中转

默认路径下，翻译请求发往作者的腾讯云函数网关（service-pnrys8g3-1254074572.bj.apigw.tencentcs.com），appkey 与 key 作为查询参数出现在 URL 中。URL 会进入代理、网关与服务器日志。README 第 104 行称“配置 key 后，后台不会做任何记录”，这一点无法从仓库验证。README 第 90 行还承认作者的免费额度“即将耗尽”，并限制句子翻译。

Lens 是 BYOK：请求直接发往读者选定的服务商，key 应当只放在请求头里，不放进 URL。

4. 调试脚本进入生产清单

manifest.json 的后台脚本列表包含 lib/hot-reload.js，这是开发期的热重载脚本，读者安装的扩展里也会带着它。

5. web_accessible_resources 暴露所有脚本

manifest.json 中 "web_accessible_resources": ["*.html", "*.js", "*.css"]，任意网页都可以加载这些资源，用于扩展指纹识别，也扩大了攻击面。应当只列出确实需要暴露的文件。

6. 存储结构：整表 JSON 写回

所有生词存在 chrome.storage.local 的单个数组里（键为 materials），每次写入都重写整个数组。词量增加后，每次操作的成本线性增长。Lens 的 settings.json 也是单文档，但有明确的所有者规则（PRODUCT.md 第 101–104 行），这一点比 BlueSea 严谨。

7. 维护停滞且无许可证

代码最后一次提交在 2021 年。33 个开放 issue 中有 21 个没有任何评论。没有许可证，也没有测试。它的 star 来自 2020–2021 年的积累，今天的维护状况与 star 数不匹配。

风险与局限

  • 未在 Chrome 中加载扩展，issue #74 的“加载报错”未能复现。
  • 复现使用内存版 chrome.storage。真实存储是异步的，时序可能不同，但本次复现的是写回语义，不依赖时序。
  • README 中关于作者网关“不做记录”的说法无法验证。
  • 有道翻译返回的内容未测试。

方法

通过 repo-cache 克隆仓库，阅读 manifest.json、logic.js、background/background.js 与 README。用 Node 24 复现存储写回路径，并单独验证 URL 编码行为。对照项目的 GitHub 元数据与 issue 列表来自 gh CLI。
