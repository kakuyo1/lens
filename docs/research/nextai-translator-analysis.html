可改进（nextai 的问题，Lens 应避免）

1. 把屏幕文字和查词历史发给模型

src/common/components/QuickTranslator.tsx 的 summarizeContext（第 300–311 行）把以下内容写进提示词：鼠标下的文字、焦点元素的文字（最多 600 字符）、窗口段落（每段最多 280 字符）、应用名与 bundle id。buildPickerPrompts（第 344 行起）还附上用户最近 25 条查词与多词查词样例，作为“查词历史指纹”。这一功能由快捷键调出，不是自动运行。

这违背 Lens 的原则：“绝不发送整屏或快照全文”（PRODUCT.md 第 23 行）。它的功能设计有价值（让模型从屏幕上挑出读者可能想查的词），但隐私代价过高。若要做，只能作为显式开启、默认关闭、发送前可预览的选项，并写进 SECURITY.md。

2. 默认推荐的服务商带推广链接

README 把 TeamoRouter 列为“推荐”，链接带 utm_source=nextai_translator 等参数，并写有“up to 90% off”。它也是内置服务商（src/common/engines/teamorouter.ts）。一个让读者填自己 API key 的工具，把某个中转商作为默认推荐，会带来利益冲突，应当披露。

Lens 的服务商来自 data/llm/catalog.json，该文件中没有推广或联盟字段（已搜索 utm、affiliate、referral、promo，无结果）。

3. 许可证标注不一致

README 徽章写 MIT，LICENSE 文件是 AGPL-3.0 全文。读者无法判断能否合规复用。Lens 应确保 README 徽章与 LICENSE 文件一致。

4. 单词输出是自由文本，格式靠提示词约束

translate.ts 要求模型按固定版式输出单词卡（词性、释义、例句、词源）。客户端没有对应的解析代码（在 src/common 中搜索不到对该格式的解析），结果直接渲染。模型偏离格式时，界面不会报错。

Lens 的 JSON schema 与响应校验更可靠，保持现状。

5. 本地 IPC 没有鉴权，非 Windows 路径不安全

src-tauri/src/main.rs:513 在 Windows 上监听 127.0.0.1:62007，没有 token。非 Windows 分支使用固定路径 /tmp/openai-translator.sock，启动前直接 remove_file（错误被 unwrap_or_default 吞掉），没有检查该路径是否是 socket，也没有检查是否为符号链接。在多用户机器上，这个固定路径存在被抢占或替换的风险。

Lens 没有本地服务，保持。端口与 socket 名仍是 openai-translator，说明改名没有彻底，这一点影响较小。

风险与局限

  • 未运行扩展或桌面端，判断来自源码阅读。
  • ax_context.rs 的 macOS 实现已读，Windows 对应实现未读，因此不确定 Windows 版是否也读取焦点元素。
  • TeamoRouter 的定价与返利说法来自 README，未核实。
  • star、提交与测试数来自 GitHub API 与本地克隆的快照（2026-10-16）。

方法

通过 repo-cache 克隆仓库，阅读 README、AGENTS.md、src/common/translate.ts、src/common/components/QuickTranslator.tsx、src/common/engines/、src-tauri/src/ax_context.rs 与 main.rs 的 IPC 段，并核对 LICENSE、.github/workflows/ 与测试文件数量。
