可借鉴

借鉴点依据对 Lens 的建议优先级
英文释义的离线来源：词典数据做兜底 pot 的 Cambridge 与 ECDICT 服务都是词典类，不依赖 LLM。 Lens 仓库已经解析 WordNet 的异常表生成 data/irregulars.tsv（见 docs/history/PHASE1.md §4.1），只用了屈折变化，没有用释义。WordNet 的 data.* 文件带有英文释义，可作为离线、免费的兜底。这一点是 WordNet 的格式事实，本仓库尚未验证。 高
Windows 系统 OCR 作为可选后端 src-tauri/src/system_ocr.rs 调用 Windows.Media.Ocr。语言包缺失时，错误信息会指向 PowerToys 的支持语言说明。 Lens 目前随包分发 Tesseract。增加一个系统 OCR 选项，可以省下安装包里的 OCR 运行时，也能复用读者已装的语言包。错误提示的写法值得照搬。 中
剪贴板监听作为一种取词模式 src-tauri/src/clipboard.rs 每 500 ms 读取一次剪贴板，与上次内容比较，有变化就翻译。 可作为可选模式。但它会读取读者复制的所有内容，所以只能默认关闭，并且在设置里说明。Lens 的 PRODUCT.md 已要求“发送前可预览”，这一条同样适用。 低，需先设计隐私边界
生词本导出到 Anki src/services/collection/anki；README 的功能列表“导出到生词本”。 Lens 的生词数据目前只能经 gist 同步（PRODUCT.md 第 76 行）。加一个文件导出，读者可以自己备份，也能迁移到 Anki。 低
每个服务一个目录（info、实现、配置分开） 22 个翻译服务各有目录，info.ts 注册名称与图标。 Lens 已经用 data/llm/catalog.json 把服务商数据化，不需要照搬目录结构。 不借鉴

可改进（pot 的问题，Lens 应避免）

1. 本机 HTTP 接口没有任何鉴权

src-tauri/src/server.rs 在 127.0.0.1:60828 监听，全文没有 token 检查，也没有 Origin 检查（搜索 origin、token、auth 均无结果）。/config 会打开配置窗口，截图 OCR 相关路径会触发截图流程。网页向本机端口发送 text/plain 的 POST 不需要预检，因此网页可以触发这些接口（响应读不到，但动作会执行）。

Lens 没有任何本地服务：src/ 中没有 QTcpServer、QLocalServer、QHttpServer。Lens 的建议：不为“外部调用”开放端口；确需 IPC 时使用带 ACL 的命名管道，并在首次连接时让读者确认。

2. 插件可以运行任意程序

src/utils/invoke_plugin.js 用 eval 执行插件的 main.js，并把 run 暴露给插件。src-tauri/src/cmd.rs 的 run_binary 直接执行 Command::new(cmd_name)，没有白名单。安装一个 .potext 文件就等于授予任意代码执行权限，并且没有签名校验。

Lens 的 ADR 0043 选择了数据包：只含 JSON 与 PNG，应用不执行包内任何代码。这是正确的边界，应当继续坚持。

3. 内置 ECDICT 服务把查询词外发，README 没有说明

src/services/translate/ecdict/index.jsx 把查询词 POST 到 https://pot-app.com/api/dict。README 把 ECDICT 列为插件（“[插件](…pot-app-translate-plugin-ecdict)”），却没有说明内置的 ecdict 服务会访问 pot-app.com。

Lens 的原则是“只发送选中内容，发送前可预览”。外发端点必须在文档中列明。

4. 词典服务只做英汉，没有英英路径

src/services/translate/cambridge_dict/index.jsx 只在源语言为英文、目标语言与源语言不同时查询，数据集固定为 english-chinese-simplified。它抓取的是中文译文节点（.trans.dtrans）。因此这个服务的设计目标就是把英文翻译成中文。这与 Lens 的理念相反。它还依赖 HTML 结构，页面改版即失效。

5. 没有测试，维护停滞

Rust 与 JS 测试均为 0。最近一次 Release 是 2025-05-10，2026 年的提交以翻译同步为主。Star 数很高，并不代表代码在持续维护。

6. 错误路径用 unwrap，失败即 panic

src-tauri/src/system_ocr.rs 中，文件打开、位图解码与识别都用 unwrap()，只有 OCR 引擎创建失败会返回可读错误。图片路径异常时会直接 panic。Lens 的 OCR 与 LLM 错误路径应返回可读的错误，不应崩溃。

风险与局限

  • 未读 selection = "1.2.0" 这个 crate 的源码，因此不知道 pot 取词的具体方式（UI Automation 还是模拟复制）。
  • 未运行应用，所有判断来自源码阅读。
  • star、Release 与提交数来自 GitHub API 的快照（2026-10-16）。
