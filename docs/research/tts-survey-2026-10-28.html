00摘要

如果只读一段，读这一段。

结论

成熟项目几乎都不把"发音"当成一个按钮，而是拆成两层：取音频（source）与放音频（player）。 source 可以换（系统合成 / 在线音频 / 本地模型），player 只做一件事：同一时刻只响一个，新的来了先停旧的。 这层抽象是所有项目的最大公约数，也是 Lens 现在缺的那一块。

三个发现

  1. "单词发音"和"句子朗读"是两种产品，不是同一个接口。 同类工具里，单词发音几乎都走词典音频端点（一个 GET 拿到 mp3，100ms 级）； 句子朗读才需要真正的 TTS（Edge / Azure / 本地模型，300ms 起步）。qwerty-learner 23.5k 星只做前者，做得很干净。
  2. 系统合成器是最便宜的兜底，但音质常常不够用。 Anki、Easydict、GoldenDict-ng 都接了系统 TTS；代价是"用户机器上有什么声音就只能用什么声音"。 本机实测：SAPI5 只有 Zira (en-US) 和 Huihui (zh-CN) 两个，OneCore 只有 3 个中文音色，没有神经音色。 拿 Zira 读单词教发音，是在教机器口音。
  3. 免费 ≠ 能用。 有道 dictvoice 端点 100ms 级、免鉴权、无 Referer 校验，但它本质是词典条目音频： 实测 as a matter of fact 返回 200 / 45KB，而 give up the ghost 和一句 9 词的普通句子直接 HTTP 500 + 120 字节。 把它当唯一音源，句子卡片会静默失声。

决定（一句话版）

当日已定（docs/adr/0134）：发音只做单词，不做句子。系统合成器为缺省引擎； 不可用时按读者选的兜底走——在线音频（缺省）或本地模型（可选下载，不随包）。 落地仍是 speech_duty + 一个 SpeechSource 接口 + 磁盘缓存 + QMediaPlayer（QBuffer 供源，不落临时文件）， 只是三档 source 的主次换成这个顺序；Azure / edge-tts 这类整句合成不在范围内。

调研发现仍然成立，取舍与落地见 §05。

01Lens 的起点

先量一下我们站在哪里，再谈抄谁。

仓库里 docs/adr/0010-model-ipa-without-speech.md 写得很清楚：音标随释义一起返回，气泡只读展示，不接入 TTS。 那个决定的理由是"避免引入本地音标库及其数据与许可维护"——它成立的前提是"发音"等于"本地音标库"。今天要加的是音频，前提变了，所以该由一条新 ADR 取代它，而不是绕过去。

先记一笔

Qt 6.9 里 QTextToSpeech 本身不含合成引擎，它只是系统引擎的壳：Windows 上 winrt（音质好、要新 Windows SDK、MinGW 不可用）和 sapi（音色少、质量差）。 换句话说，"用 Qt 自带 TTS"= "用 Windows 自带 TTS"，并不会凭空多出音色。

B 路线：在线音频，四个不同的接法

qwerty-learner RealKai42★ 23,574
TypeScript · GPL-3.0

打字背单词网站。发音就是一个 URL：dict.youdao.com/dictvoice?audio=word&type=1|2，type 切英音/美音，另有 le= 参数覆盖日/德/俄等语种。播放交给 Howler（html5: true），带 rate/volume/loop，并有一个 usePrefetchPronunciationSound 预取钩子。

可借鉴单词发音不需要 TTS，只需要一个稳定的词典音频 URL + 预取。这是同类产品里成本最低、体感最好的做法。

JavaScript + Rust(Tauri) · GPL-3.0

TypeScript · MIT

没有用现成库，直接在 TS 里实现了 Edge 朗读协议的客户端：SSML 拼装、volume/rate/pitch 枚举、audio-24khz-48kbitrate-mono-mp3 输出格式、WebSocket 收流。播放层 createTTSPlayer() 只有 init/play/stop 三个方法，play() 第一件事是把上一个 AudioBufferSourceNode stop 掉。

Python · GPL-3.0

A 路线：系统合成，Qt 项目最该看的两处

goldendict-ng xiaoyifang★ 3,121
C++ / Qt · GPL-3.0

同一个仓库里把两件事分得很干净：src/audio/ 负责播放（后端可插拔：Qt Multimedia / FFmpeg / 外部播放器），src/speechclient.* 负责合成（QTextToSpeech，编译期 TTS_SUPPORT 开关）。播放器把内存字节塞进 QBuffer 直接给 QMediaPlayer::setSourceDevice()。

可借鉴播放 ≠ 合成。Lens 以后要换音源，换的是 source，播放层一行都不用改。
Anki ankitects★ 32,358
Rust + Python / Qt · AGPL-3.0

最完整的一套：Player 抽象出 rank_for_tag()，AVPlayer 按 rank 选最合适的播放器；TTS 有三条实现——macOS 起 say 子进程、Windows 走 SAPI.SpVoice COM（Speak(text, ASYNC|IS_NOT_XML) + WaitUntilDone(100) 轮询）、以及 WinRT 合成成 tts.wav 再交给播放队列。语速映射到 SAPI 的 -10..10。

qt/aqt/tts.py qt/aqt/sound.py
可借鉴合成结果按 hash(voice+lang+text) 命名落盘——注释里直说是"to allow for caching"。
Easydict tisfeng★ 15,102
Swift / ObjC · GPL-3.0

macOS 划词翻译。TTS 后端枚举了五家：youdao / bing / google / baidu / apple，用户在设置里选；播放层是单例 EZAudioPlayer，URL 音频走 AVPlayer，Apple 那一路走 NSSpeechSynthesizer，并按 premium > enhanced > compact 给音色排优先级。

04代码级细节

五个可以直接搬走的模式。

① 播放层：内存字节 → QBuffer → QMediaPlayergoldendict-ng

这是 Qt 桌面端最干净的一段代码：没有临时文件、没有 URL、没有解码器选择。注意 stop() 里显式把 device 解绑，否则下一个 QBuffer 析构时播放器还握着悬空指针。 

// goldendict-ng / src/audio/multimediaaudioplayer.cc（节选）
QString MultimediaAudioPlayer::play( const char * data, int size )
{
  stop();
  audioBuffer.reset( new QBuffer() );
  audioBuffer->setData( data, size );
  if ( !audioBuffer->open( QIODevice::ReadOnly ) )
    return tr( "Couldn't open audio buffer for reading." );

  player.setSourceDevice( audioBuffer.get() );   // 直接吃内存，格式自己嗅探
  player.play();
  return {};
}

void MultimediaAudioPlayer::stop()
{
  player.stop();
  player.setSourceDevice( nullptr );   // 必须显式解绑
  player.setSource( QUrl() );
  ...
}

② 合成结果落盘时用内容哈希命名anki

Anki 的注释写得很直白——"Return a hashed filename, to allow for caching generated files"。缓存 key 是 voice + lang + text，不含语速（语速在播放侧调），这个取舍值得抄：改语速不该重新合成。

def temp_file_for_tag_and_voice(self, tag: AVTag, voice: TTSVoice) -> str:
    """Return a hashed filename, to allow for caching generated files."""
    buf = f"{voice.name}-{voice.lang}-{tag.field_text}"
    return os.path.join(tmpdir(), f"tts-{checksum(buf)}")

③ 播放器只认"rank"，不认类型anki

每个 player 回答"这个 tag 你多合适"，AVPlayer 挑分最高的。好处是新增一路音源（比如以后接 Azure）不用改调度逻辑，只要新 player 报一个更高的分。Lens 现在只有一路，但接口形状可以先按这个来。

class Player(ABC):
    def rank_for_tag(self, tag: AVTag) -> int | None:
        """AVPlayer will choose the player that returns the highest rank
        for a given tag. If None, this player can not play the tag."""

⑤ 播放 ≠ 合成goldendict-ng / anki

两个最成熟的 Qt 项目都把它们拆成两个模块：GoldenDict-ng 是 src/audio/（放）与 src/speechclient（说）； Anki 是 aqt/sound.py（放）与 aqt/tts.py（说）。合并成"一个发音按钮类"的写法，在这两个仓库里都找不到。

05给 Lens 的方案

按"v1 能上线、v1.5 能换源"来设计，而不是一次到位。

决策矩阵

按 2026-10-28 的决定（ADR 0134）标注采用范围；调研结论不变，只是主次换了。

方案定位单词音质句子离线装包风险
A 系统合成器 缺省引擎 任意文本 是 +1.8MB 音色由 Windows 语言包决定
B1 词典音频 + 缓存 缺省兜底 弱 否 ≈0 端点非官方；失败静默
C 本地模型（sherpa-onnx） 可选兜底 强 是 运行时随包，模型下载 下载 / 校验 / 兼容
B2 云 TTS（Azure / OpenAI） 排除 强 否 0 要 key / 按字符计费，句子才需要
B3 edge-tts 直连 排除 强 否 0 句子才需要；非官方 + DRM
已定的组合（ADR 0134）

缺省 = 系统合成器；不可用时按读者选的兜底走：在线音频（缺省）或本地模型（可选下载），也可以关掉兜底。 明确选了在线或本地之后不在两者之间静默切换（同 ADR 0130 对 OCR 的要求）。 本地模型用 Apache-2.0 的 sherpa-onnx，不引入 GPL-3.0 的 piper；安装包只带运行时，音色模型由设置页下载并校验 SHA256。 发音不花钱、不进每日预算，也不发往解释服务商。

  QBuffer buffer_;              // 内存播放，不落临时文件
};
void SpeechDuty::playBytes(const QByteArray &mp3)
{
  player_.stop();                 // 新声音打断旧声音，写在第一行
  player_.setSourceDevice(nullptr);
  buffer_.close();
  buffer_.setData(mp3);
  buffer_.open(QIODevice::ReadOnly);
  player_.setSourceDevice(&buffer_);
  player_.play();
}

06风险与未解

写方案时最容易被跳过的部分。

风险说明对策
端点随时会变 词典音频端点与 Edge 朗读服务都不是公开 API；Edge 那侧已有 Sec-MS-GEC DRM，说明反爬在进行 端点做成配置项 + 缓存优先；任何失败都退回系统音色，功能整体不"消失"
句子覆盖不到 实测词典端点对任意句子返回 500；Lens 已有句子卡片（ADR 0124） v1 明确"句子暂不发音"，或接 Azure；不要用"看起来能读"的端点赌
系统音色参差 用户机器上可能只有 Zira；装了中文语言包的用户反而英文音色更少 只在用户开启"允许系统音色"时兜底；设置页显示当前音色名，让用户知道自己在听什么
连点与竞态 快速点 3 个词，三个请求乱序返回 每次 speak 自增 token，回调里比对 token，过期直接丢弃（比"停播放器"更根本）
焦点与遮挡 发音不应改变窗口焦点，也不该让气泡重新布局（ADR 0107 / 0113） 播放状态只驱动图标动效，不改高度；不做自动滚动
许可 piper GPL-3.0、espeak-ng GPL-3.0、sherpa-onnx Apache-2.0；词典音频的再分发权不明 缓存只存本机、不随包分发；真要内置模型时优先 Apache-2.0 的 sherpa-onnx

没答案的三个问题

  1. 词典音频能不能缓存到磁盘？ 技术上当然可以，条款上灰色。保守做法：缓存上限压小（50MB）、只存 hash 文件名、不写来源元数据。
  2. 要不要给"音标里单个音素"发音？ espeak-ng 是唯一现成能做的（[[...]] 音素输入），但需要 IPA → espeak 音素映射表，且音质与单词音频差一大截，拼在一起会突兀。
  3. 句子卡片到底读不读？ 读，就要引入第二个 source（Azure 免费额度 50 万字符/月，官方定价页口径）；不读，产品上会显得"只做了一半"。这个取舍该由产品决定，不是实现决定。

方法

  • 星数、语言、许可证、最后推送时间：gh api repos/<owner>/<repo>，2026-10-28 抓取。
