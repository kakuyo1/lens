# 桌面宠物插件 / Mod 扩展：可行性评估与重构方案

> 基线：`main` @ `1e69ebe`，2026-10-15。只读评估，未改动代码或数据，未编译未运行。架构图见 `docs/pet-architecture.html`。

## 1。结论

- **技术上可行。**宠物已经是纯数据（JSON + PNG）：动作名、帧数、锚点、配饰都在数据里，解析整只拒绝，核心层不依赖 Qt 且有单测。现在新增一只宠物就是加一个目录，外部包只是把这件事交给读者。
- **产品决定已放开**（2026-10-15）：允许读者导入宠物包，形式是**只含数据的目录**，不做代码插件。决定记在 `docs/adr/0043`，契约记在 `docs/pet-package-format.md`；`PRODUCT.md`、`GLOSSARY.md`、`UI.md`、`SECURITY.md` 已同步，`docs/adr/0031` 的 “不做导入” 一项被取代。
- **分两步走：**
  1. **先修缺口。**§3 的 G1–G5 是恶意包的直接入口，必须在放行导入之前修掉；包格式整理成有版本、有上限的契约。
  2. **再做导入。**用户目录、扫描、被拒列表、来源标记与首次确认。
- **明确不做代码插件**（DLL、脚本、包内 QML）。隐私承诺 “宠物读不到屏幕文字” 目前由 `PetEvent` 枚举在类型上保证；代码插件能绕过这条约束。项目也没有签名体系（更新包只校验 SHA256，不签名）。

## 2。现状中可复用的部分

| 能力 | 位置 | 对扩展的意义 |
|---|---|---|
| 动作名由数据给出，角色闭集 11 个 | `pet_config.cpp`、ADR 0030 | 外部包可以自定义动作名，但不能新增情形 |
| 整只拒绝，不带残缺状态运行 | `parseAnimations` 等 | 一只坏包不会半途出错 |
| 核心无 Qt，可用假数据单测 | `src/core/pet/` | 校验逻辑可以脱离窗口测试 |
| 事件结构只有枚举 | `PetEvent`（12 个值） | 隐私边界在类型层面成立 |
| 随包数据整体接受的测试 | `pet_data_test` 的 `EveryShippedPetIsAcceptedWhole` | 可直接扩展为外部包的门禁 |
| 负面用例的夹具 | `pet_data_test` 的 `ScratchPet` | 恶意样例可以沿用同一写法 |

## 3。缺口清单

依据是代码阅读，未运行。按对外部包的风险排序。

| 编号 | 位置 | 问题 | 对外部包的影响 |
|---|---|---|---|
| G1 | `pet_assets.cpp` 的 `absolutePath` | `directory / relative` 没有路径约束。`std::filesystem` 的 `/` 对绝对路径是替换语义，`..` 也不拦 | 包可以把图片指向包目录之外（只能是通过尺寸检查的图片） |
| G2 | `pet_assets.cpp` 的 `sheetSize` | `frames`、`canvas` 没有上限。尺寸检查只读文件头；空白 PNG 压缩比极高，可以做到文件很小、声明的尺寸很大 | 小体积的包可能在解码时占用数 GB 内存（待实测） |
| G3 | `pet_assets.cpp:113`、`pet_state.cpp:181` | `frames * canvas`、`frames * 1000` 是 int 乘法 | `frames * 1000` 在约 215 万以上溢出，`frames * canvas` 在约 2440 万以上溢出，有符号溢出属未定义行为 |
| G4 | `pet_assets.cpp`、`SpriteLayer.qml` | 表情索引（含眨眼）不对照表情 sheet 的格数。`pet_data_test` 只检查列表长度 | 索引越界时 clip 落在图外，静默显示空白，不报错 |
| G5 | `pet_assets.cpp:125` | `sheets.at("idle")` 硬编码动作名 | 角色 `idle` 映射到别的动作名时，宠物以难读的 `out_of_range` 拒绝；代码里仍有动作名字面量，与 ADR 0030 “动作名属于数据” 相悖 |
| G6 | `SettingsExtensionsPage.qml` 的 `actionLabel`、`accessoryLabel`、`petLabel` | 显示名是 QML 里的 switch，`default` 返回原始 id | 外部包的动作与配饰只显示原始 id；与 ADR 0030 “新增动作名不需要改代码” 的后果描述不一致 |
| G7 | `pet_controller.cpp` 构造函数与 `pets()` | 单一根目录，启动时扫描一次，属性为 `CONSTANT` | 无法刷新，也没有多根与冲突规则 |
| G8 | `pet_store.cpp:41` | 默认宠物 `"dog"` 写死 | 可以保留，但要明确它永远来自随包数据 |
| G9 | `pet_controller.cpp`（约 565 行） | 数据加载、衣柜、持久化、帧合成、窗口定位、原生窗口、时钟、屏幕事件；20 个 `Q_PROPERTY` 与 15 个 `Q_INVOKABLE` 集中在一个类 | 任何扩展都要改这个类；帧计算只能通过 QTest 验证 |
| G10 | `ui-prototypes/pet-prototype/src/pet-engine.js` | 状态机在 JS 原型中重复实现，两份规则靠人工同步 | 规则漂移无法被测试发现 |

G1–G5 是缺陷，不依赖任何产品决定，应当先修。

## 4。从需求重新推导

按 fresh-arch 的做法：先写需求，不以现状为框架。

### 4.1 需求

| 类型 | 编号 | 需求 |
|---|---|---|
| 新增 | N1 | 读者可以把宠物包放进用户目录，刷新后在选择器里看到 |
| 新增 | N2 | 外部包失败只影响自己：拒绝并说明原因，其他宠物与程序照常运行 |
| 新增 | N3 | 外部包不执行代码，不携带 QML 或脚本，不读取事件之外的任何数据 |
| 新增 | N4 | 外部包不能新增角色或事件映射（角色闭集不变） |
| 新增 | N5 | 外部包不能覆盖随包宠物的 id |
| 新增 | N6 | 外部包的名字与动作名原样显示，不进翻译 |
| 新增 | N7 | 读者能看到每只包的来源与被拒原因 |
| 保留 | K1 | 隐私：宠物只收事件类型；窗口排除抓屏；单帧时钟；整只拒绝 |
| 保留 | K2 | 安装目录只读，读者数据在 `%APPDATA%` |
| 删除 | D1 | 启动时一次性扫描、列表为常量 |
| 删除 | D2 | 显示名只在 QML 中维护 |

### 4.2 已经过时的现状

- `pets()` 为常量、单一根目录（G7）。
- 显示名与动作名映射（G6）与 ADR 0030 的承诺不符。
- `PetController` 的边界按 “一只随包宠物” 设计（G9）。
- `idle` 硬编码（G5）违反 ADR 0030。
- PHASE3 §3.8 的扁平目录布局（见 `docs/pet-architecture.html` 第 10 节）。

## 5。目标设计

只有在产品决定放开后才启用第二步的读者侧能力。分层沿用 `AGENTS.md`：core 无 Qt，app 承载 Qt。

```
core/pet/package     纯函数：JSON 文档 + SheetInfo → PetPackage 或 Refusal（枚举原因，风格同 ADR 0025）
core/pet/path        纯函数：resolveInside(root, relative)，拒绝绝对路径、盘符与 ..
core/pet/runtime     状态机 + 衣柜 + “时刻 t 显示哪一帧”（从 PetController::sync 挪入）
app/pet/catalog      扫描随包与用户两个根，处理 id 冲突，支持刷新；SheetInfo 的 Qt 实现（QImageReader 读文件头）
app/pet/session      QObject：Pet.* 属性与 20 ms 时钟；原 PetController 瘦身为这一层
app/pet/window_host  窗口放置、穿透、排除抓屏、屏幕变化
```

**Seam 只放在真正会变化的地方：**

- `SheetInfo` 是真 seam：一个 Qt 适配器，一个测试用的假实现。校验逻辑由此可以在 `lens_gtest_unit` 里用假尺寸覆盖，不需要真的解码图片。
- 包来源不抽象成接口。目前只有 “随包” 与 “用户” 两个目录，用同一个函数传入根路径即可。

### 5.1 包格式 v1（草案）

- `pet.json` 增加 `"format": 1`；未知版本整只拒绝。
- 增加可选的 `"name"`，外部包原样显示；缺省时用 id。
- id 即目录名，限定为小写字母、数字与下划线。随包 id 保留，用户包不能占用。
- 上限（建议值，待确认）：

| 项 | 建议上限 | 理由 |
|---|---|---|
| canvas | 16–128 | 窗口宽 = canvas × scale，最大 512 逻辑像素，限制置顶窗口的尺寸 |
| scale | 1–4 | 现有值 |
| 每个动作的 frames | ≤ 64 | 限制声明的解码尺寸（G2） |
| fps | 1–24 | 现有数据最高为 12 |
| 动作数、配饰数 | 各 ≤ 32 | 限制选择器与内存 |

由 frames 与 canvas 的上限可以推出单张 sheet 的最大尺寸：64 帧 × 128 × 128 像素，约 4 MB 解码内存。

### 5.2 拒绝原因（枚举）

建议：`Unreadable`、`Format`、`MissingRole`、`BadAnimation`、`BadAnchors`、`BadAccessory`、`SheetSize`、`ExpressionIndex`、`PathEscapes`、`LimitExceeded`、`IdTaken`。被拒原因在设置里显示，日志保留原文。

### 5.3 不变量（由测试锁定）

- 任何路径解析结果都在包目录之内。
- 任何表情索引都小于表情 sheet 的格数。
- 任何 sheet 的尺寸等于 `frames × canvas` 宽、`canvas` 高。
- 外部包无法让 `PetEvent` 携带文本（结构上已成立，测试保留）。

## 6。方案对比

| 方案 | 做什么 | 成本 | 收益 | 结论 |
|---|---|---|---|---|
| A 维持现状 | ADR 0031 不变，新宠物由开发者加入 | 0 | 无 | 已否，产品决定放开 |
| B 修缺口、拆分 | §3 的修复，拆分 `PetController` | 中 | 修掉 G1–G10；为渲染器与外部包提供同一套校验 | **先做**，是导入的前置条件 |
| C 读者侧数据包 | 用户目录、扫描、被拒列表、来源标记、首次确认 | 高：契约、UI spec、文档同步、测试矩阵 | 真正的用户扩展 | **已选**，见 `docs/adr/0043` |
| D 代码插件 | DLL、脚本、包内 QML | 很高 | 无 | **不做**：破坏隐私边界，且需要签名体系 |

## 7。重构与优化路线

每个阶段独立交付，可单独回滚。P0 必须在 P5 之前完成。

| 阶段 | 内容 | 验证 |
|---|---|---|
| P0 缺陷修复 | G1 路径约束（含重解析点）；G2 上限，并在解码前用文件头预检；G3 先判上限再乘，或改用 64 位；G4 表情索引对照格数；G5 `idle` 改为经 `roles.idle` 解析 | `lens_gtest_unit`：每条缺陷一个用例，用 `ScratchPet` 写恶意样例 |
| P1 帧计算进核心 | `PetController::sync` 的帧、眨眼、预览结束挪入 `core/pet/runtime`，写成纯函数 | `lens_gtest_unit` 覆盖；QTest 只验证绑定 |
| P2 拆 PetController | 抽出 `catalog`（两个根、扫描、冲突规则）、`window_host`（窗口）；QML 中 `Pet.*` 属性名不变 | `lens_qtest_pet`；窗口行为保留现有真机人工项 |
| P3 状态机两端对齐 | 时序与事件映射写成共享的 JSON 用例集，C++ 与 JS 两端都读 | 两端测试读同一份文件 |
| P4 文档对齐 | 修 PHASE3 §3.1、§3.4、§3.8 的漂移；ADR 0030 补 “显示名例外”；`pet.json` 的 `height` 与默认配饰写明未实现或删除 | 人工核对 |
| P5 读者侧包 | 按 `docs/pet-package-format.md` 实现校验；用户目录扫描；被拒列表；来源标记与首次确认；`lupdate` 补 4 份译文；`README` 四个语言版本同步 | 恶意样例集 + 真机 |

## 9。不做的事（YAGNI）

- 包内脚本，或包内自定义角色、事件映射。
- 包依赖、包市场、包的自动更新。
- 版本迁移框架：格式只到 v1，未知版本直接拒绝。
- 热替换正在播放的宠物。切换宠物沿用现有的 “重新加载” 方式。
